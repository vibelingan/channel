## 本轮交付什么

原来的函数测试主要证明“上传了正确的包，运行记录没有记错”。现在增加一个真正能运行的假业务程序，检查恢复后还会不会正确处理数据。

- A 版支持创建、读取、修改和停用测试记录。
- B 版增加可选的 `note` 字段，保持原来的数据和接口用法。
- 用 A 创建记录，再用 B 修改、增加字段、新增另一条记录、停用第三条记录。
- 选择明确登记为成功的 A 包，调用原 D1/C2 恢复代码；恢复后实际执行 A 的处理函数，核对版本和业务结果。
- B 增加的字段、新记录和停用标记都保留。停用使用 `deleted: true`，没有删除集合或字段。
- 另放入一个会丢新字段的错误旧程序，证明兼容检查会拒绝它。

这是一条本地测试。它使用真实 Manager SDK 的请求构造和原恢复执行代码，但网络请求由测试程序接管，发布记录和业务记录使用本地模拟存储。GitHub 归档来源也使用测试数据。通过后不能写成“腾讯云数据库事务、真实函数切换或 CDN 缓存已经验收”。

对应代码：`scripts/release/dummy-recovery-fixture.mjs` 生成固定 A/B 包；`scripts/compatibility/recovery-dummy.test.mjs` 执行归档里的旧函数；`scripts/release-dummy-recovery.test.mjs` 联测预览、指定恢复版本、实际运行身份和数据保留。现有测试辅助程序只增加可传入的函数名和程序包，默认行为不变。

## 恢复专项检查什么时候运行

| 时机 | 检查内容 |
| --- | --- |
| 正常 CI / 正常部署 | 保留原代码、接口和格式测试。不会逐个下载历史函数包，也不会运行云端恢复演练。数据格式或 API 有变更时，仍需相关的兼容测试，避免新旧网页混用时出错。 |
| 准备恢复指定版本 | 检查那一份旧包是否能处理当前数据格式和仍在使用的网页接口；只检查本次选中的函数。 |
| 真正执行恢复前 | 再读当前版本、数据规则和配置，确认没有在预览后发生变化。变化或确认码过期就重新准备。 |
| 以后启用自动恢复 | 只有发生本次线上写入，且能够证明旧包可用，才恢复一次；没有写入的 lint/build/test 失败只停发。自动恢复尚未启用。 |

本地假业务用例接入已有的 SEO 离线 CI，不增加云凭证或发布动作。测试产生的报告只证明这个假程序，不写进真实 `public-api`、`admin` 或商品同步函数的兼容记录。

## 实际执行顺序

| 顺序 | 操作 | 通过条件 |
| --- | --- | --- |
| 1，本轮本地完成 | 运行 A/B 假程序及恢复联测，包括丢字段旧程序和写入结果不确定等情况 | 定向测试及原有仓库回归通过；远端对同一提交执行 CI |
| 2，云端入口待接入 | 将现有恢复器接到独立演练记录；增加固定假资源范围和测试集合的带版本读写；在原人工入口增加演练操作 | 不能访问业务集合、业务函数或普通页面；测试能证明这些限制；正常部署 workflow 不变 |
| 3，先建立可用 A | 创建并运行假 A、假页面和测试记录；下载云端正在运行的包，与保存的原包比对；再指定同一个 A 做一次恢复 | A 确实可用且能从备份恢复。保存精确 A 运行编号与包 hash；没有通过就不发布 B |
| 4，再发增量 B | 假页面文字改为 B，假函数增加可选字段，写入 B 数据并新增记录 C、停用记录 D | 页面和函数都读到 B；原数据仍在；备份 A 不被改写 |
| 5，人工指定恢复 A | 明确选择第 3 步保存的 A，运行兼容检查，再执行恢复 | 下载包和实际运行结果都为 A；B 新字段、C 和 D 的停用标记都保留；普通网站只读检查通过 |
| 6，单独测试自动恢复 | 仅让假页面的验收失败一次，不破坏业务 API 或数据库 | 只有发生假资源写入才尝试一次恢复；原发布仍记录失败；恢复失败不递归再恢复 |

第 2 至 6 步还没有实施或执行，不能因为本轮本地通过就把它们标为完成。尚不提供一个未实现却看起来能直接运行的线上写入命令。真实业务函数的切换要等整套假业务云端演练通过，再核对该业务函数自己的数据和接口兼容性。

## 失败时怎么处理

建立 A 之前，任一步失败就停止创建，不去改业务版本。B 已经发布但演练失败时，只能恢复本次明确保存并验证过的假 A；如不知道上传是否已生效，先查询当前包和运行结果，不能盲目重试。

以下情况停止：预留名称已被占用且归属不能确认、目标不符、备份损坏或未验收、出现另一项发布、版本在检查后变化、权限不是预期值、运行包和回执不符，或普通网站检查出现异常。留下已知版本和错误记录。停止时不删除客户数据；真实演练通过、证据归档后，按最新清理方案删除明确归属本演练的假资源及专用代码/用例，保留标准、场景和证据，不扩大到业务字段或集合。

完整验收记录应包含静态普通 URL 的内容和缓存结果、假函数原 ZIP 与实际运行版本、测试数据前后值、发布记录、恢复耗时和搜索通知次数。搜索通知必须为零。浏览器缓存、真实 SDK 更新结果和数据库条件写入必须到云端验证，不能由本地结果推断。
