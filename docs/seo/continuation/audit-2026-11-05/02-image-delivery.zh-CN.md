# 模块二：修复公开图片交付

## 已经复现的故障

Google 抓取统计列出的三个图片地址，11月5日普通 GET 均返回400。三条错误正文均明确写出云函数响应超过6MB：

- `/api/images/4db8df016ac88396000781db489eb227`
- `/api/images/ea7765a56ab1dbea01d9b6924386c973`
- `/api/images/31051309-b170-4ef2-a7f7-86c645fd3fad`

见[三条完整错误](evidence/image-errors-detail.json)。这不是仅凭搜索平台旧报告推测；本轮再次读取也失败。返回的是 JSON 错误，不是图片。`robots.txt` 已允许 `/api/images/`，但允许抓取不能解决传输失败。

## 为什么会发生

代码确认 `apps/functions/public-api/src/index.ts` 使用事件型函数；`handler.ts` 的 `getCatalogImage` 读取整张图并转换成 Base64，`http-adapter.ts` 把它放进函数响应。`packages/shared/src/media.ts` 允许商品原图最大10MiB。腾讯的[响应上限说明](https://docs.cloudbase.net/error-code/EXCEED_MAX_RESPONSE_SIZE)列出的云函数响应上限为6MB。

因此，“能上传10MiB原图”和“能通过这个函数响应交付原图”没有对齐。Base64还会把数据量放大约三分之一。这条链路足以解释本次错误；原始图片精确字节数及平台在哪个封装层计数仍需管理侧读回，不能把估算的边界当作已测上限。

对照读取另一个已知图片：服务域名返回200、JPEG、220114字节；同一图片的主域请求有一次超时。不能据此说所有小图也坏了，需在实施时将主域和服务域名的路由、错误及缓存分别核对。[对照结果](evidence/image-route-comparison.json)。

## 推荐方案

保留原图，公开页面优先交付按用途生成的图片版本。先解决已失败的三张图，再分批处理已公开商品和文章；不是重新生成文章配图，也不是让客户重新上传所有商品图。

- 图片处理模块输出真实宽高、格式、字节数、内容摘要、原图来源及生成版本；按使用场景生成缩略图、商品主图和正文图。编码和尺寸必须经视觉验收，信息图的小字不能被压糊，透明图不能丢透明背景。
- 发布前保证实际公开版本经过完整读取和解码，且函数最终序列化响应有充足余量低于平台限制。不能只检查上传时声明的大小，也不能上传成功后让访客碰到400。
- 如果某张图在保真要求下无法适合这个响应入口，使用经过现有发布引用检查的原生 HTTP 字节交付或专用公开派生资源入口；不要把整个原图存储桶开放。是否复用现有 HTTP 服务，要先核对实际部署路由和运行包，不能根据服务域名能访问就假定两条线路等价。
- 所有公开图片仍要求处于已发布引用范围内。草稿预览继续通过登录授权返回字节，再用浏览器本地对象地址显示；不得把原图、凭证或临时签名地址写进公开正文和 schema。
- HTML、Product图片字段、文章封面和分享图统一选择同一套可公开交付的地址。用 `srcset`/`sizes` 选择尺寸，首屏主图优先，正文图保留准确 alt 和宽高，装饰性缩略图可以空 alt。
- 共享缓存只能用于已审核的公开派生资源，键包含资源版本。撤回和替换须覆盖现有引用计数、缓存失效与已打开页面；登录图片和会员数据不参与共享缓存。不能为了速度把撤回保护去掉。

## 拆分与验收

1. **传输边界**：在隔离测试资源上覆盖低于/接近/超过响应上限、Base64膨胀、错误类型及超时。大图不能以200返回JSON或半张图片。
2. **派生与重试**：相同原图及生成版本复用产物；失败不改变已发布资源；重试不重复加引用，不覆盖人工 alt、裁图或文章布局。
3. **实际公开交付**：三个故障地址或其受控替代路径均可读取正确图像，HTTP状态、MIME、解码、尺寸和摘要一致；Google实时查看页面能读到图。旧公开网址需要兼容时保留可靠转接，不静默丢弃。
4. **权限回归**：未发布、无引用、损坏计数、撤回、跨文章复用和私有预览均验证；不通过用户代理伪装绕过权限。
5. **性能比较**：同条件复测图片字节、主图加载和LCP；这是修复后的证据，尚未发生，不先填节省比例。

涉及SDK时按仓库契约规则核对已安装包源码和官方文档，并运行 `pnpm verify:cloudbase-sdk`。本轮只读诊断，没有改SDK、图片或线上权限。Context7在当前工具中不可用，已通过CloudBase文档MCP核对响应限制，并核对本仓库实际函数与存储封装。

恢复以程序与派生资源版本为单位。原图及人工内容保留；新派生图先准备后切换，失败继续引用原有可工作的版本。已损坏的旧地址不能当作可用恢复来源。
