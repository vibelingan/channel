## 交付怎么分

每个模块有问题依据、推荐实现、相关文件和独立验收；没有把所有细节堆成一个巨大任务。

| 推荐顺序 | 模块与产物 | 本轮做到哪里 | 下一段交付标准 |
|---|---|---|---|
| 先处理 | [图片可靠交付](02-image-delivery.zh-CN.md) | 三条真实错误、函数响应和官方限制交叉核对；方案完成 | 图片实际可读取且仍保护草稿/撤回，大小边界及重试验证 |
| 随后 | [网址与商品发现](01-indexing-and-discovery.zh-CN.md) | 7个逐页核查完成，分类及分页源码检查完成 | 初始商品链接、可抓取分页、OEM/Toys与旧文章重抓记录 |
| 随后 | [商品增强展示](03-product-search-results.zh-CN.md) | 找到明确缺项及当前实现边界，规则设计完成 | 真实可公开报价与HTML一致；询价商品不造价格、不漏会员字段 |
| 再交付 | [视频与内容](04-video-and-content.zh-CN.md) | 明确视频未索引原因，观看页和内容关联方案完成 | 真实观看页、视频/封面/schema/地图一致，随后观察视频索引 |
| 先审方案 | [性能与海外分发](05-performance-and-region.zh-CN.md) | 美国/本机基准已存在，已补本次发现，尚未优化 | 分模块同条件Before/After；静态海外分发独立对照；主域永久跳转 |
| 贯穿以上 | [搜索跟进与增长](06-search-follow-up.zh-CN.md) | 当前搜索、AI、抓取、异常和安全报告已核对 | 一份持续更新的证据表，分开技术通过、实际索引和业务结果 |

视频页、分页路径和图片方案均是待实施设计，不是已经上线的新功能。性能仍遵守“先看基准和方案再改”，本轮不以用户说“继续调研”扩大为未经审阅的性能/付费基础设施切换。CI八分钟目标保持单独事项，本轮不修改pipeline。

## 验收和恢复

1. 使用当前分支，在每段实施前核对main的新变化，保留其他工作流。现在不合并或改动其他分支。
2. 模块局部测试与代表页浏览器验证通过，再准备交付。涉及页面变化先给同视口截图；图片和分页不能靠源码推测可用。
3. 线上只发布该段范围，沿用已验收的备份/恢复和共享部署锁。恢复程序时保留当前商品和文章内容，不因技术回退撤销客户新文章。
4. 发布后查真实HTTP、正文、图片、交互、权限，再看Google实时测试及索引；每项状态分别写。正常重复页、平台尚未更新、缺业务数据和代码缺陷不混在一起。
5. 不承诺全部540网址都一定收录、视频一定展示、改LCP一定提升排名，也不把这些不受直接控制的结果伪装成已完成。对能修的代码与资源问题按模块交付，不只停在“等待Google”。
