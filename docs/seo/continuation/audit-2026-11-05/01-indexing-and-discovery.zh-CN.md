# 模块一：网址收录与商品发现

## 要解决什么

让应该独立展示的正式网址容易被找到；重复地址继续合并到正式网址。本模块不追求 Search Console 的“未收录”为零。

11月5日逐页检查确认：历史清单中的 `/ai-gadgets/`、`/electronics-toys/`、`/misc/` 已收录，`/oem/`、`/toys/` 仍未收录，没有抓取日期；OEM首次检查为“已发现”，复查又显示“网址未知”，变化原样记入网址表。`/headphones/?page=1` 采用 `/headphones/` 为正式地址；另一个蓝牙筛选参数地址也被 Google 合并到 `/headphones/`。完整证据见[网址核对表](URL-LEDGER.zh-CN.md)。

另有一篇文章的 Google 历史记录仍显示10月29日的 noindex 响应头。今天从正式网址读取的 HTML 与响应头没有 noindex。需要重新抓取后确认，不能把旧记录当作今天仍有这个响应头，也不能把网站侧修好说成文章已经入索引。

## 已确认的源码与网页缺口

- `apps/site/src/pages/{headphones,ai-gadgets,toys,misc,electronics-toys}.astro` 的分类首屏内容主要靠 React 加载。实读首页、分类及三件商品的初始 HTML，没有发现指向独立商品页的普通链接。商品详情本身已有静态正文；问题是从分类继续发现商品仍依赖运行脚本。
- `CatalogFamilyGrid.tsx` 在脚本完成后会输出真实商品链接，这部分应沿用；不能说 Google 完全看不到它。
- `CatalogPagination.tsx` 的页码、上一页、下一页目前都是按钮；Google 通常不会为发现后续商品去点击这些按钮。
- 当前静态分类页面对查询参数返回同一份 HTML。不能只给第二页写一个自己的 canonical，却仍然返回第一页商品。

这些是值得修的发现路径，但**不能据此断言它们就是 OEM 和 Toys 未收录的唯一原因**。OEM 是业务介绍页，仍需单独检查内容差异、内链和 Google 的实时抓取结果。

## 推荐实现

1. 复用已有公开商品快照和版本规则，为各分类生成首屏商品卡片及正常的 `<a href>`。在现有页面和组件内补初始数据，不另做一套视觉风格；React 接管后照常请求最新公开 API，筛选、价格权限、展开详情及询盘沿用现有实现。
2. 无筛选的第二页及后续页采用可预生成的路径，例如 `/headphones/page/2/`。每页输出自己的商品和 canonical，并有前后页真实链接。第一页正式地址保持 `/headphones/`。这是建议的新路由，尚未实现，不是现有线上地址。
3. 各分类由同一快照按已有公开排序规则分组，固定唯一排序键；商品公开内容或分类变化后，把相关分类分页一起列入当前自动交付计划。重新分组时检查页码缩减、重复商品、遗漏商品及最后一页边界。
4. 交互筛选继续使用原来的查询参数；不把任意筛选组合批量建成搜索落地页，也不删掉筛选状态。将来有独立业务价值的分类词，再做有明确正文和商品范围的落地页。
5. 为 OEM 与 Toys 补真实、相关的入口和有用内容：OEM 从首页服务说明、相关文章与相关产品引入；Toys 展示实际商品或真实业务说明。没有现成业务资料时不编造产能、证书、价格，不用大段重复文字填充。
6. Blog 列表与两篇公开文章保留收录；草稿、预览、登录、后台及404仍不收录。文章日常发布继续走实时文章服务，不改回等待 GitHub 构建。

## 分段交付与验收

| 交付段 | 内容 | 验收标准 |
|---|---|---|
| 首屏商品 | 快照传给现有列表组件，客户端再刷新 | 禁用脚本仍能看到首屏商品和可点击详情链接；开脚本后无重复、无闪回旧列表；公开价格和登录价格不串用 |
| 正常分页 | 真实链接与逐页 HTML | 第2页正文与第1页不同；每件在售商品可沿有限链接找到；页码过界真实404；刷新、前进后退、筛选和新标签打开正常 |
| 自动变化 | 分类与商品共用交付版本 | 新增、移类、撤回、排序改变都刷新受影响分页；旧任务不覆盖新内容；恢复代码时仍使用当前内容 |
| 搜索复查 | 小批提交真正需要重抓的正式网址 | 记录实时抓取、请求是否接受、后续实际索引，三者分开。两个正常重复地址不提交“修复验证” |

先跑受影响的分类组件、快照和HTML测试，再在交付验收中读取完整公开网址清单。无需每个文档提交重跑所有后台业务。上线前提供同视口截图，保留现有卡片、筛选和询盘操作。失败按已验收的程序版本恢复，不回退商品或文章数据库。

Google 的[JavaScript处理说明](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)明确说明可以处理脚本生成的内容；采用初始 HTML 是降低发现依赖，不是声称 Google 不运行 JavaScript。[分页说明](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)要求后续页有可抓取链接及与内容一致的正式地址。


## 兼容旧图标入口

抓取统计的404样例两条都指向 `/favicon.ico`，不是商品页。当前页面使用SVG图标；在本模块补实际可用的兼容ICO资源，继续保留SVG，不把所有缺失路径重定向到首页。验证正确MIME与图像字节，并确认真正不存在的网页仍404。该项优先级低于图片正文故障和商品发现。
