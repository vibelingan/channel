# 03 商品发现、分类分页与网址入口

> 2026-11-16：DISC-1/2已真实交付528商品及46个分类页面，后续正常main/test版本66c915dc部署也通过。初始HTML商品链接、路径分页、真实浏览器翻页/返回/详情与询盘入口均已验收。独立复核发现的“实时新增页尚未交付”和无尾斜杠边界已补上，46项单元、5组浏览器旅程通过。既有根分类文案与交互保留，分页使用同一商品快照；不增加API采集。主域HTTP301仍单独处理，详见[现场记录](EXECUTION.zh-CN.md)。

> 2026-11-12历史设计记录：本模块属于搜索发现与网址一致性，不等同于CWV。截图中的portfolio已通过真实HTML、无脚本电脑/手机、robots和sitemap核对，无对应代码修复。后续实际交付以上方11月16日记录为准。

## 现状与目标

商品详情已有独立 URL 和初始 HTML。缺口在分类：最初返回的页面没有商品详情链接，列表依赖 React；分页主要是按钮。Google 能运行脚本，但通常不会点击按钮发现下一页。既有sitemap已有商品地址，旧记录为528件，不代表今天全量；这次补站内链接和抓取路径，不能说让商品第一次被发现。目标是在保留现有筛选、图库、详情展开和询盘操作的同时，用普通链接找到所有公开商品。

## 高层结构

`当前公开商品快照 → 同版分类清单 → 分类首屏 / 分页 HTML + 真实链接 → React 接管并读取当前公开 API`。

分类首屏继续用现有页面和卡片，不另建一套 SEO 专用页面。后续页已交付 `/headphones/page/2/` 这类静态路径，其他大类采用同一规则。每页有对应商品及自己的 canonical；第一页保持现有 `/headphones/`。11月16日已独立读取线上第二页并核对正文，完整验收见上述现场记录。

快照按现有公开排序加唯一稳定键分页。同一次交付中的商品、分类和 sitemap 使用同版内容；既有自动交付增加受影响分类集合，不新增一套商品保存机制。创建、移类、撤回及排序变化须重新计算相关页码；过界页返回真实 404，不继续展示旧商品。

浏览器打开这些 HTML 后仍能刷新 API。构建时只有两页、API随后增至三页时，已交付的前两页继续使用静态地址，第三页先使用根分类的查询参数和API，不提前请求尚未生成的HTML；刷新与前进后退按实际文档页码恢复。快照较旧时，真实列表可以更新；不得把新旧版本的分页结果拼在一起。原有分类内展开交互保留，商品卡片仍有稳定独立详情链接；鼠标、键盘、新标签、刷新与前进后退都要正常。

## 网址规则统一管理

| 地址 | 处理 |
|---|---|
| 正式商品、分类、文章 | 200，独立标题、正确 canonical，按公开状态入地图 |
| 第一页参数副本 | 合并到正式第一页；内链不再制造多份地址 |
| 真正的第二页及后续页 | 各页正文不同、canonical 指向自己，前后页用 `<a href>` |
| 排序、临时搜索和任意筛选 | 不批量放进 sitemap；仅内容等价时合并，否则按明确索引策略处理 |
| 草稿、预览、后台、登录、缺失页 | 保留现有权限及不收录规则；真实缺失为 404 |
| www 和 HTTP | 保留路径、查询参数并统一到正式 HTTPS 主域；禁止跳转循环 |

www 301 已验收，不重复做。11月18日独立Node完整GET与curl再次核对：裸域HTTP目前返回200，www的HTTP/HTTPS均一跳301到HTTPS裸域并保留路径和查询串。不要把历史原生开关试验的307写成当前状态；本轮只读取，没有改域名或HTTPS开关。主域 HTTP 301 仍未完成：CloudBase 原生强制 HTTPS 曾实测返回 307，已恢复；实施先核对官方及现场入口能力，再选择最小范围的永久跳转入口。若必须让根域经过新边缘服务，单独列 DNS、TLS、费用和回退方案，不能借静态子域试验悄悄接管根域。现有 API 和第三方回调列入兼容核对，不笼统用 301 改写所有 POST。

### 11 月 19 日复核主域入口

已用管理接口只读核对上海站点为 CloudBase 标准版，官网主域仍使用直连并同时接受 HTTP 和 HTTPS。这个入口下，首页和通用路径进入静态托管，`/blog` 进入文章服务。实测 `http://supplychainsai.com/headphones/?page=2` 返回 200；`https://www.supplychainsai.com/headphones/?page=2` 一跳 301 到 `https://supplychainsai.com/headphones/?page=2`。历史试验记录表明，主域直连开启 `HTTP_TO_HTTPS` 时返回 307，试验后已恢复。Google 将 307 当作临时跳转。腾讯 CLI 文档将同一设置写为 301，但自定义域名的产品文档在边缘加速下列出可选 301。现网返回值是此次验收依据。 [CloudBase 网关配置](https://docs.cloudbase.net/cli-v1/gateway) · [CloudBase 自定义域名](https://docs.cloudbase.net/service/custom-domain) · [Google 跳转规则](https://developers.google.com/search/docs/crawling-indexing/301-redirects)

给腾讯支持的复现已经准备好：请确认当前直连入口能否配置永久跳转，给出适用于现有环境的设置和接口。可从上述公开分类地址开始核对路径及查询参数。静态托管的路径替换规则按路径或错误码匹配，不能作为已确认的协议跳转开关。若只有边缘加速支持目标行为，产品文档要求标准版及资源点计费，且需切换根域 DNS。当前已确认套餐等级，账单模式、增量费用和切换前的试验入口仍需核对。此次没有发工单、开通收费服务或改 DNS。 [静态托管规则](https://docs.cloudbase.net/hosting/manage#重定向规则) · [计费说明](https://docs.cloudbase.net/quick-start/resource-point)

任何新的入口都先在隔离地址验证。用首页、带查询参数的分类路径及商品页验 HTTP GET/HEAD 一跳 301 并保留地址，同时读回原有 HTTPS 页面、文章、地图、真实 404、公开图片和受保护入口。涉及写入的接口和回调维持原有 HTTPS 合同，只在隔离环境验证请求方法及正文。测试失败时保留原入口，先确认恢复前的证书、DNS 和源站路由都可用。视频分段按自己的 206 与播放器拖动检查验收。海外静态子域的工作仍按原顺序排期。

本次复核了两个域名的实际路由。www 的请求由专用跳转函数返回 301，路径和查询参数都保留。裸域的网页由腾讯静态托管直接回复，Blog 有独立入口，二者的 HTTP 和 HTTPS 共用路由。就现行的按域名和路径转发规则，把 www 的函数直接挂到裸域也会影响现有 HTTPS 页面。继续保留当前入口，通过腾讯现有能力或隔离入口验证永久跳转后再切换。 [腾讯域名管理接口](https://docs.cloudbase.net/en/api-reference/manager/node/domain) · [Google 永久跳转处理](https://developers.google.com/search/docs/crawling-indexing/301-redirects)

同轮又从官网读取 `/favicon.ico`，得到 404，页面明确引用的 `/favicon.svg` 可以打开。Google 早期抓取统计列出的两个 404 样例都指向这个 ICO 地址。兼容文件直接用现有 SVG 生成 16、32、48、64 像素四档。浏览器原有 SVG 引用保留。这项修复对应图标请求，网站正文、收录和排名另看各自的报告。 [原始抓取统计记录](../audit-2026-11-05/01-indexing-and-discovery.zh-CN.md) · [Google 网站图标说明](https://developers.google.com/search/docs/appearance/favicon-in-search)

补一个真实可用的 `/favicon.ico`，保留 SVG；不把其他未知路径转首页。OEM、Toys 的待收录需要核对真实内容和相关内链，不能断言分页就是它们未收录的唯一原因。

## 分段验收与恢复

3A 分类首屏、3B 真实分页及自动变化、3C HTTP 入口与图标，分别验收。无脚本检查首屏和有限链接遍历；对比页 1/2 商品集合；覆盖新增、移类、撤回、最后一页缩减及迟到交付；浏览器保留全部业务操作。页面变化先给同视口截图。

线上检查真实响应、标题、canonical、地图和当前 API；Google 实时可读与后续实际收录分开记录。程序恢复用当前商品内容重建相容产物，不恢复旧商品库。DNS 恢复不是瞬时操作，须在切换前留好源站与证书通路。

依据：[Google 分页规范](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)、[JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)。

## 底层设计：同一份数据生成分类和分页

新增 `lib/seo/category-snapshot.ts`，从已校验的 `ProductSnapshot` 生成 `CategoryPageData`：`family`、`page`、`pageSize`、`total`、`pageCount`、当前页公开商品、集合revision、canonical路径和邻页路径。沿用每页12件，以商品ID升序分页；公开列表API与构建使用同一排序，避免翻页时重复或漏项。

`headphones.astro` 等既有四个family页接收第一页数据；`electronics-toys.astro` 沿用聚合目录规则。后续页使用 `pages/[family]/page/[page].astro`，`getStaticPaths()`只生成已知family与实际存在的第二页及以后。第一页仍由原文件负责；`/page/1/`不生成，返回真实404，所有第一页内链均指根分类。第N页有对应商品、独立canonical和普通前后页链接。

将初始数据传给现有 `CatalogFamilyPage` / `CatalogFamilyGrid`；Astro服务端渲染与浏览器首轮使用相同数据，不能只在effect填。`CatalogPagination` 支持真实href，普通点击可由React接管，修饰键、新标签和无脚本导航仍使用链接。当前详情展开、筛选参数、价格显示和询盘流程不重做。任意筛选不生成无穷静态组合。

自动交付已有商品变化记录。新增 `category-page-manifest` 列每页路径、内容摘要、商品ID集合和实际内容日期；从新旧快照计算受影响family，重建该family分页，而非尝试只改含某件商品的一页。排序和页码变化会影响后续多页，更新与删页要成同一受控交付单元。旧任务迟到仍按既有版本保护拒绝。恢复旧程序时从当前公开内容重建，不能拿旧分类清单覆盖新商品。

## 底层设计：路径分页和旧查询链接

当前 `numbered-catalog-state.ts` 用 `parseCatalogQuery()` 从查询串读page，`catalogUrl()` 用 `?page=N` 写页码；每页12件。`CatalogFamilyPage` 的初始化、push/replace及popstate必须同段改为理解路径，不能只改分页按钮href。

选择 `/headphones/page/2/` 是为了在现有静态托管上返回不同文件。查询串方案在SSR服务同样可做，但本轮不迁移分类到服务器。商品详情地址、第一页根分类地址保持不变。已有查询串canonical指根页不等于可以证明没有任何排名历史，应保留兼容并观察。

| 访问方式 | 目标行为 |
|---|---|
| 根分类、`?page=1` | 第一页仍是根分类；不制造page/1副本 |
| 新路径第N页，无过滤条件 | 路径决定页码，初始HTML和React一致；下一页链接写路径 |
| 旧根分类 `?page=N`，没有筛选/搜索且N合法 | 首选 `location.replace` 到等价新路径，一次额外GET取得正确HTML，保留安全hash；不是HTTP301。可先显示明确跳转状态，不短暂冒充第二页内容 |
| 新路径又带冲突page参数 | 合法路径为准，去掉冗余page；不能让查询参数覆盖路径正文 |
| 带筛选/排序/搜索 | 沿用根分类的交互查询，不批量生成静态组合；保留过滤状态，不把它误跳到未过滤第N页 |
| 零/负数/小数/非数字/过界 | 交互输入按现有明确校验；实际不存在的新路径真实404，不偷偷显示第一页 |
| 前进/后退、刷新、新标签、修饰键 | 路径、列表及选择保持一致；普通链接可独立工作；不依赖按钮点击 |

`history.replaceState()`只改地址，不取HTML或切列表。因此不作为旧查询迁移的默认方案；未来如为了减少跳转采用它，必须先取得等价页数据、同步列表和元信息并验证，另行评审。前后页各自canonical，不能全部指第一页。缩页精确移除旧生成页并确认真实404，删除范围仅限确认不再存在的生成页面，不清理原图或业务数据。

## 底层设计：入口与状态

复用 `lib/seo/page.ts`、`route-policy.ts` 与已有product身份函数；扩展构建检查，要求每个分类页的可见商品链接与清单相符，所有公开商品沿有限链接可发现。页数缩减后精确清理已有生成页，确认真实404；不能仅从新构建目录里消失就当旧托管文件已删除。

主域HTTP跳转独立执行。11月4日原生HTTPS开关只得到307；已有专用跳转方案也必须重新核对线上路由后才能启用。目标是GET/HEAD保留路径和查询串的一跳301到正式HTTPS。POST/API/回调按现有入口处理，不把方法转换副作用扩散到后台。先保存当前网关/证书/托管配置和可恢复来源；规则不支持就明确保留未完成，不猜SDK方法、不改整站DNS来凑通过。CDN延后不阻止查清这个独立入口。

`/favicon.ico` 为现有图标的兼容文件，保留SVG；真正未知网页仍404。`/portfolio`与`/portfolio/`今天均200且canonical一致，正文相同，属于正常可合并副本；不把截图改造成不存在的案例详情404任务。

构建只读取一次已验收商品快照生成全部分类，新增运行期云调用为0。浏览器继续使用现有当前页API，不依赖模块02重构。分类整合验收遍历产物及有限链接，不为每件商品打开一遍真实后台。
