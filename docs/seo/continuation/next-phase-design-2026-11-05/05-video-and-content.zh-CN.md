# 05 视频观看页与业务内容关联

> 2026-11-12：保留已运行的Blog后台、实时发布和助手草稿能力。本模块只补搜索发现、视频观看页及现有内容关联；不重装Hermes，不新增自动公开权限。

## 要解决的问题

Google 报告发现首页视频，但未将其作为视频收录，原因是首页主要目的不是观看该视频。这不需要把首页改成视频站。Blog 的编辑、图片、草稿、人工发布与实时 HTML 已有实现，本模块不重做这些功能，也不新增助手权限。

## 视频方案

新增一张真正以现有视频为主体的观看页，候选地址 `/videos/factory-overview/`。沿用 BaseLayout、SiteHeader、SiteFooter 和现有播放器语言。初始 HTML 有可见播放器、准确标题、摘要、文字说明、封面和字幕入口；播放仍由访客决定，不强制自动播放。

`已核实的视频资料 → 观看页 + VideoObject + 视频 sitemap → 首页 / OEM 真实入口`。

元数据与实际素材同源：时长从文件读取，首次发布日期、视频授权和场景说明有记录。不能拿文件修改时间当首次发布日期，不能把同步文案中的公司产能或认证直接当已核实事实。元数据缺失时先补资料，不伪造字段。

视频和封面验证 HTTP、MIME、HEAD、Range 与手机播放。视频本体不抢首屏图片的带宽；海报能先显示。视频地图列观看页面地址，播放器与结构化数据指向同一真实视频。观看页面进入索引与视频进入索引分别观察，不承诺出现视频结果。

## Blog 和业务关联方案

围绕实际查询词安排“一个搜索需求 → 一个合适页面 → 相关商品 → 询盘”。优先关联现有 OEM、耳机询价及样品检查内容，不为同义词批量写重复文章。后台保留人工审核；既有内容助手仅存私有草稿，不能替人公开。

文章中的关联采用普通可抓取链接，复用既有编辑器能力；若以后需要可配置的相关商品，单独增加有类型、可验证的引用，不在本模块引入通用 Meta→Action 执行器。Blog 分类没有当前必需性，不能为修一个并不存在的分类错误扩展后台。

## 分段、验证与恢复

5A 素材事实与页面草图，5B 观看页及地图，5C 文章和业务内链。新 UI 先给桌面/手机截图；检查键盘播放、字幕和加载占位。发布、修改封面及撤回后，观看页、地图和引用保持一致；草稿不能公开。

现有 Blog 发布直接更新公开版本，服务器按当前版本返回 HTML；不转回 GitHub 定时构建。代码回退不让新文章下线；不兼容新内容节点时需要可显示的文本/链接降级，不能静默丢内容。视频页出现技术故障时可暂撤新入口，保留原首页及原件，不删除业务资料。

GEO 继续依靠真实可引用事实、清晰来源和普通 SEO。当前 Google AI 报告仅作本平台观测，不能证明所有 AI 都引用本站；不把 llms.txt 或助手能读页面当作效果。依据：[Google 视频规范](https://developers.google.com/search/docs/appearance/video)、[AI 搜索与网站](https://developers.google.com/search/docs/appearance/ai-features)。

## 底层设计：素材登记与页面

新增 `lib/seo/video-record.ts` 类型与受版本管理的公开素材清单。字段为稳定视频身份、观看页path、真实title/description、文件与封面地址、duration、经确认的uploadDate、字幕/文字稿来源及发布状态。清单不放管理凭据，也不把公司所有视频默认公开。

新增 `pages/videos/[slug].astro`，复用现有页面布局和播放器；初始HTML输出真实video/source/poster和正文，元数据使用同一记录创建VideoObject与Breadcrumb。独立视频地图只列公开观看页，加入现有sitemap-index的合并逻辑。页面404、元数据、文件撤回和地图变化应一致，不能页面已撤回却保留索引入口。

视频文件先测实际元数据和Range，海报设宽高。播放器采用controls、playsinline及metadata或none预载，遵守减少动态效果；不自动下载整段大视频。封面需要模块01处理时复用派生版本，不为视频上线购买新流媒体服务。首次页面打开预算为1份HTML、1张海报、浏览器必要的元数据范围读取；完整视频只在播放时下载，实际Range请求数由浏览器行为另记。

案例页今天已经包含完整STAR正文和真实案例图；不为截图中的AI回答凭空新增案例单页。如果业务以后需要每案例独立URL，另有内容身份和页面设计，不能与本次故障修复混做。

## 底层设计：文章与商品关联

首期用现有编辑器普通链接，连接相关OEM页、分类和稳定商品URL，不扩展通用动作执行系统。人工确认文章关联后保存当前公开版本，`lib/blog/page.ts` 和文章服务器按当前版本渲染；不触发GitHub整站构建。仅在真实业务需要自动关联时，后续增加有类型的引用字段和对应允许字段适配，不能直接让Agent在正文里执行任意操作。

文章日常读取仍使用现有 `lib/blog/server-client.ts`，按部署配置中的固定API地址读取匿名公开文章和图片，不直连COS，也不携带管理员登录凭据。容器运行身份不等于网站管理员身份；私有草稿仍由已登录后台通过受保护入口预览。恢复旧渲染程序不能撤销新文章或重公开撤回文章。

## 小任务与验收

| MIU | 结果 | 验证 | 依赖 |
|---|---|---|---|
| CONTENT-1 素材事实 | 一条真实视频及可核对元数据、文字稿、授权 | 文件与封面可读，duration真实，日期有来源；缺事实明确缺项，不猜值 | 业务素材核对 |
| CONTENT-2 观看页 | 独立页面、结构化数据、视频地图及自然入口 | 无JS可见播放器；手机播放、Range、字幕；正文/地图/状态一致；UI截图 | CONTENT-1 |
| CONTENT-3 内容关联 | 现有文章到相关业务/商品的自然链接 | 预览、人工发布、更新、撤回；技术恢复保留当前文章；记录真实点击/询盘而非承诺增长 | 当前Blog链路 |

上线后分别记录观看页普通索引和视频索引；检测通过不写成视频已经被Google展示。
