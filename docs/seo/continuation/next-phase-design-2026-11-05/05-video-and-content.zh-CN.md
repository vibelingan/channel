# 05 视频观看页与业务内容关联

## 要解决的问题

Google 报告发现首页视频，但未将其作为视频收录，原因是首页主要目的不是观看该视频。这不需要把首页改成视频站。Blog 的编辑、图片、草稿、人工发布与实时 HTML 已有实现，本模块不重做这些功能，也不新增助手权限。

## 视频方案

新增一张真正以现有视频为主体的观看页，候选地址 `/videos/factory-overview/`。沿用 BaseLayout、SiteHeader、SiteFooter 和现有播放器语言。初始 HTML 有可见播放器、准确标题、摘要、文字说明、封面和字幕入口；播放仍由访客决定，不强制自动播放。

`已核实的视频资料 → 观看页 + VideoObject + 视频 sitemap → 首页 / OEM 真实入口`。

元数据与实际素材同源：时长从文件读取，首次发布日期、视频授权和场景说明有记录。不能拿文件修改时间当首次发布日期，不能把同步文案中的公司产能或认证直接当已核实事实。元数据缺失时先补资料，不伪造字段。

视频和封面验证 HTTP、MIME、HEAD、Range 与手机播放。视频本体不抢首屏图片的带宽；海报能先显示。视频地图列观看页面地址，播放器与结构化数据指向同一真实视频。观看页面进入索引与视频进入索引分别观察，不承诺出现视频结果。

## Blog 和业务关联方案

围绕实际查询词安排“一个搜索需求 → 一个合适页面 → 相关商品 → 询盘”。优先关联现有 OEM、耳机询价及样品检查内容，不为同义词批量写重复文章。后台保留人工审核；既有内容助手仅存私有草稿，不能替人公开。

文章中的关联采用普通可抓取链接，复用既有编辑器能力；若以后需要可配置的相关商品，单独增加有类型、可验证的引用，不在本模块引入通用 Meta→Action 执行器。Blog 分类没有当前必需性，不能为修一个并不存在的分类错误扩展后台。

## 分段、验证与恢复

5A 素材事实与页面草图，5B 观看页及地图，5C 文章和业务内链。新 UI 先给桌面/手机截图；检查键盘播放、字幕和加载占位。发布、修改封面及撤回后，观看页、地图和引用保持一致；草稿不能公开。

现有 Blog 发布直接更新公开版本，服务器按当前版本返回 HTML；不转回 GitHub 定时构建。代码回退不让新文章下线；不兼容新内容节点时需要可显示的文本/链接降级，不能静默丢内容。视频页出现技术故障时可暂撤新入口，保留原首页及原件，不删除业务资料。

GEO 继续依靠真实可引用事实、清晰来源和普通 SEO。当前 Google AI 报告仅作本平台观测，不能证明所有 AI 都引用本站；不把 llms.txt 或助手能读页面当作效果。依据：[Google 视频规范](https://developers.google.com/search/docs/appearance/video)、[AI 搜索与网站](https://developers.google.com/search/docs/appearance/ai-features)。
