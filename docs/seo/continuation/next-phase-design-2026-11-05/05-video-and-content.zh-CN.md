## 要解决的问题

Google 报告发现首页视频，但未将其作为视频收录，原因是首页主要目的不是观看该视频。这不需要把首页改成视频站。Blog 的编辑、图片、草稿、人工发布与实时 HTML 已有实现，本模块不重做这些功能，也不新增助手权限。

## 视频方案

新增一张真正以现有视频为主体的观看页，候选地址 `/videos/factory-overview/`。沿用 BaseLayout、SiteHeader、SiteFooter 和现有播放器语言。初始 HTML 有可见播放器、准确标题、摘要、文字说明和封面；本次素材没有音轨，以可见场景说明提供文字替代，不伪造字幕。播放仍由访客决定，不强制自动播放。

`已核实的视频资料 → 观看页 + VideoObject + 视频 sitemap → 首页 / OEM 真实入口`。

元数据与实际素材同源：时长从文件读取，素材来源和场景说明有记录；首次发布日期未知时明确记为未确认。不能拿文件修改时间当首次发布日期，不能把同步文案中的公司产能或认证直接当已核实事实。缺少必填事实时省略相应结构化条目，先补资料，不伪造字段；视频地图采用已确认的必需资料。

视频和封面验证 HTTP、MIME、HEAD、Range 与手机播放。视频本体不抢首屏图片的带宽；海报能先显示。视频地图列观看页面地址，播放器与结构化数据指向同一真实视频。观看页面进入索引与视频进入索引分别观察，不承诺出现视频结果。

## Blog 和业务关联方案

围绕实际查询词安排“一个搜索需求 → 一个合适页面 → 相关商品 → 询盘”。优先关联现有 OEM、耳机询价及样品检查内容，不为同义词批量写重复文章。后台保留人工审核入口。另一个已授权的直接发布流程中，客户明确要求公开时，由发布助手调用受限发布工具；内容助手负责创作或修改，发布助手负责发布。默认不明确的任务先保存草稿并询问，不能自行推断公开意图。本轮真实工具保存、图片、发布、重试与撤回已通过；发布助手反向交给内容助手改稿及群内自然语言完整协作仍需分别验收，不能用工具联测代替。

文章中的关联采用普通可抓取链接，复用既有编辑器能力；若以后需要可配置的相关商品，单独增加有类型、可验证的引用，不在本模块引入通用 Meta→Action 执行器。Blog 分类没有当前必需性，不能为修一个并不存在的分类错误扩展后台。

## 底层设计：素材登记与页面

新增 `lib/seo/video-record.ts` 类型与受版本管理的公开素材清单。字段为稳定视频身份、真实标题/描述、文件与封面地址、时长、首次公开日期的确认状态、素材摘要、场景说明及发布状态。观看页地址由稳定身份生成。清单不放管理凭据，也不把公司所有视频默认公开。

新增 `pages/videos/[slug].astro`，复用现有页面布局和播放器；初始HTML输出真实video/source/poster和正文，元数据使用同一记录创建Breadcrumb；只有日期有来源时才创建完整VideoObject。现有普通sitemap的观看页条目直接加入video扩展，只列公开记录，不新增重复地图。页面404、元数据、文件撤回和地图变化应一致，不能页面已撤回却保留索引入口。

视频文件先测实际元数据和Range，海报设宽高。播放器采用controls、playsinline及metadata或none预载，遵守减少动态效果；不自动下载整段大视频。封面需要模块01处理时复用派生版本，不为视频上线购买新流媒体服务。新增页面自身的资源预算为1份HTML、1张47,880字节海报；沿用页面布局原有的字体、样式和导航请求，不把它们算成零。preload=none让视频在播放前不发请求，实际Range行为由浏览器单独核对。

案例页今天已经包含完整STAR正文和真实案例图；不为截图中的AI回答凭空新增案例单页。如果业务以后需要每案例独立URL，另有内容身份和页面设计，不能与本次故障修复混做。

## 底层设计：文章与商品关联

首期用现有编辑器普通链接，连接相关OEM页、分类和稳定商品URL，不扩展通用动作执行系统。人工确认文章关联后保存当前公开版本，`lib/blog/page.ts` 和文章服务器按当前版本渲染；不触发GitHub整站构建。仅在真实业务需要自动关联时，后续增加有类型的引用字段和对应允许字段适配，不能直接让Agent在正文里执行任意操作。

文章日常读取仍使用现有 `lib/blog/server-client.ts`，按部署配置中的固定API地址读取匿名公开文章和图片，不直连COS，也不携带管理员登录凭据。容器运行身份不等于网站管理员身份；私有草稿仍由已登录后台通过受保护入口预览。恢复旧渲染程序不能撤销新文章或重公开撤回文章。

### 现场发现：官网网关没有正确返回视频分段

对既有公开视频做只读对照，同样两个请求范围（开头1KB、第1MB处1KB）：

| 读取入口 | 实际结果 | 含义 |
|---|---|---|
| 既有官网地址 | 两次均200，长度7,201,197，无Content-Range | 返回整段，未满足本次分段请求 |
| 按既有管理身份签名读取COS源站 | 两次均206，各1,024字节；与原文件相应字节一致 | 文件和源站支持分段；签名不进入页面或日志 |
| 未签名源站 | 403 | 不能把私有源站地址直接塞入公开页面 |

请求头改为小写range、Accept-Encoding=identity以及Chrome形式User-Agent后，官网仍返回200。当前域名接入为DIRECT，静态路由没有删除请求头的自定义规则，只有既有响应Cache-Control设置；本轮未改配置。真实官网浏览器拖动时也发出了Range请求却得到200，跳到第80秒未能在20秒内完成，后续能读到该处画面；不能把最终读到画面写成拖动验收已通过。原文件的moov元数据已经位于第32字节，不存在需把尾部索引移到文件头的优化，不能靠重编码假装修好了。

这把问题缩小到网站网关到静态资源的交付路径，尚未证明有可用的网关开关能修正。当前不新建转发函数、不公开桶、不把短期签名作为稳定视频地址、不为过验收篡改206断言。后续先确认腾讯现有托管是否有受支持的Range设置；如无，再与既有静态CDN模块一起评估同一公开视频的稳定媒体域和分片回源。CDN/域名/计费需另行确认，不能偷偷启用。普通网页进入索引和视频进入索引仍分别由Google判断。

### 11 月 19 日续查，现有文章服务可按需返回视频字节

同一个官网域名，给两种入口发送带字节范围的请求。静态托管的工厂 MP4 收到“只取前 1,024 字节”时，实际返回 200 和全部 7,201,197 字节。文章服务上一份已经上线的 CSS，收到“取第 100 至 199 字节”时返回 206、正确的 Content-Range 和整整 100 字节。这把限制进一步缩小到静态托管入口。CloudBase 网关能够把分段请求交给现有文章服务，并把 206 送回浏览器。

在 Chrome 149 的手机视口，使用实际官网 MP4、约 160 KB/s 下载和 120 毫秒延迟，三次开播约 2.73～2.78 秒。跳到 80 秒时 Chrome 发起新的 Range 请求，三次均收到 200，17 秒内画面没有恢复。再用同一视频的真实字节，在同速条件下做本机候选对照。

| 实验方案 | 三次正常开播 | 三次从开头跳到第 80 秒 |
|---|---|---|
| 模拟现有静态入口，忽略分段请求 | 1.024 / 0.993 / 0.984 秒 | 三次均超过 17 秒 |
| FFmpeg 保留原画面编码，只切成 HLS 文件，浏览器从头用分段播放 | 5.798 / 5.781 / 5.786 秒 | 4.642 / 4.633 / 4.674 秒 |
| 先播 MP4，发生远距离拖动后切到 HLS | 0.981 / 0.958 / 0.973 秒 | 10.674 / 10.627 / 10.494 秒，切换后仍先下载开头片段 |

### 最初对静态托管分段的调查


现有默认测试域名也返回200整段；这不是换一个CloudBase默认域名就能解决的问题，而且默认域名不宜用作生产替代。当前已试过两段字节、不同请求头、真实浏览器、官网/默认域/签名源站/未签名源站，并核对网关规则和原文件索引位置。只读对照证明：视频文件没有损坏，源站可分段，当前STATIC_STORE网关路径未满足分段请求；未找到官方已公开的对应开关。这不等于腾讯所有托管产品都不支持Range。

最初考虑让腾讯确认静态入口的分段能力，以及模块 07 的稳定媒体域、私有 COS 回源和分片读取能力。现有文章服务的分段能力实测成立后，本次观看页先通过该服务交付。媒体域只公开这份已公开视频和海报，不改变原桶权限；文章私图、商品受保护图片和接口仍保留当前权限边界。上线前须先证明206字节与原件一致、浏览器拖动可用、旧页面仍能播放，并核对备案/证书、GSC媒体域所有权和实际费用。该动作涉及新的域名/加速配置，当前没有启用。

不推荐把临时签名写进地图（会过期）、为了此视频新增常驻转发服务、把7MB视频复制进文章服务器镜像，或把缓存策略改成全部公开。这些会增加权限、运行或维护成本，却没有先证明能修复当前网关。

如需技术支持，现有公开地址足够复现：对`https://supplychainsai.com/media/oem-factory.mp4`发GET并带`Range: bytes=0-1023`。预期206及`Content-Range: bytes 0-1023/7201197`，实际200及整段Content-Length；源站同请求为206且字节一致。向支持方提供上述安全事实和请求时间即可，不能提供密钥或临时签名。这里仅准备复现说明，尚未提交工单或联系第三方。
