# 04 商品搜索展示与真实报价

## 问题和目标

代表商品已进入普通索引，同时 Product snippets 提示缺报价、评论或评分。两件事并不矛盾。目标是让有依据的商品得到正确的机器可读描述，不能为消除红色提示填 0 元、假评分或会员价格。

## 推荐结构

`当前批准商品 + 匿名可见报价规则 → 共用报价适用性判断 → 页面可见内容 / 初始 HTML / JSON-LD`。

复用现有 pricing 的公开投影与批准变体规则；本模块不改变后台报价算法、价格权限或同步数据。旧 `catalog-seo.ts` 的报价拼装不能直接替换独立商品页逻辑；先核对页面对应的商品、配置、数量、币种和价格有效性。

| 真实情况 | 输出规则 |
|---|---|
| 对所有访客公开且适用于该页面的报价 | 页面与 Offer 同源，金额、币种、条件与商品地址一致 |
| 只询价或会员价格 | 保留普通网页收录、正文和面包屑；不生成缺必要数据的富结果 Product 节点 |
| 多配置、阶梯价或最小数量 | 先说明页面实际对应内容；使用官方支持的表达，不拿跨变体最低价代表整件商品 |
| 有可核对的真实公开评价 | 按真实数据处理；没有就不输出评论和星级 |

Google 商品摘要要求名称加 offers、review 或 aggregateRating 中至少一项。AggregateOffer 不能作为一组不同变体的捷径。纯询价商品暂不追求价格增强结果，是对业务事实的表达，不代表放弃普通网页收录。

## 交付与验收

4A 明确报价适用规则与匿名字段；4B 接入独立商品页；4C 小批真实页面做 Rich Results Test，再扩大。需要业务确认的是价格及条件真实性，而不是让客户设计 schema。

局部覆盖无价格、固定价、阶梯、缺币种、0/负数、未读全变体、撤回和会员价；核对 HTML、JSON-LD、API 一致。真实网页查看同一报价，图库、数量与询盘照常使用。当前报价变化沿用已有自动交付，不另建价格队列。

失败只回退搜索描述生成程序，保留当前商品与报价；保守回到普通 WebPage、Breadcrumb 和完整商品正文，不泄露字段。验收承诺准确、可抓取和符合适用规范；是否展示价格或更高排名由搜索平台决定。

依据：[Google 商品摘要规范](https://developers.google.com/search/docs/appearance/structured-data/product-snippet)。与 [01 图片](01-images.zh-CN.md)共用可读取的公开图片地址，与 [03 分类](03-discovery-and-urls.zh-CN.md)共用稳定商品身份。
