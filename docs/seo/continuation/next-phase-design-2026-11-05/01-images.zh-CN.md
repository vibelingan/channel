# 01 图片可靠交付

> 2026-11-12：三个线上样例仍返回400，本模块尚未实施。以下高层方案保留，具体实现与小任务已补在后面；用户本轮要求先设计，不把方案当修复。最新执行边界见[执行计划](EXECUTION.zh-CN.md)。

## 目标与现状

先让已发布商品的图片稳定显示，再减少不必要的下载。三张大图的 Alibaba 来源正常、字节与存储记录一致，但网站通过事件型云函数返回 Base64 时遭遇 6MB 响应限制。[实际对照](IMAGE-SOURCE-CHECK.zh-CN.md)。这不是 robots 或建立文章分类能解决的问题。

## 推荐结构

`原图 → 校验与生成网页版本 → 产物记录 → 现有发布引用检查 → 公开图片入口 → HTML / React / 搜索图片字段`。

原图保持原样。新增网页用途的版本：商品卡片、详情大图、文章正文与封面。产物记录原图摘要、生成规则版本、实际格式、宽高、字节数与产物摘要；同一原图、同一规则重试复用产物。人工 alt、裁图与文章插图位置仍由现有内容记录管理，不让生成任务覆盖。

默认修复沿用现有图片身份和公开引用判断。旧 `/api/images/{id}` 返回可交付的网页版本并给准确 MIME；不能让旧地址永久留着 400。新 HTML 按用途选择版本、输出宽高和 `srcset`。首屏主图优先，下方图片按需加载；是否 preload 由实际时序决定。

上传原图大小与响应大小分别校验。事件型函数只交付有充分余量的小版本，实施时同时测试最终序列化包体，不能只看压缩前图片大小。若高质量版本无法适合该入口，改用受相同发布检查保护的原生 HTTP 字节服务；先核对真实路由与部署成本，不未经验证把商品交付挂到 Blog 服务。质量不够时报告失败，不靠无上限降低画质强行通过。

## 与其他模块的约定

- 商品和 Blog 共用产物描述，继续使用各自的发布、引用和私有预览规则。私有图片通过已登录接口返回字节，再以浏览器 Blob 显示；不公开桶、不把签名地址写进正文。
- 已发布图片仍受当前引用检查保护。首期不加跨请求共享长缓存；版本号只解决内容混淆，不能代替撤回授权。离线保存或已经下载的图片无法从访客设备抹除，这不属于 CDN 能保证的范围。
- 商品或文章公开前准备好必要版本，生成失败保留当前可工作的公开版本；不将草稿半成品加入 sitemap。历史三张失败图逐张补产物，之后分批处理现有图库，避免瞬间全库重编码。
- 公开价格、商品审批和跨文章共享图片引用继续使用现有规则；不改 pricing 的数据格式或同步逻辑。

## 分段交付及验收

| 段 | 交付结果 | 检查 |
|---|---|---|
| 1A | 原图与网页产物记录、受限生成 | 畸形文件、超大像素、透明图、文字信息图、相同任务重试；实际解码与摘要正确 |
| 1B | 三个失败地址可显示，旧地址兼容 | 正常 GET/HEAD、MIME、宽高、完整解码；旧地址不再返回平台错误；私有和撤回不能读取 |
| 1C | 商品与文章选择适合尺寸 | 桌面/手机截图，图库、放大、正文和预览；人工 alt 与位置不变；首屏字节和 LCP 对照 |

真实交付还覆盖共享引用、待确认引用、计数损坏、撤回、旧任务晚到、生成失败和恢复。先做隔离资源，再在明确范围内交付三张现有图；不改客户文字，不重新建文。

## 恢复与完成标准

切换产物前保存原映射和可工作的程序版本；原图不删除。失败回到已验证可显示的版本；原先 400 的地址本身不是可用恢复方案。程序恢复不撤销后来发布的文章或人工图片修改。

完成标准是三个样例实际可显示、受保护资源没有泄露、交互和图片质量通过；性能改善另报真实数值。涉及 CloudBase SDK 时执行仓库契约核对与 `pnpm verify:cloudbase-sdk`，依据已安装运行时，不自行补不存在的方法。[官方限制摘要](evidence/cloudbase-response-limit.md)。

## 底层设计：原图、网页版本与交付

图片准备程序属于 Channel 后端，首段以受控 Node 命令运行；后续由现有图片上传、来源同步完成处理调用同一函数。它不调用模型，使用执行环境现有 CloudBase 凭据读写本网站私有存储。公开图片接口仍属于现有 public-api Event Function。浏览器不拿管理凭据；公开引用检查决定是否允许看图。

复用 `packages/media-storage` 的存储注入、读取上限及真实像素校验。当前该包已依赖 Sharp 0.35.5，已有 `decodeCatalogImagePixels()`；新增 `renditions.ts` 与显式包导出，不再引入另一个图片服务。原图读取使用现有 `mediaStorage()`，不经当前会超限的公网图片地址，也不从任意用户 URL 下载，避免把处理器变成开放代理。

新增私有产物表 `imageRenditions`（设计名，未创建），不覆盖原图记录。记录的允许字段为：`imageId`、`sourceSha256`、`policyVersion`、`state`、`variants`、`createdAt`、受限错误代码。`variants` 每项仅含宽高、MIME、实际字节数、SHA-256、私有存储身份。公开接口不得直接返回整条记录或存储凭据。

- 确定身份为 `imageId + sourceSha256 + policyVersion`；对象路径使用这些不可变身份及允许尺寸，不含客户输入的文件名。相同任务重试复用已校验产物。
- 首版长边目标320、640、1280像素，只缩小、不放大。照片优先WebP；带透明背景保留透明度；文字图先检查清晰度，必要时保留PNG。动画/SVG不静默变成静态帧，保持旧的安全交付规则，作为单独兼容分支。
- 首屏图片目标不超过500KiB；所有经Event响应交付的网页版本硬上限暂定2MiB，并检查最终序列化响应不超过4MiB，给6MB平台限制留余量。500KiB是性能预算，2MiB是传输保护，两者不能混用。质量不够时阻止切换并报告，不连续降低画质到不可读。
- 状态为 `preparing → ready` 或 `failed`。同一身份有一个存储级生成占用；超时接手要核对旧执行者，不能只因时间到就重复写。产物全部读回、像素与摘要正确且原图身份未变，才用条件更新登记ready。旧任务不能把新来源的映射写回。
- 首段仅处理三张已知大图。接真实生产者时，放在已有图片验证与就绪步骤内，共用相同准备函数和已有重试状态；不在浏览器GET里解码原图，不额外增加常驻服务或高频扫描。对大图准备未完成的发布步骤显示“图片仍在准备”，失败可重试，不能声称发布图片已就绪。集成阶段必须验证现有保存/同步调用方，不能只交一个无调用方的工具。

## 底层设计：旧地址兼容与权限

`getCatalogImage()` 保留现有占位图、有效发布引用、账本及历史记录规则。检查通过后，同一次请求内使用已确认的图像身份读取ready产物；不在每个helper重复核对引用。`/api/images/{id}` 默认选择1280或较小可用版本；可新增允许值为320/640/1280的 `w` 参数。参数严格校验，不支持任意格式、原图路径或远程URL。原URL继续可用。

先准备产物、后切读路径。原图未变化时，小于传输预算且原入口可工作的历史图可继续旧交付；已知超限图不能退回会400的旧响应。缺产物的大图返回明确暂不可用状态，页面保留失败反馈或占位，后台能重试；上线验收必须确保三个目标均已ready，不能用占位当修复成功。`product-snapshot.ts` 当前只接受不带参数的商品图片路径，首段沿用旧URL；响应式参数扩展与快照解码在同一后续MIU修改，避免“新增URL被构建拒绝”。

响应MIME来自实际产物，保留nosniff与SVG的CSP。首期新产物响应采用 `no-store`，并修正旧入口当前 `public,max-age=3600` 的撤回窗口；发布前说明旧缓存最多仍存活一小时，云端按已有能力精确失效，浏览器已下载副本无法撤销。不要把版本号当访问权限。私有后台继续走登录字节接口与Blob预览，不顺带改为公开链接。

每张原图首次准备预算：1次源文件读取、最多3次产物写入与3次读回；已有ready版本不再读写字节。每次公开GET调用一次现有引用判断、最多一次产物记录读取和一次小图读取；引用账本内部的必要读取按现有实现计量，不虚报为一次数据库请求。无效参数在存储读取前拒绝，无引用时不读取图片字节。

## 小任务与执行顺序

| MIU | 最小可验收结果 | 验证与完成证据 | 依赖 |
|---|---|---|---|
| IMG-1 生成与登记 | 本地三类真图生成、重试复用、来源变化不覆盖 | 解码、透明图和文字图看图；一次来源竞争缺陷注入应使测试失败；调用数记录 | 无 |
| IMG-2 修三张实际图 | 受控准备产物，旧URL返回可解码图片 | 三个真实GET为200/正确MIME/完整图像；原图摘要不变；私有/撤回仍拒绝 | IMG-1，写入范围另审 |
| IMG-3 接上传与同步 | 两类真实入口都准备网页版本并暴露失败 | 隔离真云图片上传、重试、同步完成到公开GET；不写真实商品 | IMG-2 |
| IMG-4 响应式与文章复用 | 商品和文章选适合尺寸，人工alt与排版保留 | 同视口前后图、图库/放大/后台预览；LCP与字节对照 | IMG-3，公共字段兼容 |

恢复只切回可工作的产物映射和程序；保留原图及客户文字。若恢复来源仍会超限，则停止，不能把旧故障重新上线。原图、产物与私有表均不安排自动批量删除。
