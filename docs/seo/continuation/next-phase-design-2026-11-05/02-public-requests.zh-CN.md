# 02 公开页面的请求与诊断

> 2026-11-12：本模块只设计，不实施全站请求重构。分类400的旧结论已撤回；仅在测出不必要调用或具体缺陷后改对应公开页面。

## 先更正问题

不新建 Blog 分类来解决 400。该接口读的是全站商品导航分类；缺少必需的 `family` 时 400 是正常校验，有效大类即使没有子分类也能返回 200。54 份美国报告中的 222 次请求全部 200；本机 Blog 样本未记录失败请求。[完整参数的复核](evidence/taxonomy-trace-review.json)。

旧采集脚本保存网址时统一删除查询串，因此从 `/api/catalog-taxonomy` 不能判断浏览器到底有没有传参数。后续采集只保留公开、无敏感内容的允许参数，例如 `family`、`page`；仍删除凭证、搜索输入等敏感参数。不能为了查错开始全量保存 URL 或请求头。

## 目标结构

`共用 HTTP 处理 → 有类型的商品 / 分类接口 → React 业务查询 hook 或 Astro 导航调用`。

共用 HTTP 层处理 URL、取消、总超时、响应校验及统一错误；接口层明确参数与公开字段；业务层决定缓存、分页、重试与刷新。沿用已有 API envelope 和 React Query 依赖，不再为每个新页面手写一套请求状态机，也不在这次把后台、sales 和 pricing 全部重构。

React 页面使用现有 QueryClient 模式，query key 包含大类、筛选、页码、商品版本及必要身份范围。构建快照作首轮显示数据；挂载后仍读真实 API，不把有快照等同于数据永久新鲜。分页固定完整版本；版本变化按业务规则重启，迟到结果不覆盖新商品。

Astro 导航本身不是 React 岛，不为使用 React Query 强行引入 React。它可复用同一类型接口和页面级同条件请求合并。先测同一条件是否真的重复，再引入共享在途请求；取消一个使用者不得取消其他使用者。服务端不放跨客户、跨请求的全局身份缓存。

## 请求规则

| 情况 | 行为 |
|---|---|
| 合法空分类 | 成功显示空列表，不报故障、不偷偷换大类 |
| 缺参、权限、字段不合法 | 保留明确错误；不无穷重试，不用空数组假装成功 |
| 暂时网络失败或限流 | 有上限的重试，遵循 Retry-After；总时限覆盖完整读取 |
| 换商品、离开页面 | 取消不再使用的请求；同条件共享者仍能完成 |
| 恢复标签页、重新联网 | 按公开数据的新鲜度策略刷新；不得污染会员价 |
| 已发布内容变化 | 以真实 API 为准；不等待下一次网站构建才更新当前页面 |

## 分段、验收与恢复

2A 先补可判别的记录和调用清单，区分预取、交互触发、页面切换和真实重复。2B 只收敛已证实的公开调用方；2C 再把商品业务请求按现有交互迁移，避免一次改动全站。

关联测试验证参数、错误类型、双使用者取消、晚响应、身份变更与重新联网；浏览器验证导航、空大类、分类筛选、详情与询盘入口。比较相同场景实际请求次数和时序，不以源码“用了缓存”判定减少请求。

本模块不改后端分类数据或强制创建文章分类。恢复只回退本段调用代码，保留 API 契约；实现时先与最新 main 核对，重叠的公共请求层设计供其他工作流参考，未经确认不改它们的文件。

## 底层设计：请求的三层职责

现有 `lib/api-url.ts`、`lib/api-envelope.ts` 负责地址与响应格式；`islands/shop/api.ts` 和 `catalog-taxonomy.ts` 有公开业务解码；React Query目前主要在后台使用。新增 `lib/http/request.ts` 处理浏览器HTTP生命周期，`islands/shop/queries/` 包装商品业务请求。后台、Sales与Hermes的调用本次不迁移。

拟议 `requestJson({url,signal,timeoutMs,headers,decode})` 接收 `unknown` 并调用真实解码函数，返回已经验证的数据。错误保留网络、超时、HTTP状态、业务代码四种来源；只记录路由类别及允许公开参数，不保存Authorization、客户输入或完整查询串。默认总超时15秒，覆盖响应头与正文；一次重试只能由业务查询层负责，避免两层各重试造成倍增。

浏览器发起的每个请求独立核对当前登录状态。匿名和会员价格使用不同query key；登录、退出与角色变化时取消旧查询并移除相应缓存。服务端是否允许看到会员字段仍由API决定，浏览器缓存不是授权依据。SSR只注入匿名数据，不把用户token写进HTML或全局进程缓存。

## 底层设计：React与非React分别接入

- React：在公开目录根岛创建每页一个QueryClient，商品列表、详情和报价共享它。类型接口与现有解码保留。query key包含数据类型、身份范围、family、规范化筛选、页码或cursor、必要内容revision。只在组件中声明查询，不手写并行的loading/error状态机。
- 初始快照通过 `initialData` 或明确的hydration数据提供正文；挂载后的查询仍刷新。商品详情用 `staleTime:0`、挂载/恢复焦点/联网刷新；价格不持久化到localStorage。分类导航可用60秒页面内缓存。不要用“请求少了”牺牲刷新后看到最新数据。
- 必需的分页继续使用现有revision规则。变体未读全就继续有界分页，不能为了请求数少截断变体；身份或revision变化时清空旧分页，迟到结果不得提交。URL选中变体属于页面状态，不触发无关详情全量重读。
- Astro导航不引入React。给 `catalog-taxonomy.ts` 增加每个family的页面内在途请求合并及60秒成功缓存；成功空数组可缓存，失败不当成功缓存。使用者退出仅解除订阅，最后一个使用者退出才取消底层请求；页面卸载释放。

普通打开分类页预算：一个当前页列表请求，导航按需每family最多一个在途请求；不预取四个大类的全部商品。打开某件详情，初始详情一个请求，额外变体页按真实完整性需要计数。请求次数按同一用户动作核对，后台自己的QueryClient不在此预算内。401/403/参数错误不重试；网络/429/503最多一次有界重试，重试遵循Retry-After和总截止时间，不叠加默认三次。
