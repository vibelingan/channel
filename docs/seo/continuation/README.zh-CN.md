# 商品自动更新与网站收录：进度和执行入口

更新于2026-10-30。沿用`feat/seo-foundation`，不新开分支或worktree，不改pricing和其他应用。这里汇总当前结果；每次失败、修复和早期测试保留在[工作记录](WORKLOG.zh-CN.md)。

## 先说现在能用什么

商品独立网址、首次打开就有正文、浏览器继续请求实时API，以及Blog后台、配图、私有预览和人工发布，之前均已部署并实际验收。Blog按请求返回当前文章HTML，日常发文章不用GitHub构建。

Blog正式域名已开放收录，临时地址、草稿、健康检查和错误页继续排除。两篇现有公开文章按用户确认保留；公开商品图片的robots规则也已修复并上线。10月30日再次读取全部539个公开网址，全部通过技术规则、与528个当前公开商品清单一致；[本次完整结果](evidence/live-all-pages-20261030.json)。10月30日重新读取 Google 单网址检查：Blog 列表已进入索引，Google 选定 canonical 与正式地址一致；一篇文章也已进入 Google 索引；另一篇历史抓取仍显示旧 noindex，但本次实时抓取已确认允许收录，等待重抓。Bing 地图成功、发现 519 个网址；Blog 实时检查允许收录，尚未进入索引。[平台逐项结果](evidence/platform-observation-20261030.json)。

**商品修改后自动更新初始HTML尚未开启。**本轮已把保存记录、完整内容比较、增量快照和上传保护接起来，并开始真实CloudBase验证；固定程序归档、定时检查和当前内容配旧程序恢复的代码及本地测试本轮已补；真实归档、定时器接入和正式 HTML 交付验收继续执行，开关仍关闭。以前用“SEO全部好了”概括这些不同步骤不准确，以本页逐项状态为准。

不清楚为什么API更新后还要更新HTML，先读[原理和四模块摘要](EXPLAIN.zh-CN.md)，或看[HTML与浏览器API对照图](diagrams/html-and-api.html)。普通访客与搜索引擎访问同一份初始HTML，没有专供Google的页面。

- 修复已知失败后的接手：确认没有未决云调用，才释放原执行者和任务；下一轮按当前内容重新交付。未知上传继续占用并等待读回，不因过期就放行，不用旧内容覆盖新商品。
- 修复并发请求的时间边界：较早请求可能较晚提交，公开日期不倒退，真实内容变化仍推进版本；首次纳入跟踪但历史日期未知时省略lastmod。

## 后续按这个顺序交付

1. 隔离云库和自动清理已通过；继续验证实际候选与HTML交付，不跳过未知结果读回。
2. 归档固定源码、锁文件和运行版本的渲染程序；支持旧程序读取当前商品资料，禁止代码恢复顺带倒退业务内容。
3. 接可靠唤醒与积压补漏；核对全部实际写入方、登记现有已验收页面，再受控开启记录和就绪状态，执行新增、修改、撤回及恢复验收。
4. 计量采集、构建、归档、上传和验收的完整耗时。常规批次争取八分钟内；未有实测前不承诺。随后接已验收变化事件，继续观察搜索平台。

本轮没有合并回main/test，也未开启商品记录或自动交付。原main/test在本轮开始时已包含于SEO分支；之后仍按实际远端提交核对，不影响其他工作流。
