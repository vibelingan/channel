# 商品自动更新与网站收录：当前实施状态

2026-10-29。沿用 `feat/seo-foundation`，不新开分支或 worktree，不修改其他应用。四个模块分别交付，已有功能继续使用。

先读[为什么API刷新了，服务器HTML还要更新](EXPLAIN.zh-CN.md)，也可以先看[浏览器与HTML的对照时序图](diagrams/html-and-api.html)。四份模块文档开头都有摘要，说明为什么做、改哪里和怎样验收。

## 目前已经做到了什么

商品独立网址、构建时正文、浏览器后续API读取已经实现并做过现场验收。Blog后台、图片、私有预览、人工发布与实时文章HTML也已经接通。日常发布文章不调用GitHub构建。

本轮正式开放了Blog收录：正式域名的列表、两篇已公开文章与sitemap允许收录；临时地址、草稿、健康检查和错误页继续排除。两篇文章按用户确认保留，没有改正文、日期或状态。正式入口与临时入口的实际HTTP结果已分别核对，三张已发布图片200且有alt，三个文章API的数据校验值与操作前一致。

Google已对Blog列表和两篇文章完成开放后的实时测试，均允许收录；三次重新收录请求也已被接受。首页与耳机分类页的独立报告显示已经收录。Google地图成功、发现539网址；Bing原地图成功、发现517网址；本轮重新提交现有地图已被接受，当前Processing。发现数量不是实际收录数量，两篇文章也不能因请求被接受就记作已经收录。

商品公开变更后自动更新静态HTML，目前仍未接通。此前把商品SSG、Blog功能的完成概括成“SEO全部好了”不准确；这里将已实现、已部署、已验收和仍待实现分开列明。

## 商品自动更新接下来怎样做

先做02的可靠待办：所有真正改变公开内容的写入入口，在同一个事务里记录商品与新版本。再做03：复用已验收模板和资源，只读取变化商品，合并连续修改，处理新增、撤回、旧任务和失败恢复。最后让04只消费已验收上线的变化。

本轮已找到一处可复现的额外重传原因：两个真实构建包的528个商品，正文及React参数完全一样，只有询盘日期输入的最早日期及随之变化的Astro标识不同，导致约54.37MB HTML重新上传。SSG-01须让初始HTML稳定，由浏览器设置访客当前日期，保留原有日期校验。[产物比较](evidence/product-html-date-diff.json)。不能简单删功能、跳过验收或手工修改HTML来提速。

新增商品在独立HTML就绪前，买家应能通过现有动态详情入口打开；页面验收后再使用规范独立网址和加入地图。撤回则要分清接口已撤回和静态文件已清理，不承诺异步重建能够立即完成404。两种过渡都已补入03的设计与测试要求。

目标是公开变更后一分钟内尝试启动，常规小批次端到端争取八分钟内；这是待验收目标。现有全站发布明显超时，不能直接接到每次商品保存后就宣称完成。Blog继续实时读取公开文章，不进入商品重建队列。

## 收录结果的判断边界

所有当前公开商品都参加，不新增资料完整度门槛。营销、分类、商品、正式Blog的正文、规范网址、链接、状态和地图一起检查；草稿、管理和私有预览继续排除。

普通网页收录与商品富结果分开。真实Offer或评价缺失可能让Product snippets不满足增强展示条件，但不等于商品页禁止普通索引。IDX-03只使用页面实际展示且适用范围明确的报价，不补虚构价格、评分或评论。

网站先交付正确页面，再让搜索引擎抓取。sitemap和重新抓取请求不把HTML直接写入Google索引，也不能保证每个公开网址都在固定时间内被收录。外部通知失败不会恢复网站或倒退数据库；代码恢复也不回灌客户文章、商品、凭证或新字段。
