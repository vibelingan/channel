# 03 编辑器和私有预览

2026-10-23：E1 已接入本地后台并验收保存/重开/文字预览；E2 媒体仍未接入，真实 CloudBase 与部署未验收。详见 [共同记录](NEXT-STEPS.zh-CN.md) 和 [本轮结果](03-editor-worklog-2026-10-23.zh-CN.md)。依赖 01/02。交付位置是现有后台内部，不另建 CMS 或要求客户跳去 Payload。

2026-10-22 用户补充：常用操作直接、方便，减少无用按钮和重复流程，UI 与现有后台一致。首屏优先标题和正文，主要操作为保存草稿和预览；SEO 等偶尔使用的设置折叠。预览可先保存再打开，不要求用户额外走一次手动保存流程。普通保存不增加确认；离开未保存内容和版本冲突才作必要提醒。后续顺序与真实浏览器验收见 [下一步计划](NEXT-STEPS.zh-CN.md)。

## 复用现有界面和请求方式

在 `apps/site/src/islands/admin/DashboardShell.tsx` 和 `sections.ts` 增加文章自定义栏目，沿用已有导航、Select、按钮、表单反馈和布局。文章正文复杂，使用独立 ArticleEditor 业务组件，不强塞进 RecordForm 的通用字段；文章列表仍沿用现有后台的表格和分页样式。

请求通过现有 `admin/api.ts` 的会话和请求封装，再包装 article API 与 React Query hooks。query key 包含当前账号和 articleId，登出清理私有缓存。保存用 mutation，成功后更新服务器 revision；取消旧查询、切换文章和冲突由统一 hook 处理，不在每个组件另写 fetch 生命周期。脏表单不能被窗口聚焦后的后台刷新覆盖，必须提示有新版本。

## 编辑器范围

使用 Tiptap OSS，锁定兼容的包版本，不安装 Pro、Cloud、AI、转换服务或协作组件。只启用 01 已支持的节点、标记和属性；H1、合并单元格、任意 HTML/CSS、脚本和 Meta→Action 不显示入口。先实际检查 StarterKit 自带节点，关闭本版本未支持的节点，不能依赖默认配置“应该差不多”。

`articleImage` 为自定义节点，持久化只存 mediaId、alt、caption、align。编辑器 NodeView 可以有选图/替换/删除工具，但这些工具不进入文章 JSON 或公开 HTML。正文 JSON 通过 `fromTiptapJSON` 保存，重新打开用 `toTiptapJSON`；未知版本提示升级，不把未知内容清空后自动保存。

首期旁边配置标题、slug、摘要、署名和搜索标题/描述；封面作为后续媒体关联字段单独定义，不把正文第一张图偷偷当封面。发布前可从标题建议 slug，但已经公开的地址不因改标题自动变化。

## 草稿、预览和图片

首期手动保存，有保存中、已保存、有未保存修改、保存失败和版本冲突反馈。离开脏表单前提醒。保存按钮不能在图片上传/校验未结束时提交正文。并发冲突保留本地输入，允许重新载入或复制内容，不自动覆盖别人的修订。

预览读取刚保存的指定 revision，展示“草稿预览”，不修改公开状态。未保存修改先保存成功再预览。浏览器和公开文章都使用 01 的渲染规则；预览只替换媒体访问方式，不另写一个宽松 HTML 解析器。纯 HTML 输出插入受控预览容器前必须来自共享渲染器，不能直接插入作者提供的 HTML。

私有图片通过现有鉴权媒体路由返回字节，前端创建同源 Blob URL；DOM 不放原始 COS 地址或私有临时链接。替换、移除图片、切换文章和卸载时撤销 Object URL，并取消旧图片请求。图片元数据、MIME 和尺寸由服务端已验证媒体记录提供，不相信作者填写的尺寸。预览页面要求登录、`no-store` 和 noindex；noindex 不能代替鉴权。

01 的正文媒体规则已实现；把文章接到现有上传、引用计数和预览权限的工作在本模块完成。不能直接把 articleId 当 productId 混用旧权限。需给媒体业务层增加明确的文章用途和归属检查，且不改其他用途的权限。

## MIU 与验收

| MIU | 独立交付 | 必须通过的检查 |
| --- | --- | --- |
| BLOG-E1 | 列表、编辑表单、Tiptap、保存和重新打开 | 真实编辑器 getJSON/setContent 对所有启用节点往返；刷新后不丢文；请求失败可重试；冲突保留输入；切换文章不串数据；未支持操作不可用 |
