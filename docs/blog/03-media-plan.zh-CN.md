# 文章图片接入计划

2026-10-23，基于 `c7ee6138`，继续同一 SEO 分支。沿用模块 03 的 BLOG-E2；不创建分支或 worktree，不部署，不写线上数据。共同进度继续使用 NEXT-STEPS，不另建任务系统。

| 顺序 | 实现内容 | 验收 |
| --- | --- | --- |
| 1 | 在内部 `articleMedia` 集合保存图片用途、所属文章、上传者及状态；同一个请求重试不多建记录，只有管理员能操作 | 本地真实存储与实际 SDK 离线事务：账号降级、文章不匹配、过期、并发完成、写入失败 |
| 2 | 复用媒体存储的签名 PUT；服务端核对字节长度、摘要、类型和尺寸，复制已验字节到浏览器不能覆盖的正式路径再激活 | 假扩展名、截断图、错误摘要、旧签名覆盖、响应丢失重试；保存正文拒绝未激活或别篇文章的图片 |
| 3 | 编辑页插图、替换、移除和图片说明；先保存新草稿取得归属，上传或校验中禁止保存正文 | 可视浏览器从真实 HTTP 上传到隔离文件存储，保存、重开、刷新，数据与字节读回 |
| 4 | 鉴权读取图片字节，编辑器和指定修订预览用 Blob URL；使用已有安全正文渲染器 | 未登录/非管理员/其他文章拿不到图；无 COS 地址进 DOM，替换/关闭/离开后取消请求并释放 URL |
| 5 | 回归、截图、审查、推送及远端 CI | 分别报告本地、SDK 离线和真实云端状态，不把测试传输当腾讯云验收 |

设计补充：文章媒体放在独立内部集合，不修改商品 `images`、商品引用计数或清理任务。用途固定为 `article-image`，归属在创建后不再改变；本期没有删除或变更归属的入口，因此正文保存前检查的已激活记录不会被并行撤销。文章正文最多 20 个不同图片，每张最多 3 MiB，JPEG/PNG/WebP；用服务器检测的尺寸并限制像素量。鉴权字节沿用管理 POST 接口返回编码内容，浏览器转换 Blob；不增加公开图片地址。公开 Blog 的图片发布在模块 04 另接。

浏览器上传凭据可以重复使用到过期，不能把校验时检查过的临时路径直接当最终图片。因此完成步骤把当时已核验的字节另存为不可由该凭据改写的内容摘要路径，记录只指向后者。重试通过固定请求编号和摘要判断；移除正文引用不删除图片，暂存对象清理另行明确授权。

本地签名上传测试只在 `--articles-only` 的临时服务中显式启用，禁止与 TCB_ENV 同用，服务仅监听回环地址。默认开发服务与云函数仍使用既有真实 CloudBase 路径，不把离线测试传输带入部署流程。
