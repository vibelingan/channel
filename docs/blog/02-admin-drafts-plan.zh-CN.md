# 后台草稿保存实施计划

依据：[已有设计](02-admin-drafts.zh-CN.md)。范围只到本地文章服务和后台请求接线，不创建 CloudBase 集合、不部署、不改 UI、pricing 或其他工作流。沿用原 SEO 分支，由当前会话完成实现和审查。

目标：管理员可以创建、读取、列出、保存、预览草稿；网络重试不重复创建，过期版本不能覆盖新内容，草稿编辑不改变已经发布的内容。

## 改动位置

- `packages/articles/src/draft-repository.ts`：窄的 `ArticleRepository`、摘要和错误类型。方法只接受文章相关参数，不接受任意集合或数据库命令。
- `packages/articles/src/draft-service.ts`：严格解析 `create/list/get/save/preview`；先检查请求大小，再解析正文；统一给出安全错误和冲突版本。
- `apps/local-server/src/article-repository.ts`：本地存储实现，复用现有 JSON 数据库的互斥锁和原子文件替换，不另造第二套锁。
- `apps/local-server/src/json-adapter.ts`：在同一存储锁内交出文章事务；失败时恢复旧状态。文章记录不进入通用 CRUD 注册表。
- `apps/functions/admin/src/handler.ts`：在原有 JWT 和当前用户检查后接入 `articleDrafts`，只准当前管理员使用；存储能力未配置时明确失败。
- `apps/local-server/src/main.ts`：把真实本地适配器注入后台配置。云函数入口不注入假存储。
- 两个消费文章核心的工作区增加 `workspace:*` 依赖并更新锁文件，不增加第三方包。

## 按顺序交付

- [x] 1. 后台入口拒绝未登录、普通会员、停用/删除/降级账号；未配置文章存储时明确失败。
- [x] 2. 创建与读取：服务和本地适配器接线；按操作者和 requestId 识别重复创建，相同请求号对应不同内容时冲突；重启后仍能读到草稿。
- [x] 3. 保存与并发：在原有文件锁内读取版本、调用文章核心、写回；同版本并发只能成功一次；相同内容不增加版本；冲突带当前版本。
- [x] 4. 列表与预览：列表只给摘要；按唯一文章编号稳定翻页；限制页长与查询字数；预览锁定已保存修订，只返回正文 JSON 和媒体编号。
- [x] 5. 异常与旁路：拒绝未知字段、过大请求、损坏存储和错误游标；通用 CRUD 不能读写文章；草稿保存保留公开引用和不可变快照。
- [x] 6. 审查、回归、类型检查、函数打包、本地 HTTP 检查；更新实际状态和下一步，按原分支交付。

每项先增加能失败的行为测试，看到正确的失败，再写实现。测试从后台 action 和真实本地适配器进入，不检查私有函数。需要纯格式校验时直接测文章核心的公开函数。新权限和版本保护还要临时移除保护，确认测试确实报警，随后恢复。

## 本次明确的实现选择

- `AdminConfig.articleRepository` 是可选依赖；CloudBase 未配置时返回明确的 `INTERNAL_ERROR`，不伪装保存成功。
- 请求数据上限先设为 256 KiB，单条本地存储记录不超过 384 KiB。这是本轮保守限制，不代表 CloudBase 已验收；接入真实数据库时再按官方上限核对。
- 创建去重按操作者和 requestId 配对，记住初始内容摘要；重试返回同一文章的当前状态，不把旧正文写回。
- 文章记录与创建去重信息一起原子保存。列表默认 20 条，最多 50 条；标题查询最长 100 字。游标绑定查询并按唯一 id 翻页。
- 本地事务再次核对操作者当前状态。存储记录和返回数据均经过运行时校验；遇到损坏明确报错，不静默清空或覆盖。

## 审查重点

最容易漏掉的是：保存期间被停用的账号、服务重启后的重试、两个进程/实例的旧读数、损坏记录被当成正常数据、以及列表或预览意外带出正文/私有地址。逐项记录验证结果；未做真实 CloudBase 测试就保留“未验证”。
