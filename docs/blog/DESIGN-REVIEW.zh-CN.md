# 本轮 Blog 设计审阅

2026-10-22。核对 10 月 16/18 日方案、当前后台与文章核心实现后，保留 Tiptap OSS、既有后台、Astro 静态正文、草稿与公开版本分离、Hermes 只写草稿的方向。以下只记录实际需要修正的地方。

| 发现的问题 | 本轮处理 | 后续验证位置 |
| --- | --- | --- |
| 原 BLOG-1 把编辑器、存储、发布、SEO、Hermes 放在一个任务中 | 拆成 01–05，每份模块文档自带接口、MIU 和验收 | 本目录 README |
| 原先建议另建 Blog 分支，与用户最新要求不符 | 全部沿用原 SEO 分支，不创建工作树 | 提交和远端 CI 记录 |
| 商品供应商 HTML 转换器允许降级，不适合作者正文 | 新文章核心拒绝未知结构，保留可迁移 JSON，不用 HTML 作唯一原件 | 01 的格式/往返/异常输入测试 |
| 保存、冻结内容和真正上线容易混为一谈 | 第一部分只能准备候选；不设置 publishedAt，不登记公开成功；04 单独验收交付 | 01 快照测试，04 任务验收 |
| 纯函数检查 revision 不能防数据库并发覆盖 | 02 明确事务内读、检查、写；本轮不声称已有原子保存 | 02 真实数据库并发测试 |
| 直接注册通用后台 CRUD 可能绕过发布/权限规则 | 独立文章服务和受限 Repository；沿用真实会话校验 | 02 权限和旁路测试 |
| 图片可预览不等于可公开，也不能把 COS URL 写入文章 | JSON 只存媒体编号；私有预览用鉴权字节和同源 Blob；公开引用另接 | 01 渲染测试，03 媒体 UI/权限，04 引用计数 |
| 自定义解析器和 Tiptap 默认功能可能不完全一致 | 明确启用节点范围，关闭合并表格/H1/未知节点；03 必须真实编辑器往返 | 01 当前只证明格式合同，03 才证明编辑器接线 |
| Agent 重试可能覆盖人工编辑 | 幂等创建一次，不做按外部任务反复覆盖；新生成另建草稿 | 05 幂等与人工编辑保护 |

本轮没有新增收费组件、通用 CMS、独立后台或任意脚本执行能力。封面、文章媒体持久化、真正数据库事务、编辑器 UI、公开页面和 Hermes 均保留在所属后续模块，不能因文章核心通过就算整个 Blog 完工。

文字审阅覆盖本目录六份模块/入口文档及本文。具体改写：将“publication candidate”“adapter contract”分别解释为“待发布快照”“前后端按同一约定读写的接口”，仅在代码标识符处保留英文。核对事实：现有后台确实使用 React Query、自定义栏目和实时会话校验；本轮包无数据库/网络依赖，不改现有 UI 或发布 workflow。
