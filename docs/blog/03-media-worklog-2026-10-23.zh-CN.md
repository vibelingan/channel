2026-10-23，继续原分支 `feat/seo-foundation`，起点 `c7ee6138d513dc30d2788c386f4c50247502de61`。本轮完成模块 03 / BLOG-E2 的代码和本地验收。没有新建分支、worktree 或 PR，没有部署、登录云平台或写线上资源；pricing 与正常部署 workflow 未修改。

## 现在可以怎样用

后台仍使用现有 Articles 页面。点击 Image 选择 JPEG、PNG 或 WebP；新草稿先保存取得文章编号，再上传图片。图片核验完成后进入正文，上传中不能保存正文或打开预览。图片下方可填写说明（alt）、图注和对齐，替换图片或移除正文中的图片。保存、重开、刷新后，正文和图片引用保持一致。

草稿预览从刚保存的指定修订读取正文，图片经管理员鉴权接口读取字节，浏览器生成 Blob URL；正文渲染仍使用同一个安全渲染器。页面不放私有 COS 链接。关闭预览、替换图片、移除节点、切换文章和卸载会释放 Object URL；账号相关请求走 React Query 和现有公共请求层。图片读取失败会提示重试，不把它伪装成公开图片。

图片从文章里移除，只修改正文引用，**不删除存储文件**。本期没有图片删除或更换归属的入口，也不运行清理任务。

## 存储与请求的具体接法

| 部分 | 当前实现 |
| --- | --- |
| 归属与权限 | 独立内部 `articleMedia` 集合，固定 `purpose: article-image`、articleId、上传者、文件摘要及状态。未注册到通用增删改入口；媒体事务同时检查当前 users 账号和所属草稿 |
| 上传请求 | 现有管理 POST 的 `articleMedia` action，严格区分 `intent` / `complete` / `preview`。稳定 requestId 和文件摘要用于重试去重，同一编号换文件会冲突 |
| 直传 | 沿用 `mediaStorage().getUploadCredential()`；商品和文章共用 `admin/api.ts` 的 `putImageUpload()` 发送原始字节。继续使用 PUT 和签名请求头，不添加另一套 COS 上传协议 |
| 完成上传 | 服务器重算实际字节长度与 SHA-256、检查文件签名及图像头尺寸，最多 3 MiB、边长 16384、总像素 3200 万；再把已核验字节保存到服务端的摘要路径，事务将记录切换为 active |
| 防止旧凭据覆盖 | 浏览器签名只能写临时上传路径；记录最终指向另存的正式路径。凭据未过期时重写临时对象，也不能改变已经核验的正式图片 |
| 保存正文 | 创建新草稿时不能夹带未归属图片；保存时最多 20 个不同媒体编号，每个必须是这篇文章已 active 的图片。记录本期不可删除和转移，因此这些前置检查不会被本期其他入口并行撤销 |
| 私有预览 | 返回已校验 MIME/尺寸及编码字节，不返回 storageFileId、原始地址或临时下载 URL。读取字节后再检查一次当前权限；无身份、降级账号或别篇文章都不能取得图片 |
| 商品边界 | 商品 `images`、发布引用计数、同步任务及清理任务不处理 articleMedia；公开 `/api/images/:id` 也不能读取文章集合。文章公开图片与引用规则留在模块 04 接入 |

本期图像检查使用 `image-size@2.0.4` 读取图像头，配合已有 magic-byte 与摘要检查；它不是完整的图片解码器。实际浏览器验收另外检查了图片可解码且 naturalWidth 正确。没有承诺所有损坏图片都能由图像头检测发现。

## SDK 与外部资料核对

先读项目的 SDK 核对规范和 CloudBase / Storage skill。Context7 本轮不可用，已通过 CloudBase MCP 的 `searchKnowledgeBase(mode=openapi, apiName=storage)` 取得官方 Storage OpenAPI，并检查安装包：`@cloudbase/node-sdk@3.17.2`、`wx-server-sdk@4.0.2`。官方原始接口和已安装 SDK 返回字段分开核对，未增加任何 SDK shim。

安装包 `dist/storage/index.js` 的发送函数确认签名使用 put，字节使用 raw PUT，凭据使用请求头；新增文章客户端调用同一个发送函数。`pnpm verify:cloudbase-sdk` 继续验证该协议，并且现在实际执行 16 项草稿与 4 项媒体 SDK 离线事务测试。它验证的是实际 SDK 代码加隔离传输，不是腾讯云在线实例。

依据：[CloudBase Storage API](https://docs.cloudbase.net/http-api/storage)、[image-size 官方仓库](https://codeberg.org/image-size/image-size)、[固定版本发布元信息](https://registry.npmjs.org/image-size/2.0.4)。同时检查安装包 `Readme.md`、`dist/esm/index.d.ts` 和实际 PNG/WebP 结果。新增依赖打入 admin 函数，构建后的 CJS 产物在没有 node_modules、禁止网络的临时目录可冷启动。

## 下一步现场验收怎样做

当前授权只覆盖离线开发，下面是待执行清单，不是已完成的操作。

1. 先读回最新 SEO / main 接口与现场状态；确定同事不在同一目标部署，明确测试身份、目标环境和测试前缀。未经新的范围确认，不创建集合或写业务数据。
2. 在获准范围显式准备 `articleDrafts`、`articlePublications`、`articleSlugs`、`articleMedia` 四个 ADMINONLY 集合并读回权限；准备函数仍未接入默认部署。核对存储读取规则、实际浏览器 origin 和 COS CORS，不能只证明自定义 API 不返回图片，就认定桶的原始地址也私有。
3. 用隔离测试草稿和 `articles/` 下的测试对象，通过本地页面接真实服务完成上传、保存、重新打开与预览；从真实存储读回摘要和尺寸。无身份/非管理员/其他文章不得读取，浏览器不得绕过服务直读私有对象。
4. 验证真实事务并发完成、修订冲突、权限变更、响应丢失重试及旧凭据覆盖临时对象后正式图仍不变；图片响应的实际函数大小上限也在现场检查。任何权限、归属、计数、摘要或业务数据异常立即停止，不用普通商品测试修正它。
5. 全程不发布文章、不改商品/价格/询盘。测试结束先撤销测试身份和请求入口，保留清单；如要删除测试草稿、暂存对象或正式测试图，先逐项核对测试前缀和引用，再按单独获准清单清理。不自动触发业务版本恢复或清空集合。
