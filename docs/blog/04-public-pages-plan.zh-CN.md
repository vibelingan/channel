# 公开文章页面这一段怎么交付

沿用已确认的模块 04，当前只做 BLOG-P1。保存草稿不会生成公开页面；本轮不增加发布按钮、不连接云资源、不改现有部署入口。

## 内容入口与图片

构建显式接收 `SEO_BLOG_SNAPSHOT` 文件。文件只包含已验收版本的公开字段、固定修订、正文 hash、公开日期及媒体清单；不接收草稿、候选版本或数据库整条记录。不配置时不生成 Blog 页面，保持当前站点范围；配置后文件缺失、格式错误、媒体不全都使构建失败，不偷偷输出空列表。

图片使用按内容 hash 命名的 `/media/articles/<mediaId>/<sha256>.<ext>` 静态地址。构建只读取快照旁 `assets/` 中精确列出的文件，核对字节、大小和 MIME；由 Astro 静态端点输出。私有 `articleMedia` 的存储路径和预览地址不进入快照或页面。后续发布器负责在权限检查、发布引用登记和交付完成后提供这份输入；当前文件格式本身不能证明真实线上验收。

这是对媒体交付方式的具体化：图片进入同一静态交付包，复用同一备份、文件清单与恢复流程。图片移除或文章撤回不自动删除存储原件。静态历史文件的撤回和缓存仍由后续共享发布器处理，本轮不声称实现。

## 页面与现有界面

`/blog/` 显示按公开日期排序的文章摘要，`/blog/<slug>/` 输出正文。沿用现有 SiteHeader、SiteFooter、PageHero、字体、品牌色及 article-body 排版；文章页增加面包屑、作者、真实日期及返回列表链接，不改商品页或全站菜单。

独立标题、canonical、Article/Breadcrumb、sitemap 都使用同一地址。没有显式 SEO 描述时依次取摘要、正文；没有 SEO 标题时用文章标题。无内容变化重建不改公开日期。页面不加载 Tiptap，不把草稿或内部验收信息放进浏览器。

## 检查与顺序

1. 先测严格公开数据格式：候选/草稿、错误 hash、重复身份、日期倒序、非法 slug、缺图和私有地址不能进入构建。
2. 实现快照读取和静态图片；测试资产越界、缺失、字节被换、大小不符和本地样本不能用于正式域名。
3. 实现列表、正文及 SEO，检查无 JavaScript 正文、真实链接、图片、表格、桌面/窄屏、缺失页面及日期稳定。
4. 生成本地独立目录的构建产物，实际启动并在浏览器操作。保留截图和字节/HTML 检查结果。回归已有商品构建、全仓测试、类型、lint，并推送原分支核对准确提交的远端 CI。

发布/更新/撤回任务、生产公开引用、真实 CloudBase 验收和 Hermes 仍是后续工作。生产启用前，部署器须拒绝漏带已上线 Blog 的快照，并验收旧文件删除/恢复不会复活撤回内容；本轮不接线正常 Deploy Test。
