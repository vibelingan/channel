# 内容助手接入：高层设计

状态：设计交付于2026-10-24，2026-10-26用户已同意在基础Blog和恢复验收后实现，并启动隔离的本地Hermes内容助手模拟。受限接口、格式转换、存储规则、MCP工具和后台直达链接已写代码并在本地验证；真实接线和模型联测尚未完成。不改Hermes生产配置，不向真实企业微信群发消息。

## 用户会怎样使用

客户仍在原企业微信群让内容助手写文章。助手完成后，额外调用一次“存成网站草稿”工具，确认网站已经保存，再回复文章标题和编辑链接。客户点击链接，使用网站现有账号登录，直接打开那一篇草稿；编辑、图片、预览和发布继续使用现有后台。

“助手生成好了”“网站存成草稿了”“已经公开发布”是三个不同结果。网站没有确认成功时，助手只能说明尚未确认保存，不能回复一个看起来成功的链接。发布由管理员决定，不交给模型。

## 两个仓库的责任

| 部分 | 责任与边界 | 本轮动作 |
| --- | --- | --- |
| Channel | 定义并实现草稿导入/结果查询 API；负责权限、事务、版本保护和编辑链接 | 只交付本设计 |
| Channel 工具适配器 | 对 Agent 暴露两个固定工具，把工具调用转成 HTTPS 请求；保管凭证和重试参数 | 设计，可放在本仓库，未来独立打包 |
| HermesInfra / 内容助手运行环境 | 生成文章、保留稳定任务号、在合适时机调用工具、向原群回复结果 | 本轮不改代码、不安装、不改配置 |
| 网站管理员 | 登录、审核、修改、补图和发布 | 沿用已有 Blog 能力 |
| 人工发布 | 后台事务确认公开修订，Astro按请求返回HTML；列表、图片与sitemap读同一公开记录 | 真实后台发布、更新、撤回和重新发布已验收，公开 HTML、图片、列表及 sitemap 已接通 |

这是跨系统接入，**不必为了它修改两个仓库的业务代码**。业务合同在 Channel；Hermes 最少仍要有一次工具安装/配置。若实际运行环境没有所需的工具扩展能力，届时再提出小范围 Hermes 改动，本轮不能提前承诺“配置一定足够”。

## 推荐接法

采用“网站 HTTPS API + 很薄的工具适配器”。API 不认识大模型、企业微信群或 Hermes 内部运行器，只接收经过认证的文章草稿。这样以后换 Agent 平台，网站接口和文章数据都可继续使用。

已只读查阅 HermesInfra 本地 `ff066b12a52fbc435478bf6d1de3cfba68933e20` 的 `native-mcp.md`：该文档描述启动时发现 stdio/HTTP MCP 工具，并提示密钥环境变量需要显式传入。这说明存在**配置接入的可行路径**，没有证明客户当前部署已经启用该能力。文档还描述工具可能进入多个平台工具集，因此不能把客户网站的凭证随意挂到共享的全局 Agent 配置中。

优先提供 stdio MCP 小适配器，工具只包含 `channel_blog_create_draft`、`channel_blog_get_import`；它内部调用网站 HTTPS API。网站的 REST 地址不能直接填进 MCP 的服务 URL，两种协议不是一回事。若届时已有受限的 HTTP 工具机制，也可直接调用同一 API，无须额外部署 MCP 网络服务。

不采用的方式：把管理员密码/JWT交给模型；让 Agent 直接读写 CloudBase；让模型选择站点/集合/请求 URL；让网站反过来调用或调度 Hermes；每次生成就自动发布。这些方式会扩大权限或让网站与 Agent 内部实现绑定。

## 一次生成和一次导入

1. 内容助手生成文章，并在调用工具前确定稳定的 `draftKey`。它表示一次业务生成结果，HTTP 重试不能换号；同一任务生成多篇时分别带文章序号。
2. 工具使用绑定站点的受限凭证，发送标题、正文和来源任务编号。
3. 网站验证凭证、配额和正文格式，在一个数据库事务里保存草稿与导入记录。只成功一半就全部放弃。
4. 新建返回 201；同请求号、同内容重放返回 200 和同一篇文章。相同请求号换内容返回 409，不自动覆盖或换号。
5. 工具把确定结果交给 Agent，Agent 在原会话回复需登录的编辑链接。群消息发送失败只补发消息，不再创建文章。
6. 客户编辑后，即使 Agent 再次投递原结果，也只拿到原导入记录，不写入已经修改过的草稿。

网站只保证**同一请求号的幂等**。Hermes 如何在重启、工具超时或跨进程重试后保留该号，是接入验收项；不能从一个外部任务编号推断它天然可靠，更不能把它当作用户身份凭证。

## 安全与数据归属

每个工具连接绑定一个网站和一个集成身份。凭证只允许新建草稿、读取自己导入的结果，不允许列出全部草稿、发布、撤回、删除、管理用户、读商品或价格。外部任务号只是来源信息，不能改变这些权限。

第一期接到获准客户的独立内容助手配置/运行环境。若多个客户共用一个工具配置，必须先具备可信的身份和站点隔离；不能只让模型在工具参数里选客户。未确认隔离条件，不上线这个工具。

文章原始来源、草稿及凭证摘要都只在服务端保存。浏览器和群消息没有服务密钥，编辑链接没有 token。图片先由人补充，不由服务器抓任意外链。

## 交付与上线的顺序

先审阅本设计；获准后按实施页完成网站接口、工具客户端与后台深链接。先在本地验证业务和真实 SDK 合同，再在可用发布窗口准备正式文章集合、网关和凭证，完成实际 CloudBase 验证。最后仅为一个隔离的本地内容助手安装配置，模拟创作需求，走草稿、人工编辑、预览和发布。真实企业微信群接入另行安排，不包含在此次本地模拟中。

不需要等海外部署才能开发这个功能；但也不能用本地成功替代跨系统验收。基础 Blog 的发布恢复和商品 SSG 的交付验收另有待办，Blog 完成并不代表整个 SEO/GEO 只剩海外部署。

## 2026-10-26 的实现选择

草稿入口使用独立的`article-import`云函数。这样给助手接工具时，不必替换已经运行的管理API、只读API或Astro文章服务；也不会把服务凭证送进浏览器管理员分发器。它使用原来的articleDrafts行格式和保存事务，没有另建CMS。正常部署清单不包含这个新函数，必须单独核对、部署和验收。

一期本地模拟在生成前由运行程序固定任务号和草稿号，保存在隔离配置里；工具拒绝模型改号。模型生成的内容先保存为草稿，编辑、私有预览和发布仍由人完成。实际企业微信群的任务号持久化与多客户隔离不包含在本地模拟的完成声明里。
