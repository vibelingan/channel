# 把现有图片放进网站私有草稿

本次直接处理 VibeKB 文档203，对应原有网站草稿。复用内容机已生成的两张 PNG；不重写文章、不重生成图片、不另建文档，也不公开发布。

## 怎么接起来

内容助手调用 `channel_blog_attach_images`，提交原文档编号、现有图片文件、准确说明和位置。程序先检查文档确实属于 diversity 工作区2，再将图片做成私有快照，通过已有受限 SSH 连接送到发布机。SSH 只允许交接正文和图片这两个固定命令，不开放远程命令或任意文件路径。

发布机使用现有网站凭证申请单个文件的临时上传许可。它没有新增 COS 管理密钥，内容机也拿不到网站凭证。网站随后读取实际字节，核对大小、格式、SHA-256 和尺寸；通过后另存一份不受临时上传许可影响的图片，才允许插入草稿。

图片沿用现有编辑器的 `articleImage` 节点，保存 `mediaId`、`alt`、说明和对齐方式；不向文章塞存储链接。后台继续通过已登录的私有图片预览接口显示图片。公开图片仍由已有文章发布流程控制。

## 重试和人工编辑

- 相同文档、文件和位置组成同一批任务。传输中断后继续原任务，不换文章编号或重新生成图片。
- 每张图和整批插图都有稳定编号；重复上传、完成校验和重复提交，不增加图片节点。
- 开始上传前记住网站当前文章版本和完整内容校验值。插图时两者必须仍一致，否则保留人的修改并停止插图。
- 整批插图在同一个数据库事务中完成，不能只插一半。图片上传完成但文章插入失败时，私有图片和进度记录保留，返回未完成，不谎报图文草稿完整。
- 插图成功后再次读取网站正文，确认图片及 alt 已保存。回复丢失后重试使用原回执；人后来删图或改 alt 时，不擅自恢复旧设置。
- 校验被中断后，五分钟的执行占用到期可重新接手。单文件上传许可过期可为同一文件续办，不新增图片编号或重复占用额度。

## 本次线上改动范围与退路

只更新 `article-import` 函数代码，保留它的运行配置、路由和现有凭证。增加仅服务器可读写的 `articleImportImageJobs` 集合，以及现有正式发布连接的图片权限记录 `media-access-hermes-wecom-supplychainsai-02`。不改其他云函数、网页部署、pricing、Hub、模型、生图设置或其他助手工具。

写入前将旧函数程序包、候选包和配置清单保存到 GitHub 构建附件。新程序未通过健康检查时，只恢复原函数代码，不回灌文章、凭证或业务数据。图片权限结果不明时保留候选代码并先读回确认，不盲目反复开权限。

两台助手各增加本功能自己的版本目录，保留旧版。只切换 `channelblog` 工具路径、对应网站技能和本功能专用 SSH 公钥的受限命令；其他工具、群和模型配置须前后核对。必要时在空闲后仅重启助手网关，保留 A2A 服务。

出现目标环境或文章不符、原图校验不符、人工改稿、权限不符、程序包或配置被他人改动、结果无法确认时立即停止相关写入。已经保存的用户数据和图片不自动删除。需要撤回程序时切回已保存代码及本功能旧配置；不拿旧数据库覆盖人的新内容。
