# 发布机上的长期凭证维护

网站密钥只留在发布机。内容助手不需要它，内容安装包也不包含它。正式连接不限制一篇文章，正常使用不要求客户每十四天续期。

## 服务端规则

正式凭证有效期 90 天，30 天开始轮换。凭证主记录仍保持现有字段；维护信息以 managed-<keyId> 存在同一私有集合的另一条记录中，不改变商品、价格或其他 App 的数据库结构。

POST /api/integrations/v1/article-drafts/credential-rotation 只接受有效服务凭证和 32 位十六进制 rotationId。它不能修改站点、集成或任意有效期；旧试跑凭证没有管理端建立的维护记录，不能自行升级。

轮换时在同一个事务中更新当前摘要、版本、有效期和上一代摘要。上一代最多重叠 24 小时；停用主凭证记录会同时拒绝新旧凭证和续期。网站只存摘要，不存密钥明文。

## 回复丢失也能继续

发布机先在 0600 文件中保存轮换编号、旧凭证、本次候选凭证和原配置摘要，确认落盘后才请求网站。候选凭证通过现有秘密、当前版本和轮换编号的 HMAC 确定，网站独立计算同一结果。

如果网站已经换好钥匙，但回复在路上丢失，发布机重启后先用候选凭证查询同一次轮换。即使旧钥匙的 24 小时重叠已结束，也能在新钥匙有效期内恢复，不盲目再换一把。已停用或过期的连接不能借此重新启用。

收到经校验的回执后，发布机比对原配置摘要，写私有临时文件并落盘，再原子替换。若操作人中途修改了配置，自动操作停止，不覆盖。密钥不进入 stdout、群、Git 或构建附件。

## 调用与维护任务

locked-invoke.py 取得专用 OS 文件锁后，调用独立 Node 包；同一凭证的保存和轮换不能同时改文件。维护任务遇到正在保存的请求可以跳过该次检查；提交任务最多等锁 25 秒。

建议维护任务每小时检查一次。未到 30 天轮换时间时只读本地状态，不访问网站。持续失败应由专用任务的非零退出和维护日志报告，不能默默显示成功或回退到被停用的试跑凭证。

本轮只交付和验证代码，尚未安装或启用这个任务。现场登记正式密钥、部署轮换路径并确认实际权限后，再启用。不能把“维护代码通过测试”说成“线上凭证已经切换”。

现有群测 MCP 在进程启动时读取一次凭证。不能只给它换文件并打开轮换任务，否则常驻进程还会拿旧钥匙。正式接线时要把该入口切到每次持锁、重新读取凭证的运行方式，验证后再停用试跑连接。这个切换只在正式安装时做一次；以后正常轮换不需要重配助手或重启服务。

若发布机长期停机、网站长期不可用直到正式钥匙过期，需要管理员重新授权；不是永不过期的秘密。客户日常使用无需参与这项维护。

## 已覆盖的验证

- 正常轮换及两代重叠；超过重叠期后旧钥匙被拒。
- 使用旧钥匙或新候选重放同一次轮换，结果一致。
- 回复丢失、进程重启、两天后恢复。
- 停用后两代均不能用，也不能续期。
- 试跑密钥无法自行变正式，调用方不能指定长期有效期或换身份。
- 私有文件权限、符号链接、错误回执、人工同时修改。
- 维护前不产生多余 HTTP 请求；独立包在 Node20 由 CI 再验证。

真实云端轮换、维护任务启停和告警接入仍放在联合验收中。恢复旧程序时保留当前密钥状态，不恢复过期的凭证文件。
