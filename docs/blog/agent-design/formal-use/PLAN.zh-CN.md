# 网站草稿的正式接入：按模块交付

2026-10-27。用户已明确采用“内容助手 → VibeKB → 发布助手 → 网站私有草稿 → 人审核上线”。沿用 feat/seo-foundation，不创建分支或 worktree，不动 pricing、Hub 公共调度或其他 App。

[完整流程图](diagrams/kb-blog.html)。图中的交接入口和凭证维护尚未在生产启用，不能把图当成已运行的全流程。

## 1. 职责与内容安装包

发布机已经移走本轮新增的 channel-blog-writing，删除对应能力登记，将网站职责改为取指定知识库文档和保存私有草稿；保留原 VibeKB、网站草稿 MCP、网站凭证及其他工具。已在空闲时只重启发布助手网关，四渠道重新连接，原 A2A PID 未变。备份和真实结果见交付记录。

内容机由用户安排内容助手自行安装新版内容专用包。包只含写作技能、安装器和说明，不含网站凭证、发布机工具或固定任务号，不改原 MCP、SOUL、模型或其他技能。安装和重复安装已用实际 ZIP 测试；是否在真实内容机安装，等待内容助手回报，不能说已经完成。

验收：发布机原生技能发现中无写作技能，草稿技能可读，两个网站工具仍可发现；安装包反复安装不改变已有配置。已通过。

## 2. VibeKB 文档与网站请求编号

代码已实现并离线验证，见 [取稿与去重](KB-DELIVERY.zh-CN.md)。同一站点、集成、工作区和文档 ID 始终生成同一个请求号。新文档产生新草稿；相同文档重投不重复创建。知识库正文后来修改仍用原号，网站报冲突，不偷偷生成第二篇，也不覆盖人的后台编辑。

验收已覆盖：连续两篇、八次并发重投、人工第 2 版保留、凭证轮换后重投仍返回原文、跨工作区拒绝。这使用实际安装 SDK 的离线传输和真实业务事务，不是云数据库现场验收。

## 3. 长期凭证维护

维护代码已实现，见 [凭证维护](CREDENTIALS.zh-CN.md)。正式凭证 90 天有效，30 天轮换；建议每小时自检，未到轮换时间只读本地文件。旧密钥最多重叠 24 小时；停用主记录后新旧都拒绝。

已验证回复丢失、进程重启、旧钥匙重叠期结束、错误回执、人工同时修改凭证文件等情况。正式工具使用 OS 文件锁，密钥写入采用私有文件、内容比对、落盘和原子替换。

尚未将该代码部署到 article-import，尚未登记正式维护记录、启用维护任务或替换现有试跑凭证。现有十四天、固定任务的连接仍受限制，不能先摘掉限制冒充正式接入。自查明确工作区和真实交接入口后统一切换；客户不需要每篇配置或每十四天续期。

## 4. 交接与联合验收

等待内容助手自查：VibeKB 正确客户工作区、文档结构、实际协作任务入口、pipeline 的用途和连通性。此前发现内容机的 pipeline 配置使用 host.docker.internal，而其原生进程环境不能解析；不能仅凭工具名称认定已有发布队列，也不在别的 App 上擅自改地址。

确认入口后才接收文档任务。取稿适配器必须真实读取指定文档并核对工作区；不能信模型传入的 workspaceId。kbDraftRequest 是内部编号转换函数，不是独立权限入口。不要全库扫描新增即提交，也不要同时用多个通道派单。

联合验收顺序：只读连接与身份 → 指定文档取稿 → 两篇私有草稿 → 重投与变更冲突 → 后台人工编辑与预览 → 真实轮换及恢复观察 → 用户群测。不要发内部测试群消息，不公开测试文章，不动社媒发布或业务数据。

## 云端启用与恢复边界

仅更新既有 article-import 函数并添加受保护的轮换路径；保持现有网关和其他函数不动。先保存实际旧包、配置和源码版本，使用原共享部署锁。函数、身份或包摘要不一致即停止。

正式密钥仍放发布机；内容包和群消息均不含它。操作人确认过的正式凭证及工作区配置到位后，再启用交接和独立维护任务。旧试跑凭证停用时保留原文章和导入记录。

程序恢复不回灌文章或密钥。凭证主记录保持旧格式，维护信息另存私有记录；恢复旧代码时仍需核对当前凭证兼容性，不能用旧私有文件覆盖已轮换的密钥。现场全流程尚待联测，不宣称已经上线。

此前“直接把群消息正文交给发布机”的未交付原型已移出产品源码，保存在本机忽略目录供查证；不安装、不交付，也不要求改 HermesInfra 公共调度。
