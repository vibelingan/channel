# 内容助手接入：实施和验收划分

本页是计划，没有自动启动开发。只用原 SEO 分支；不新建 worktree、PR，不修改 HermesInfra。每段代码、离线检查、真实存储和跨系统验收分别登记。

## 1. 网站受限草稿接口

运行场景：同一个工具请求超时后重发，或者客户编辑完成后 Agent 又投递旧文。结果必须仍是同一篇草稿，不能重复建文或覆盖人工修改。

拟新增 `packages/articles` 的导入合同、Markdown adapter、导入事务；在 `packages/db/src/article-repository.ts` 复用已有事务读写；在 admin 函数新增独立 HTTP 路由。新增私有资源仅为 LLD 列出的导入集合，不改商品、价格、同步 schema 或默认部署资源。

数据核心：稳定 idempotencyKey、完整请求摘要、确定主键的 articleImports 和 articleDrafts。草稿、操作和额度单事务保存。接口对服务身份开放两个动作，对浏览器 action 分发器没有后门。凭证失效和同号异文必须在任何写入前拒绝。

先写并实际运行失败用例，再实现：

- Markdown 支持节点和编辑器往返；未知内容、脚注、HTML、图片、危险链接和超限正文准确拒绝。
- 八个并发同号只建一篇；同号改标题/正文/格式为 409；不同集成无法查询结果。
- 人工保存到 revision 2 后重放，不保存或回滚草稿；不对当前草稿做整条替换。
- 导入草稿的严格行结构、集成创建者标识、后台管理员读取与人工修改正常；不能把现有管理员 create 方法改成接受服务凭证。
- 实际安装 SDK 的提交失败、零写入回执、冲突重试、额度上限与凭证在提交前撤销。
- 实际 HTTP/base64/大小限制；没有服务凭证、过期钥匙、轮换钥匙、任意 admin/商品请求全部拒绝。

验证命令沿用文章、DB 和 admin 的包测试、`pnpm verify:cloudbase-sdk`、类型检查和实际函数包。代码检查不能代替真实 CloudBase 事务与权限验证。若正式集合未准备或部署窗口未开放，现场项保持未验证。

## 2. 工具客户端与后台直达链接

运行场景：客户从群消息点链接，登录后应直接看到该文，刷新不丢选择；工具不能从未确认的响应拼一个假链接。

拟新增 `tools/hermes-blog` 的固定 HTTP 客户端/stdio MCP 包装；`packages/articles` 提供无编辑器依赖的合同和链接校验。后台只补 Dashboard 选择、Articles 初始文章和安全 returnTo，不重做页面、不加 Agent 发布按钮。

沿用现有文章 API 和 React Query。客户端仅两个工具，不提供通用网络工具；密钥由安全运行配置传入，模型只能给文章输入。稳定 draftKey 的来源由内容工作流明确，不能将每次 HTTP 请求随机号当业务去重号。

先运行失败用例，再实现：实际本地页面/后端导入 → 点链接 → 登录 → 打开指定文 → 人工修改 → 保存 → 刷新 → 预览 → 重放。独立读回持久记录；网络回复丢失与假响应身份不匹配必须被发现。拒绝外站 returnTo、重定向、跨站 editUrl 和超大响应。截图是辅助证据，不替代操作和读回。

本段完成只说明工具包可用，不代表已经给 Hermes 安装。跨平台客户端可以直接用 REST，避免将业务规则写进 MCP 适配器。

## 3. 真实内容助手接通（配置与现场验收）

前置：基础 Blog 已部署到可以使用的真实入口；网站接口和私有集合就绪；一个客户的内容助手运行环境隔离已确认；具备该环境的配置权限。无需把这个步骤混入网站正常 CI，也不触发 pricing 的部署。

1. 只读核对 Agent 运行版本、工具扩展机制、客户/群绑定以及稳定任务号如何保留。
2. 在获准的内容助手环境配置已固定版本的工具包和该站受限凭证；不修改 HermesInfra 仓库。若现有能力不足，先列明最小需要的改动，不临时改 Agent 内核。
3. 客户在实际群发一次需求；确认真实 Agent 的工具调用、网站操作号和草稿 ID；群里只回标题、编辑链接和草稿状态。
4. 客户登录编辑、补图、预览；重新投递原任务不覆盖修改；没有权限的账号和其他集成都不能打开私有内容。
5. 管理员选择一篇获准内容发布，实际检查公开 URL、正文/图片、canonical、sitemap；这沿用基础 Blog 的发布验收，不让 Agent 代替人确认。
6. 撤销工具凭证后再调用应失败；不删客户草稿。出现串客户、泄露凭证、重复文章、假成功或覆盖人工内容立即停用工具并保留证据。

成功标准是实际企业微信任务到网站草稿以及人工操作都可追溯。只有 HTTP 脚本成功、只有配置文件、或者群里出现一段文章，都不能算完成。

## 设计审阅后的调整

- 草稿导入先用同步事务，不引入队列和 202 假异步状态。
- 取消一期远程图片抓取和跨文章图片引用，避免文章归属及 SSRF 变成隐含需求。
- 编辑深链接和静态登录页的 returnTo 是独立验收点，不能只返回一个目前无法定位文章的 URL。
- 区分“无需修改 Hermes 仓库代码”和“无需给 Hermes 配置工具”。后者不成立。
- Hermes 文档提到工具可能全局可用；因此客户隔离必须是现场前置，不把模型传的客户名当权限。
- 提前写的 Agent 运行代码已移出本次交付；以上三个模块目前都不登记为实现完成。
