# 发布、更新和撤回：执行与验收计划

本轮继续原 SEO 分支，起点 `cd4cd2b9527344799732d819b3306ee51e6e6c98`；开始时读回 main 仍为 `404d1a257722175dcd70916e3f92ec6763fa0243`。用户本轮明确要求细分实施、完整前后端验证，并部署隔离 dummy。该授权覆盖本任务必要的隔离测试资源，取代原交接中“只做离线”的限制；不授权发布正式 Blog、改业务数据、正常部署入口或 pricing。

## 按可以检查的结果分段

| 顺序 | 实现与边界 | 通过标准 |
| --- | --- | --- |
| 1，后端发布任务 | 管理员请求指定修订；在同一数据库事务内查权限、冻结正文与图片、占用 slug、登记任务。状态查询只返回页面需要的字段 | 双击/响应丢失不重复建任务；旧修订、非管理员、停用账号、缺图、占用 slug 被拒绝；保存新草稿不影响冻结内容 |
| 2，构建输入 | 从服务器保存的任务生成专用内部候选输入，合并其他已公开文章；图片按固定清单读取并验字节。正式公开导出仍只读已验收记录 | 不伪造 accepted；缺文件、hash 不符、草稿泄漏或媒体归属不符时，构建失败且当前公开状态不变；重试沿用原候选 |
| 3，交付和恢复 | 接现有发布锁、写入前备份、逐步记录、普通 URL 读回和恢复。只有已确认的结果才能更新文章公开引用 | 未写线上时失败不恢复；写入结果不确定时停止并读回；恢复只选已验收的旧包；恢复失败不递归；旧任务不能盖掉新状态 |
| 4，后台完整操作 | 在现有编辑页增加发布、更新、撤回、进度与失败重试。保存/预览继续沿用已有行为，网络请求用公共请求层和 React Query | 页面操作确实创建后端任务，重新打开仍能读到进度；未保存内容处理清楚；失败保留输入；撤回有明确确认，普通保存不加确认步骤 |
| 5，真实 dummy 准备 | 读回实际目标、凭证和资源占用；明确独立函数/集合/对象/页面前缀，形成精确清单。部署同一业务实现，不另写假成功接口 | 云端运行代码身份可核对；测试集合 ADMINONLY；测试身份及凭证不入库、不进静态文件；所有写入口拒绝业务资源 |
| 6，从浏览器实际验收 | 通过真实页面、云函数、数据库和存储执行下表场景，独立读回数据、页面和字节 | 不能用接口拦截返回成功，也不能把离线 SDK 结果当云端结果。保留时间、版本、截图及读回记录；完成后按清单停用测试入口，删除另行核对范围 |

每一段的结果更新同一份 `NEXT-STEPS.zh-CN.md`；细节和执行证据记在本模块 worklog。云端登录等待期间继续前四段，不把授权尚未完成写成程序错误。

## 状态与允许的转移

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| QUEUED | 后端已保存指定内容，尚未开始执行 | 工作进程领取后到 BUILDING |
| BUILDING | 正在生成和检查产物，尚未写线上 | 检查成功到 DEPLOYING；失败到 FAILED；工作进程租约过期可重新领取 |
| DEPLOYING | 已登记线上写入意图，可能已写一部分 | 所有读回与记录成功到 SUCCEEDED；确认恢复成功或确认未写入才到 FAILED；不能确认到 UNKNOWN |
| SUCCEEDED | 交付已验收，公开引用和任务结果已登记 | 终态；重复完成只读回同一结果 |
| FAILED | 已确认不影响当前公开版本，或已确认恢复完成 | 原候选可创建新的重试任务；不能悄悄换成最新草稿 |
| UNKNOWN | 可能写入，实际结果或恢复结果尚不确定 | 保留占用，先核对现场；禁止自动重发、新任务覆盖和自动再次恢复 |

每篇文章最多一个未结束任务；交付阶段还要持有环境共享锁。任务使用后端递增顺序、工作进程领取次数及有限租约，防止迟到的工作进程写回结果。终态记录和旧候选保留，不通过删除任务来解除异常。

## 并发要怎么处理

| 同时发生 | 应有结果 | 在哪里保证 |
| --- | --- | --- |
| 相同请求重复提交 | 得到同一任务；更换内容/操作重用请求号则冲突 | 数据库事务中的确定性任务编号与请求摘要 |
| 两个不同发布请求 | 只有一个取得这篇文章的占用 | 同一篇文章的发布指针事务 |
| 发布请求与保存草稿 | 冻结请求指定的修订；保存成功后不改候选 | 同一事务读取草稿 revision；候选独立保存 |
| 两篇文章抢同一 slug | 只有一篇成功；撤回后仍保留原归属 | slug 唯一文档与事务 |
| 两个工作进程领取 | 只有当前领取者能推进；过期领取不能写回 | 数据库租约、领取次数及任务顺序 |
| 完成交付与新草稿保存 | 只更新公开引用，不回写/覆盖正文 | 完成事务重新读取当前草稿 |
| 超时工作进程与后续任务 | 拒绝旧回执；已进入写入的超时先核对现场 | 任务顺序、租约和共享交付锁 |
| 撤回与历史恢复 | 恢复文件时仍尊重撤回记录，不能复活旧页 | 文章撤回记录及交付清单检查 |

## 真实 dummy 验收场景

| 场景 | 必须看到的真实结果 |
| --- | --- |
| 首次发布 A | 页面创建任务；云端保存冻结内容；dummy 公开普通 URL 有正文和正确图片；数据库显示同一任务成功 |
| 发布中继续写草稿 B | A 的候选、图片和最终正文不变；B 留在草稿里 |
| 更新到 B | 同一 slug，公开正文变成 B；首次发布日期保留，修改日期只因真实内容变化更新 |
| 重复点击/丢回复 | 不重复建文章、任务或公开引用；页面可以读回真实状态 |
| 两个标签同时发布 | 一个取得占用，另一个收到明确冲突；没有互相覆盖 |
| 旧修订、同名 slug、缺图、非管理员 | 请求真实失败；云端数据和公开页面均不变 |
| 构建失败 | 不上传、不恢复、不登记发布成功，草稿仍能继续编辑 |
| 上传后验收失败 | 只恢复本次保存且已验收的 dummy A；记录原发布失败及恢复结果 |
| 上传结果不确定/租约丢失 | 停止新写入，显示需核对，实际读回后再决定后续操作 |
| 撤回与刷新 | 列表及 sitemap 不含该文；普通 URL 返回实际 404；旧标签页刷新不继续展示旧正文 |
| 手工 A→B→A | 精确指定 A；正文、图片和运行身份可核对；数据库新字段和测试记录保留 |
| 访问与退出 | 未登录/非管理员不能读草稿和私有图片；撤销身份后继续操作也被拒绝；私有 Blob URL 释放 |

## 云端写入前的说明

写入前必须给出实际环境、固定名称/前缀、预计写入与保留的对象、现有站点只读基线、A 的保存位置、逐步恢复动作和停止条件。当前尚未完成现场资源查询，不把历史空闲名称当作当前可用。

停止条件至少包括目标/归属不符、资源重名、权限不符、备份缺失、另一发布正在运行、云端代码身份不符、写入结果未知、普通网站基线变化。停止后保留证据和数据，不自动删除业务对象或重建函数。dummy 不加入菜单、正式 sitemap 或搜索通知。

## 本轮先交付的部分

第一段的任务、事务、状态查询和 worker 能力已写代码。真实交付器尚未接线，所以正式入口默认关闭；没有向用户提供点击后永远排队的发布按钮。第 2 至 6 段仍待实施或验收，不能将这份计划当成完成清单。

### 任务数据放在哪里

| 集合 | 负责什么 | 谁能读写 |
| --- | --- | --- |
| articleReleaseTasks | 每次请求、固定修订、媒体清单、处理状态和交付回执 | 服务端专用；页面仅得到明确列出的状态字段 |
| articleReleaseHeads | 每篇文章当前任务及递增顺序、长期保留的地址和公开引用 | 服务端事务 |
| articleSlugs | 地址归属；撤回后保留，防止另一篇占走旧地址 | 服务端事务 |
| articlePublications | 指定修订的不可变正文候选；不代表已公开 | 已有私有管理读取，后续构建进程 |
| articleAccepted | 完成交付后供公开导出使用的版本；撤回记空引用，不删历史候选 | 服务端发布进程 |

浏览器只有请求发布/撤回和查询状态两类操作；不能领取任务、提交交付回执或将状态改成成功。CloudBase 与本地存储复用同一段事务规则，各自负责真正的提交或放弃。发布成功只更新当前草稿的公开引用，不整条替换正文。

### dummy 的隔离方案

`packages/db/src/article-dummy.ts` 固定映射八个逻辑集合到 `blogDummy20261023Users/Drafts/Media/Publications/Slugs/Tasks/Heads/Accepted`，不接受外部前缀或任意集合名，事务仍执行安装包中的实际 SDK。此处只是命名与隔离代码；现场尚未读回，不能承诺这些名字当前无人使用，也没有创建集合。

部署前还须补齐独立函数、图片对象前缀、静态页面前缀和运行代码身份核对。不能把正式 HTML 随便移进子目录就认为隔离完成：页面链接、图片、canonical 和 404 都必须与实际测试网址一致。普通网站与搜索文件作为只读参照，不上传覆盖。图片原件和数据库字段默认保留。

dummy 验收可先由本地浏览器操作页面、实际调用独立云函数及真实数据库/存储，交付任务由受控工作进程执行。报告必须说明后台页面、执行进程和公开页面各自实际运行在哪；不把本地 UI 加云端后端说成“后台也已云端托管”。正式长期任务触发方式还须接既有发布入口，不能把浏览器长请求当构建进程。

### 仍须补上的细节

- 失败任务的“重试原候选”是独立后续操作，不能用最新草稿重新请求来冒充重试。当前重用同一请求号会读回原任务，不自动重发。
- 已进入交付的未知结果保留占用；确认恢复完成后的状态转换，以及 UNKNOWN 的现场核对入口，必须与共享交付记录一起实现。目前只有构建失败可直接登记失败。
- worker 当前有领取、续期、交付前检查和完成登记代码；这些方法还未接真实文件上传、共享环境锁和普通 URL 读回。测试里的回执只验证事务规则，不证明线上交付成功。
- 请求人的权限变化会阻止领取或开始交付；取消尚未开始的任务及更换处理人的操作，需在页面接线前补上，不能靠删除记录解锁。
