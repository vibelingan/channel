# 05 Hermes 生成文章后送入草稿

本模块尚未实现。本轮没有修改 HermesInfra 的代码、凭证或企业微信机器人。

客户仍在企业微信群让内容助手写文章。Hermes 生成好后，通过受限接口把内容存成网站草稿，在群里返回需要登录的编辑链接；客户进入现有后台修改、预览，再由管理员发布。群里生成文章不等于网站自动公开。

## 专用接口和权限

新增版本化 `POST /api/integrations/v1/article-drafts`，服务端将该路由交给文章导入服务；具体 CloudBase HTTP 路由映射在实现时核对，不在这里宣称路由已存在。请求包含稳定 `idempotencyKey`、外部任务编号、标题/摘要/署名建议及 `format: markdown | article-json-v1` 的正文。响应返回 operationId；只有导入记录已可靠写入才返回 202。

`GET /api/integrations/v1/article-drafts/<operationId>` 返回本集成自己的任务状态：处理中、草稿可编辑、失败；成功结果包含 articleId 和编辑链接。链接不携带 token，不绕过后台登录，不作为公开预览链接。只写入当前站点的集成凭证由服务端配置绑定；不能让大模型在参数里选择站点、用户身份、集合名或任意回调地址。

凭证只允许创建草稿和读取本集成的操作结果；不允许发布、撤回、删除、批量读取草稿、管理账号或访问商品。服务端固定限流、请求大小和审计；凭证可轮换和撤销，日志不输出正文或密钥。使用独立 service credential，不把管理员密码/JWT 写进 Agent prompt。

## 幂等和人工编辑保护

唯一键由站点、集成身份和 idempotencyKey 组成。相同 key、相同请求内容返回同一个 operation；相同 key、不同内容返回 409。任务排队后失败重试不能重复建文；创建文章和把 operation 标为完成需要事务或可重入步骤，不能只在内存记一次。

首次生成成功以后，重复投递不再保存草稿，所以不会覆盖客户已经修改的正文。新的生成任务创建另一份草稿；需要“基于现有文章提建议”时以后另加修订提案，不让 Agent 直接覆盖人工作品。外部任务编号和来源另存为审计信息，不让客户端设置编辑者或公开时间。

## 正文适配与图片

Markdown 通过独立 adapter 转成 01 的正文结构，再走同一校验、存储和渲染链。原始 Markdown 保留为私有来源，转换失败返回具体位置，不能用删掉不认识内容的方式冒充成功。HTML、未知节点和超限内容明确拒绝；禁止任意 HTML 直通。

一期先支持文字；图片引用必须是已授权媒体编号。若 Agent 产出外部图片地址，返回需补图状态或由人工上传，不能由后端无条件下载任意 URL。以后加下载时单独做域名、重定向、私网访问、MIME、大小和上传意图校验。

## MIU 与验收

| MIU | 独立交付 | 必须通过的检查 |
| --- | --- | --- |
| BLOG-H1 | 受限凭证、持久导入任务、Markdown adapter、草稿接口 | 重试不重复、同 key 改正文冲突、越权读取/发布拒绝、异常 Markdown 不静默丢内容、编辑后重试不覆盖 |
| BLOG-H2 | Hermes 工具调用与企业微信群编辑链接 | 真实 Agent 生成→任务查询→后台登录→编辑/预览→人工发布；凭证不出现在消息/URL/日志；网站失败不冒充已建草稿 |

H1 依赖 01/02，可以先独立验证服务端。H2 需核对届时 Hermes 的工具接口和实际账号，不能拿网站的模拟请求证明企业微信端已接通。Meta→Action 与文章内业务按钮留到后续，不与首次草稿接入捆绑。
