## 编辑页怎么保持简洁

- 文章列表提供“新建文章”、标题搜索和继续编辑；沿用后台现有表格、分页与导航。
- 编辑区优先显示标题和正文，常用格式直接可用。工具栏只保留支持且实际需要的操作，图片在正文里选择、替换和移除。
- 主要操作是“保存草稿”和“预览”；显示保存状态。点预览时若有改动，自动完成保存后打开指定修订，不让用户重复点击或经过确认向导。
- 搜索标题、描述、slug 等偶尔使用的设置收在可展开区域；没有做完的发布能力不放假按钮。
- 普通保存不加确认弹窗。离开未保存内容、真正的版本冲突等可能丢内容的情况才提醒；冲突保留当前输入，不自动盖掉别人新保存的内容。

首期仍按原设计手动保存，暂不增加自动保存及多人协作。完整内容格式、图片和权限要求继续以 [模块 03](03-editor-preview.zh-CN.md) 为准。

## 浏览器要实际做什么

| 场景 | 实际操作与核对 |
| --- | --- |
| 完整写作 | 登录后台、新建文章，用真实 Tiptap 输入、粘贴、设置格式。保存、回列表、重开、刷新，比较正文和格式；核对服务器及存储中的同一篇文章 |
| 编辑器格式往返 | 对每种启用节点实际执行 getJSON/setContent、保存和重开；不能只验证手写 JSON 样本 |
| 重试与冲突 | 双击创建不多建文章；开两个标签页，先保存一边，再从旧版本保存另一边，确认不覆盖且输入保留 |
| 断网及失败 | 通过真实浏览器网络控制或受控服务故障触发失败；确认有清楚提示、内容仍在、恢复后能重试，不能出现假“已保存” |
| 图片及预览 | 在获准的 CloudBase 测试范围实际上传图片、选择、替换、移除和预览。上传未完成不能丢图保存；指定修订的预览正确，私有原始地址不进入 DOM，切换文章时取消旧请求并释放 Blob URL |
| 权限 | 用未登录及不具备权限的独立浏览器会话尝试打开草稿和私有图片，确认真实接口拒绝；账号被停用或降级后继续操作也被拒绝 |
| 使用体验 | 桌面、窄屏和键盘分别操作；检查焦点、按钮反馈、长文编辑和横向溢出。窄屏模拟不能记成真机测试 |

截图可留作样式对照；汇报先说明实际操作、数据结果和未通过项。回归脚本可以无头运行，但编辑页交付还要有可视浏览器的操作验收，不能把脚本数量当作体验证据。
