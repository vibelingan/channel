## 设计审阅改了什么

1. 明确仓库边界：Channel 提供 HTTPS API 和可选的薄工具适配器；本轮不修改 HermesInfra。以后仍要给获准的内容助手配置工具和受限凭证。
2. 草稿导入用一次同步事务；成功才返回 201，同内容重放 200，没有队列就不返回 202。
3. 固定请求身份和原文摘要，限制同号异文；重放只取既有结果，不覆盖人工修订。草稿异常丢失也不靠重放重建或返回假链接。
4. 第一阶段只导入文字；支持范围、未知节点和大小错误明确返回。图片用现有后台人工上传，不自动抓外链。
5. 导入必须保持现有严格草稿行格式，使用派生的集成创建者标识；不能借用要求管理员的 `repository.create` 或放宽其权限。
6. 将后台文章直达链接、登录后 returnTo、静态页面实际查询参数列成独立实现点。返回一个 URL 不代表现有页面已能定位文章。
7. Hermes 文档提到 MCP 工具可能全局注入，因此客户/内容助手隔离是接入前置，不能让模型选客户来替代权限。

只读参考了本地 HermesInfra `ff066b12a52fbc435478bf6d1de3cfba68933e20` 中的 `native-mcp.md`。该参考说明配置接入可行，不证明客户当前运行环境已具备。没有读取其实际密钥或修改配置。

## 检查中遇到的两个问题

- 首次浏览器构建把产物放到外置盘，Astro 从本机临时目录改名时得到跨文件系统错误。重跑使用同一文件系统的 `/tmp`，构建通过；没有为本机目录问题修改 CI。全仓测试在外置临时目录较慢，但已完整结束，未中断后按通过计数。
- 文章专用模式没有 Products 菜单，原导航保护测试仍点 Products，导致找不到按钮。测试已在正常模式点击 Products，在专用模式点击真实的返回文章按钮；两个模式都核对未保存输入仍在，并都通过，未跳过该场景。
