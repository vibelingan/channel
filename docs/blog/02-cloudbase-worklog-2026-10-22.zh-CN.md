# CloudBase 草稿存储：本轮交付记录

2026-10-22，沿用 `feat/seo-foundation`，从 `1f7fac43e0ff6794e09a10dfada909020d1df664` 继续。用户已要求开始实现、完成后推送，并长期采用简短中文 brief。

## 完成的代码

CloudBase 草稿适配器、云函数入口接线和独立文章资源准备函数已写好。管理员的创建、读取、保存、摘要列表、指定修订预览及旧快照读取沿用现有接口和文章核心；没有增加客户编辑页面。

- 创建按操作者与 requestId 生成确定性文档编号，在同一文档里保存草稿、原请求配对及内容摘要。SDK 冲突重试或新建仓储实例后，同一请求仍返回同一篇的当前状态；改正文重用请求号会冲突。
- 保存事务重新检查当前用户、读取当前修订、执行文章核心并完整替换记录。两个旧修订保存只能有一个业务成功；未改正文不加版本。完整替换避免删除的段落被数据库对象合并留下。
- 写入必须有 updated:1 或匹配编号的 upserted 确认。SDK 错误、零写入、坏记录或提交失败不会被写成成功；不把数据库内部错误给客户端。
- 列表在数据库只投影摘要，不读取正文；按唯一编号翻页、按文字查询标题，并在返回前再次核对权限。长中文查询暴露了原 512 字符游标上限不足，已改为 1024 并补连续请求测试。
- 旧快照重新核对身份、内容和摘要并保持冻结。编辑草稿保留公开引用，不写旧快照，不发布内容。`articleSlugs` 本轮只声明资源，公开地址占用与发布逻辑留在模块 04。

`scripts/blog-article-resources.mjs` 单独处理 `articleDrafts/articlePublications/articleSlugs`，要求 ADMINONLY 并读回确认。复用原有资源准备函数的同步 JSON 回调约定，不是异步 MCP 客户端本身。未加入默认部署清单，导入模块不会创建资源。本轮只用离线测试调用它，没有连接真实腾讯云。

## 审查与范围

按 full pipeline 对照了模块 02、实现步骤、接口、影响范围和验证结果。沿用仓库不委派代理的要求，由当前会话审查；读取 Engineering Craft 的并发、验证完整性和 SDK 边界规则。实际 craft runner 正常执行七个扫描器：新增发现 0；原基线仍有流程因果 1、表单 4、跳过策略 5、边界解析 2 项，不在本次修改文件内。两个需仓库配置的扫描器仍为不适用，不当成已经覆盖。

云函数 → 实际仓储 → SDK → 传输形状分别有运行检查；资源准备默认清单未增加文章，现有部署行为保持原样。全仓测试和类型覆盖了 articles/db 改动的其他消费者，未修改商品、pricing、通用 CRUD、公开路由或 UI。

本轮没有做文章编辑器的浏览器验收，也没有登录 CloudBase、读写真实数据库、创建集合、修改真实权限或部署网站。SDK 夹具制造的读集冲突模型不能证明真实平台采用相同事务隔离；云端并发和权限必须另做现场验收。
