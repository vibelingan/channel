# 04 公开文章、发布与 SEO

本模块尚未实现。依赖 01/02、媒体公开规则及商品 SSG 的交付链路。Astro 继续负责构建，不迁移 Next.js；网站公开页不加载编辑器。

## 地址、正文与搜索信息

首期地址为 `/blog/<slug>/`，articleId 是后台稳定身份，slug 一旦公开就固定；改地址需另做明确的重定向，不在首期静默修改。`/blog/` 输出已公开文章摘要及真实链接；详情通过 `getStaticPaths()` 从已验收公开版本生成 HTML。草稿和候选快照不出现在公开 API、页面、内链、sitemap 或结构化数据中。

页面沿用现有 BaseLayout 和共享 SEO 页面合同。文章标题为唯一 H1，正文从 01 输出 H2–H6、段落、列表、表格及图片；canonical 指向自己的详情地址。Article/Breadcrumb 数据只用页面真实可见的标题、署名、正文、公开图片和日期，不伪造组织、评价或作者资料。SEO 标题/描述为空时用文章标题/摘要的明确降级规则；不把草稿编辑时间当公开更新时间。

公开媒体由已验收媒体服务把 mediaId 映射为可公开地址、尺寸和 MIME，渲染器不能绕过发布/引用计数规则。文章撤回不意味着立刻删除图片：其他文章、商品或历史版本仍引用的文件必须保留。没有完整媒体映射就停止这次文章发布，不影响当前已成功站点。

## 发布不是保存按钮的另一个名字

| 阶段 | 记录什么 | 访客看到什么 |
| --- | --- | --- |
| 编辑草稿 | 当前 revision | 上次成功公开的文章；首次发布前没有页面 |
| 请求发布 | 冻结 articleId/revision/contentHash、媒体引用和任务编号 | 仍是上次成功版本 |
| 构建和交付 | 根据固定快照生成正文、SEO、sitemap、文件清单，备份后上传 | 交付期间保留上次成功身份；不能提前把任务标成公开成功 |
| 读回验收 | 核对普通 URL 的 HTML/hash、媒体、canonical、sitemap、HTTP 状态和当前任务所有权 | 验收成功后登记新的公开引用、首次 publishedAt 和实际 modifiedAt |
| 构建/交付失败 | 留下失败任务、已知写入和恢复结果 | 草稿仍在；公开状态不伪装成成功。是否恢复按共享发布器规则处理 |

构建过程中需要使用候选内容，所以内部构建快照与外部“已上线列表”必须分开。首次发布前的构建 HTML 可使用服务器为该任务固定的拟公开时间；验收成功后原样登记该时间，失败重试不得把上次失败时间写成真实发布日期。任务记录保存这些日期，不能用每次 build 的当前时间。

同一文章的新旧发布任务按任务编号和修订检查：旧任务迟到不能覆盖已成功的新修订。编辑草稿不改正在交付的冻结内容；发布任务失败可重试同一候选，不重新拿“现在最新的草稿”替换它。

## 与现有部署、撤回及缓存的关系

复用共享部署锁、备份、静态上传、文件清单、验收和恢复入口，不建立第二套 Blog 部署器。现有正常 Deploy Test 不在本轮切换；整站发布入口、内容变更触发、自动恢复和应急 SSG skip 尚未完成的部分必须按 SEO 执行计划继续实现，不能用文章模块绕开。

撤回是独立操作，不是删除 draft：移除列表/内链/sitemap，明确处理旧 URL，清理对应 CDN，实际访问返回 404 或在有明确永久撤回语义时 410。已加载页面、刷新、浏览器缓存和 CDN 普通请求分别验收；不能仅看带随机参数的请求成功。恢复旧静态包时也必须排除已撤回地址，不能把它们重新公开。

搜索通知只消费已验收内容变化；稳定 sitemap 不用每次重新注册。技术发布 A→B→A 的短暂变化按既有稳定窗口合并，演练地址不通知搜索平台。
