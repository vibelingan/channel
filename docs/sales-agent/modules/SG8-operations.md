# SG8 留档、运行、上线与收益验证

实施单元：SG8.1、SG8.2。审计最小字段从SG0开始消费，不能到最后才临时补；SG8.2负责关闭真实外发之前的综合验收。

## 留档位置与回执

Hermes持久保存任务/运行、输入来源版本、事实依据、固定邮件/附件、操作人批准/接管、发送操作及provider结果。Resend保存邮件相关事实，Channel保留询盘原始事实。群消息、临时目录和模型自报“已完成”不作唯一证据。

记录由接入服务、运行器、归档器、审批后端和发送网关自动写。自然语言只触发候选动作；被验证并执行后的事实才入账。无需复制整个企微聊天到Channel。

可选ChannelReceipt异步回写task/artifact/provider引用、当前已知状态与最后同步时间。失败单独重试，拒绝旧revision覆盖新记录。页面显示“最后同步状态”，不能冒充实时监控。最小官网MVP可不显示Agent进度，但Hermes审计必需。

## 失败恢复和成本

出错按可重试网络/限额、永久输入/授权、需业务补充、发送结果不明分类。只有已知可重试且幂等安全的步骤自动重试；认证失败/停用立即停止新动作。死信通知负责人并提供可恢复操作，不无限循环。运维查看依据是业务记录、outbox、provider回执和持久事件，而非只看容器存活。

指标包括保存→接入、接入→准备完成、等待人工、worker重试、队列年龄、send_unknown、回调延迟、缺客户绑定、越权拒绝、费用/任务。每客户配额度和并发限额，耗尽暂停并通知，不自动切用别人的连接。

留存按数据类型分：业务原始记录、完整邮件/附件、运行日志、审批执行证据。具体天数由客户协议确定；未确认前不自动永久留存，也不执行不可逆删除。实现删除/导出时检查法律保留和正在使用的附件引用；旧审批审计可按政策保留hash/元数据。退出服务包括停止活动、撤销连接、交接和留存，不等同关闭浏览器会话。

## 分阶段启用与回滚

1. disabled：合同、fake provider、跨客户负向测试。
2. draft_only：真实客户授权后只生成/保存草稿，禁外发。
3. test_sending：只向服务端test_recipient_allowlist发送合成任务的固定测试邮件、验证附件与线程，所有受控发送路径包括确认信/回复强制校验To/CC/BCC；Apollo用隔离测试活动和身份，禁止真实买家列表。
4. approval_required：客户同意后少量真实询盘，人批准实质邮件；固定确认模板按已批准策略启用。
5. 观察后才扩大渠道、客户和维护活动。

回滚先关闭新外发/停队列，核对dispatching/send_unknown和未发稿；保留原询盘。旧SMTP确认恢复前要证明新路径已停并处理在途发送，不能单靠部署回滚就打开两条路径。

## 工时验证

旧30分钟与常规辅助10分钟、15条/天释放73.7小时/月均是历史假设。保持[原模型](../reference/计算模型.json)，不作为承诺。试点按同口径记录需求整理、查产品、正文、附件、审核、归档的人工分钟，另记返工/接管/每天运维、Agent运行时长和模型/工具费。

至少同时展示样本量、复杂度、人工基准来源和测量窗口。先做一个可操作的小样本（建议20条、按复杂度分层，仅为试点建议），结果不足就继续采样，不用样本量充当统计显著性。报告释放处理能力，不折算裁员；漏附件/错收件人等单独计数，不预设错误下降比例。

## 切片和验收

- SG8.1：统一事件持久记录、成果/批准/发送关联、可选Channel回执、告警及成本记录；不新增通用任务大屏。
- SG8.2：端到端负向/竞争/恢复演练、切换runbook、试点采样表、接入退出检查。写清产品实现、本地测试、测试部署、真实客户验证各自状态。

目标用例 `audit_records_actor_snapshot_provider`、`channel_receipt_failure_does_not_resend`、`stale_receipt_cannot_regress_state`、`quota_exhaustion_does_not_switch_customer_key`、`rollback_does_not_double_ack`、`client_offboard_stops_campaign_and_revokes_keys`、`crash_after_provider_acceptance_reconciles`。通过后仍需客户实际环境验收，未登录/未发信不能称联调完成。
