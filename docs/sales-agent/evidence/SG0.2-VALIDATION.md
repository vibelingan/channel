# SG0.2 客户连接与动作授权

2026-10-23。实现位于packages/sales-contracts，独立于pricing和SEO。不改公开客服、登录、产品价格、询盘保存和其他工作区。实现范围是可供服务器调用的授权库及配置合同，尚未部署到线上Hermes。

## 已实现的服务器行为

- 新增client-bindings唯一schema及生成类型；Python校验同一份数据规范，不另写一套授权策略。
- 每次执行读取最新服务器配置，通过连接ID及独立凭据确定主体。凭据引用由服务器解析，SHA-256固定长度摘要经timingSafeEqual比较；输出和拒绝信息不包含凭据。
- 校验客户、业务、安装、runtime、environment和control_epoch。未知连接、停用客户、撤销连接、未知动作、重复或跨客户共用的敏感身份配置均拒绝，没有默认客户。
- Runtime即使误配approve权限也不能批准；operator必须在客户映射中。Publisher只可通过发送权限前置检查，测试模式检查实际To/CC/BCC及发件/inbox身份。
- 认证等待期间配置变化则拒绝；资料读取返回前再次检查权限，撤权后的在途读取结果不释放。被授权的人工停止动作不会因为自动化开关关闭而失去停止权限。

这里的mail.send权限不构成最终发送批准，调用方不能把回调直接接到Resend发送。精确内容批准、发送账、暂停/接管状态和未知结果对账仍由SG5实现。没有真实发送接口。

## 验证

先用拒绝全部请求的最小骨架执行12项测试的前10项：4个正向行为如期失败，6个拒绝用例通过，失败来自尚未实现允许路径。实现后10/10通过。追加publisher误配读取权限的用例，观察到Missing expected rejection；补actor限制后12/12通过。未把缺依赖或导入失败当业务RED。

最终结果：合同包21个TS测试通过（包含12个授权测试），6个Python测试通过；58个共享数据样例的TS/Python结果一致；typecheck、check:generated及手写源码Biome检查通过。原有邮件fake和固定摘要用例保留。

测试使用A/B不同canary身份与工具目标，验证拒绝时不调用目标操作，不只是检查文案。服务器配置和凭据加载器故障均有拒绝用例。以上为离线程序测试，没有访问真实客户或平台账号。
