# 连接授权和资料读取分别做什么

这两步是在官网和销售 Agent 之间建立可控的资料通道。网站继续保存询盘，Agent 通过专门接口读取；没有把数据库管理员账号交给 Agent，也没有新增 CRM 或邮件客户端。

## SG0.2：检查这次调用有没有权限

例如，A 公司的官网留下了“采购 500 个耳机”的询盘。A 的 Sales Agent 想读取时，服务器先核对这次连接属于谁、处理哪条业务、对应哪个网站安装和 runtime，权限版本是否仍有效。A 的 Agent 带上 B 的身份、使用已经撤销的连接，或把其他业务的身份带入官网询盘接口，都会被拒绝。

这里的连接凭据由服务器保存。模型说“我是 B 公司”不会扩大权限；客户/业务也不是从聊天文字中猜出来的。配置记录用于指定允许的资料和动作，实际对外发送仍要经过后续的审批与发送模块。现在的授权库不等于已经实现了暂停按钮或邮件审批界面。

这一层的结果是“这次读取允许／拒绝”，不负责写邮件，也不负责判断客户要采购什么。

## SG1.1：允许后，具体可以取到什么

这个接口已经接入原有 OEM、单品询盘记录，按白名单返回联系信息和需求。产品快照指提交询盘当时保存的产品资料；产品后来改名、改配置或改价格，原询盘的快照不会被当前页面覆盖。需要查当前批准资料时，继续调用原产品读取逻辑，不另算一套报价。

附件只有在上传已正式完成、归属本条 OEM 询盘、大小和内容校验均正确时才可读取。Agent 拿到的是受控附件引用和文件内容，不能用它查询任意路径或拿到原始私有存储地址。大文件分段读取，每段仍检查权限和文件内容。单品表单当前没有附件字段，接口没有凭空增加这一类文件。

它提供的是“按 ID 取这条资料”的服务。尚未负责把每个新询盘自动推送给 Hermes；保存后通知和漏通知补扫属于 SG1.2。

## 放进整个业务流程看

官网保存询盘 → 通知 Hermes（后续接入）→ Hermes 接收并排队 → Agent 准备处理 → SG0.2核对权限 → SG1.1取资料 → 生成邮件和附件（后续接入）→ 人审阅批准 → Resend发送。

现在已完成的是连接授权和资料读取代码。接下来的 SG2.1 分开不同客户的运行目录、知识及工具，SG2.2 负责把事件可靠存成任务：同一事件重复通知不会新建多份任务，中断后可以恢复派发。它们也不会直接生成或发送邮件。

本地／隔离 CI 验证、接通当前线上 Hermes、真实测试邮箱投递是不同的验收步骤。已有结果见[资料接口验证](SG1.1-VALIDATION.md)，后续按[真实联调计划](LIVE-TEST-PLAN.md)执行。
