# 后续真实联调与验收

本计划由本地测试之后继续执行，属于SG2／SG4／SG5接通后的集成验收。当前没有将任何一项标为通过，也不在现有客户文章或营销任务上试发。

## 开始前要记录实际运行环境

由实施者读取真实部署记录，记录线上HermesInfra提交或镜像digest、定海/发布助手实际入口和协议、Sales专属runtime及知识/文件范围、企微测试入口及操作人身份、Channel API版本/TCB_ENV、客户连接和Resend Team/inbox/发件身份。使用连接引用记录，不保存或截图明文密钥。

本地Hermes ff066b12和Channel main 404d1a25只是源码参考。若线上版本不同，先核对接口，再调整适配；不根据它们“理论上应该一样”直接测试。Channel数据库必须证明属于该安装；旧数据若混有未标归属的其他客户，先解决归属，不启用读取。

## 测试顺序及证据

| 阶段 | 实际操作 | 必须留下的证据 |
|---|---|---|
| 已部署的读取接口 | 在隔离环境准备A/B canary；由对应连接查询自己的询盘、快照和附件；尝试错客户、错业务、旧epoch、撤销连接和他人附件 | 部署版本、脱敏请求身份、HTTP结果、实际读取目标；负向用例没有返回他方资料 |
| 实际文件传输 | 用真实CloudBase存储和HTTP网关下载小文件、2MiB及接近10MiB文件；大文件以每段最多4MiB的Range请求拼接，核对完整hash；测试未分段、段过大、非法Range、源变化、错误host及超时 | 已部署网关对Range/206/Content-Range的实际透传、bytes/hash、拒绝结果、耗时；私有URL未出现在客户端 |
| Hermes真实调用 | 用独立Sales任务及测试企微入口提交；定海分派、重试和恢复；确认runtime、文件、知识及凭据均属于该客户 | 真实task/run/receipt ID、路由和存储目标、重复事件只产生一项任务；不以聊天回复替代落盘证据 |
| Resend真实草稿 | Agent产出HTML、纯文本、附件；在实际工作台及固定预览检查同一版本 | draft ID、版本与实际内容hash，附件可读；修改后旧批准不能继续使用 |
| 独立测试邮箱投递 | 仅用合成任务，服务器限制To/CC/BCC到测试地址；经明确批准后投递并回复 | provider message ID、测试邮箱实际收件/附件/线程、送达与回信事件。API接受或fake成功不算实际收件 |
| 控制与恢复 | 对上述测试任务暂停、接管、撤权；演练超时但已发送、重复批准和进程恢复 | 状态账及发送账；未知结果先对账，未产生第二封；旧任务不能借新客户/新连接续跑 |

读取测试可先于发送闭环完成。发送阶段依赖SG4/SG5；官网自动触发还依赖SG1.2、SG2.2。先做dry-run，再测隔离账号，最后在获批的小范围线上合成任务中验证。现有官网确认信与Resend切换按SG4.3单独验收，避免两路发送。

本轮已经完成的离线和loopback结果见[SG0.2](SG0.2-VALIDATION.md)、[SG1.1](SG1.1-VALIDATION.md)。客户真实业务启用前，还需业务方确定实际负责人、权限及接入范围；不再重复讨论内部接口如何实现。
