# SG1.2a：Channel 可信来源授权实施记录

2026-10-29。工作树：`channel-sales-agent-integration`，分支：`feat/sales-agent-integration`。本记录只说明本地实现与验证；未部署、未开启生产开关、未发邮件。

## 已实现

Channel 新增独立的后台 `POST /integrations/sales/source-grants`。默认 404，只有主开关与 `SALES_SOURCE_GRANTS_ENABLED=1` 同时打开才存在。它使用独立后台凭据，拒绝运行读取凭据与 Hermes 许可查询凭据冒用。调用方不能选择有效期、产品范围或发送权限。

一次 node-sdk 事务重读当前安装、客户绑定、明确归属的询盘、附件元数据和旧授权，核对完成后才一起写交接、300 秒读取 lease、请求指纹及 lease hash 使用记录。原始 token 由 Hermes 生成，Channel 只接收摘要。事务内不调用外部 HTTP。原来的资料读取接口继续核验连接、任务、当前来源和 Hermes 实时许可。

规范事件由保存的事实生成：OEM 摘要取品类，单品摘要取 brief；没有内容时使用固定说明。只有明确的正整数数量才提取，最多 1e9。单品快照引用由实际提交快照计算 hash。请求事件只有 `event_id` 可不同，其他事实必须一致。尚无服务端来源映射的智能客服事件继续拒绝。

相同请求返回原先仍有效的结果，不延长到期时间；换任务或复用同一 token hash 会冲突。过期后需要新的随机 token。已撤销或损坏的交接、lease 及请求记录不会被当作缺失记录覆盖。

已有附件引用上限不一致：询盘事件原来只允许 200 字符，读取接口与 lease 已允许 1800；32 字符记录 ID 的实际编码可达 236 字符。本次只把事件上限对齐为 1800，未改变其他授权合同。独立合同增量已推送：`38cba5913b4c0467e43756ffc04cd3e9aa0b7de6`。

先新增测试，初次运行因授权模块尚不存在而失败，再实现接线。当前结果：

- Sales integration：54 项通过，包括原有读取回归、真实本机 HTTP、来源核验、撤权、重试、并发和写入故障回滚。独立评审后补测第 1／2／3／4 次写入故障，确认前面已暂存的交接或 lease 不会留下半成品；清除故障后同一请求可正常重试。自查发现 SDK 无 data 或错误包可能被误当作缺失记录，先复现失败测试后补门禁；只有明确的 `data:null` 或空数组表示不存在，读取失败不能覆盖旧授权。
- 共享合同：TypeScript 67 项、Python 8 项、跨语言 conformance 61 项通过；生成检查与类型检查通过。
- 5 个定向缺陷在临时源码副本中注入，全部由对应行为测试抓出：放宽记录客户归属、跳过 OEM 完成状态、忽略保存事实、把撤销交接错误重置为 ready、忽略过期 lease。原工作树未被注入修改。
- CloudBase SDK 合同验证通过；函数构建、独立打包和无工作区依赖的冷启动检查通过。

SDK 依据：已读 CloudBase 技能和项目 SDK gate；Context7 当前未提供。核对官方事务文档与已安装 node-sdk 3.17.2／database 1.4.3：`runTransaction` 返回回调值，事务 `doc.get` 返回 `{data: doc|null}`，`doc.set` 使用不带 `_id` 的扁平数据，新增写入可由 `upserted` 确认。适配器复用现有 `NodeSdkDatabase`，未扩充 SDK shim。行为测试还核对不明确文档身份、无写入确认、写后读取均拒绝。CloudBase 部分使用真实 SDK 契约检查及仿真事务测试，没有连接线上业务库，不能称为生产事务验收。

跨项目独立验收最终 14／14 通过，无跳过：Hermes 使用实际 MySQL，Channel 使用实际本机 HTTP 和合成 NoSQL 事务存储。源码 hash 与 Channel HEAD 在整轮中保持一致；自建测试容器及卷已清理。这里的 54 项不包含那 14 项，二者都不能替代线上 CloudBase 或真实客户连接验收。

## 仍未接入

官网现有保存路径尚未统一写三项归属，OEM 也尚无正式最终完成标记。本单元不补录旧行、不修改表单、不安装提交 hook、不做补扫。没有证明的记录仍然拒绝。因此本单元完成后，不能宣称官网询盘已经自动触发 Sales Agent；下一单元应接生产保存与最终完成流程，再验收事件投递。

最重要的边界：Channel 只核验自己保存的来源，Hermes 仍须核验它保存的当前任务及 run。来源授权完成后如果任务停止，后续激活和每次读取仍要拒绝；已返回的数据无法追溯收回，两套服务之间也不存在一次跨库原子撤权。
