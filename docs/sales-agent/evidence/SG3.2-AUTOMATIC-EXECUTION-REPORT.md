## 现在能做的事

官网询盘正式保存、经原通知和 Dispatcher 被 Hermes 受理后，消费者会自己找到任务并开始处理。销售不用再对每条记录下“开始”指令。之前可调用的准备模块继续复用，这次补上的是自动任务读取、消费记录和真实模型适配器。

```mermaid
flowchart LR
 A[Channel 正式询盘] --> B[已有可靠通知和 Hermes 受理]
 B --> C[自动领取当前任务]
 C --> D[Channel 来源核验及短期授权]
 D --> E[受控读取实时产品]
 E --> F[真实模型分析与计划]
 F --> G[系统校验并生成正文]
 G --> H[固定版本与证据归档]
 H -.后续 SG4/SG5.-> I[Resend 草稿及人工审核]
```

模型可以分析需求、读取已知产品、列出缺项和内部建议。当前外发正文由系统根据核验资料渲染；本轮不开放模型自由编写任意 HTML 或编造报价。产品查询用实时批准资料，提交快照和本次使用的事实仍留档。

本轮没有重写官网智能客服，也没有接入暂停、继续、人工接管或新的控制页面。没有把其他 Agent 搬到新环境；通用 Hub、定海和现有内容发布流程未改动。

## 权限和重复处理

消费者只读取自己专用数据库中当前 accepted 的任务。任务、run、客户、来源和收件人从已保存记录及服务器配置取得；模型不能提供这些身份或凭据。Channel 核验来源，Hermes 核验当前任务，每次资料读取继续经过既有两端门禁。

队列领取决定谁能记录处理结果，原运行锁决定谁能真正执行同一任务。旧领取过期后，新的进程也不能重复进入模型准备；旧进程不能覆盖新的队列记录。已经完整保存的成果或失败记录，会先经过核验恢复，避免重启后重新生成。模型响应后、归档前崩溃仍可能再次计费，这个窗口没有被隐藏。

暂时故障有重试上限，忙碌不扣失败次数。错客户、旧 run、撤权、非法工具请求和被篡改的成果均有拒绝用例。默认没有发送工具，成果保持待审核状态。

Channel 存储使用事务测试适配器，HTTP、Hermes MySQL 和模型 SDK 是实际调用；因此不把这次结果当成线上 CloudBase、生产 Infra 或邮件送达验收。

独立 review 及实测修复了四类问题：授权等待期间旧任务完成却被误记失败；认证文件误配为 FIFO 时阻塞；真实 MySQL 返回 Decimal 导致重试记录失败；真实 Codex 省略 Content-Type 被提前拒绝。修复后仍保留严格任务、工具、正文流及完成状态检查。首次失败、诊断和后续成功分别留档。首轮远端 CI 另发现一条冷启动时间断言不稳定；已改为正文仍被事件屏障阻塞时必须完成错误分类，增加第九项缺陷注入，运行时代码未变。修复后 15 项模型规划器测试和 9 项缺陷注入已通过，最新整套 CI 见上方同提交链接。
