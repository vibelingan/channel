## 三条入口如何衔接

首页 OEM 表单、单品询盘表单、智能客服确认提交，都应走“保存询盘和可信来源 → 可靠交给 Hermes → Sales 读取资料并生成内容 → Resend 草稿”。智能客服只负责其中一个前端入口，后半段不应依赖它在线。

这条设计与现有实现相符，但正式开关、固定云端读取服务和常驻消费者还未配置完。历史普通询盘没有新的来源身份和交接回执，不能随意补上客户字段、当成已经验证过的任务，也不批量重新跟进。若后续要处理存量，应单独限定范围和去重规则。

普通 OEM 提交的现有程序仍有旧确认信逻辑。无真实发信的验收必须先核对该路径的有效配置，不直接点击一个可能触发 SMTP 的正式表单，也不为了测试全局关闭真实客户的邮件服务。此次没有调用它。

## 恢复后按现有用例做线上验收

复用 [真实页面旅程](../../../tests/assistant-site/fullsite.spec.ts)、[交互组件与后端用例](../../../tests/assistant-chat/connected.spec.ts)、[浏览器前进后退](../../../tests/assistant-chat/back-forward-cache.spec.ts)。复用的是用户动作、状态和回执检查；本地固定回复不能直接当成真实模型的预期文字。

| 场景 | 用户动作及要验证的结果 |
|---|---|
| 普通访客开始聊天 | “Hi”及模糊采购需求都能得到有效回应，不出现空白回答框或一直无响应。 |
| 产品推荐和连续追问 | 例如“要 300 副降噪耳机，能印 Logo 吗？”从真实公开产品中推荐，首批最多 5 个；追问沿用上下文，产品变化时重新查询，不凭空保证价格、库存或交期。 |
| 桌面与手机浏览 | 分别验证箭头／滑动／圆点、卡片宽度、继续看更多、不重复推荐；点击详情同页跳转，聊天自动打开并保留上下文，返回可继续。 |
| 公司知识库 | 用真实公司问题验证 VibeKB 查询和依据；查不到时说明缺少依据并继续引导，不把本地知识夹具成功当成 MCP 已接通。 |
| 流式回答及失败恢复 | 同一条回答在完成前确实增长；停止后迟到结果不再覆盖；一次失败后仍可提新问题。超时、无匹配、缺图等有清楚的提示。 |
| 聊天内询盘 | 在聊天内补充／修改信息，确认之前不落单；确认后只保存一次。故意丢一次成功回执时查原提交，不能生成重复询盘。 |
| 两个普通表单 | 恢复可访问后分别实际提交带标记的测试询盘，并由后台读回；确认统一来源登记、通知和不发信边界，不能只检查按钮或 HTTP 200。 |
| 接入 Sales 的首轮闭环 | 每个已启用入口至少一条受控记录，关联询盘 ID、来源回执、task/run、成果版本和 Resend 草稿 ID；核对实际邮件、附件及未发送状态。对同一条做一次重投验证去重，再做明确的错身份／旧版本拒绝。 |

每个入口先跑常见完整旅程；有因果关系的边界再补针对性用例，不组合遍历全部内部函数。没有代码变化或新失败，不重复已经通过的后半段大套测试。线上恢复后，优先补本次尚未执行的真实浏览器入口与正式自动交接。

企微审批、真实发送、客户回信后的第二轮处理不列为本次已完成内容。回信通知与任务关联已有 [SG4.2 设计](../modules/SG4-resend.md)，第一期不默认自动回复。

## 2026-11-09：发布前的离线函数校验修正

本日发布运行 `42566014896` 的源码、浏览器 CI 均通过，但在发布前加载函数安装包时停止，尚未发布网站。用相同开关在本机实际加载 admin 安装包，复现的明确错误是 `Missing Sales delivery configuration: SALES_HERMES_SOURCE_TOKEN`：发布任务启用了 Sales，离线检查继承了这些开关和客户身份，却没有它所需的凭据。不是据此认定线上 Hermes 或 Key 不可用。

修正只涉及检查程序：所有离线函数子进程统一使用合成客户身份、独立假凭据和 `.invalid` 接口地址，保留启用 Sales 的初始化检查；不把真实凭据交给测试，也不跳过原有冷启动、原生数据库适配器或缺陷注入检查。初始化失败改为记录简短异常堆栈，避免压缩源码的一整行挤掉真正原因。

本机 Node 20.19.0 下，四个新增回归与既有部署／安装包检查合计 59 项通过；新增配置回归先在修正前失败，另用故意损坏的安装包确认通过符号链接调用检查程序时也不会跳过验证。三个 manifest 函数重新构建后，实际安装包冷启动、产品读写适配器、写入回执／回滚／重试、缺失集合反例均通过。原生图片依赖按本机 macOS 打包验证，GitHub 的 Linux 发布仍须执行原来的目标运行时检查。以上结果属于本地发布前验证，不能代替后续官网和真实 Sales／Resend 验收。

本次读写核对了 `scripts/smoke-function-artifacts.mjs`、发布 workflow、两个函数的 Sales 初始化和已有安装包检查；将“安装包检查失败”具体解释为“离线检查继承了启用开关，却缺少凭据”，没有改业务权限、询盘内容或发送路径。
