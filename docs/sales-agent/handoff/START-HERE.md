## 各模块后续交接说明

以下为候选实施任务，需依赖通过后逐项开始，不表示本轮已启动。

| 模块 | 给实施者的核心要求 |
|---|---|
| SG0 | 先合同和假服务，再服务器客户连接/动作绑定；没有scope拒绝，不靠prompt隔离 |
| SG1 | 复用已存在的询盘、快照和后台，只补授权资料及可靠交接/补扫，不强行迁表 |
| SG2 | 在独立Hermes工作区复用任务基础，补客户runtime/工具/文件和manifest；不动现有文章流 |
| SG3 | 规则文档＋skill＋结构化结果；缺商务依据不编承诺；通过内容工厂准备正文附件，不拿发送权 |
| SG4 | Resend草稿是工作副本，固定payload才是自动发送依据；回调/联系人同步由程序负责 |
| SG5 | 个人身份、精确版本批准、稳定逻辑邮件身份；暂停对最新任务生效，未知结果先对账再移交发送权 |
| SG6 | Apollo独立获客；先证明授权及回复正文来源，停发成功才交接，缺正文交人 |
| SG7 | 每次接一个有明确授权数据来源的渠道；来源、业务和营销许可分别保留 |
| SG8 | 各步骤有持久证据；Channel只回少量结果引用；分阶段演练/切换并实测人工耗时 |

## 每次交付需要写清楚

1. 仓库、worktree、分支、起止提交及实际改动文件。
2. 该单元实现了什么，哪些依赖只是假服务，哪些外部能力实际联调过。
3. 具体测试结果及证据；失败项和未验证项目分开。
4. 是否保持客户、业务、版本、暂停/接管、外部发送和回滚条件。
5. 下一单元及可用接口版本。接口变化更新共同schema和依赖方，不只改本模块文字。

本任务每个单元验证后必须提交并推送origin，核对远端SHA，不能只留本地；先完成前一单元再开始下一单元。PR、部署和真实外发分别遵守当次任务与仓库规则；不得从“设计完成”推导出已允许对客户发送或购买服务。
