# Engineering Craft

Reusable implementation lessons that should survive beyond a single incident log.

## Private Media Preview Pattern

When previewing private or unpublished media in a browser:

- Keep durable media access behind an application route that performs auth and
  visibility checks before reading storage bytes.
- Do not expose raw storage/COS URLs in the DOM unless the design explicitly
  chooses a public or short-lived signed URL contract.
- For admin or authenticated previews, fetch the bytes through the app route,
  build a `Blob`, and render it with `URL.createObjectURL(blob)`.
- Treat `blob:<origin>/<uuid>` entries in browser DevTools as local browser
  object URLs, not extra CloudBase or COS network requests.
- Revoke object URLs with `URL.revokeObjectURL(url)` when the preview is replaced,
  removed, or the component unmounts.
- Keep public catalog delivery separate from admin preview delivery. Public
  routes should remain publish/ref-count gated; admin preview routes should be
  authenticated and should not weaken public visibility rules.

This pattern is preferred for private product images because it preserves the
storage privacy boundary while still giving the UI efficient image previews.

### Auth & Session Security

- **Single choke point revalidation over token generation** (`3a1ce3c`, `836c39a`): For session revocation (suspend/demote/delete), re-anchor every verified JWT to the CURRENT users row at ONE choke point immediately after token verification, so every downstream action authorizes against refreshed claims. Beats a tokenGeneration scheme: generation comparison still needs the row read, adds a bump-on-suspend invariant to every future role-mutation path, and handles deletes no better. Mirror revocation semantics with login (only explicit 'suspended' revokes; legacy status-less rows stay valid); promotion also applies without re-login. Cost: one get per authenticated request.
- **Optional auth fails closed to anonymous degrades on infra failure** (`b011f88`, `836c39a`, `ec49d44`): On endpoints where auth is OPTIONAL (public catalog with role-gated extras), never 401 — resolve every ambiguous input (no secret, blank/invalid/expired token, missing/suspended row) to the ANONYMOUS entitlement. Untrusted-input failures fail closed silently; INFRASTRUCTURE failures (row lookup throws) also degrade to anonymous but MUST be logged. Reject the reflexive 'anonymous-scale endpoint cannot afford a row read' rationale: the read only happens when a verified Bearer token is present.
- **Role union guard so corruption only loses privileges** (`836c39a`, `ec49d44`): Narrow EVERY untrusted role string (JWT claim, DB row) through one union guard — toRole() returns the value only if in the ROLES const, else '' (base entitlement) — and ban blind `as Role` casts. The collapse direction is the security property: corruption can only LOSE privileges. Pair with jwtVerify pinning algorithms+issuer+audience and per-claim type checks. Keep ROLES the single source for admin role-select options so a role can't be assignable in UI yet collapse to '' at authz time.
- **Vary authorization when a public response becomes role gated** (`3ba3039`): The moment a previously-identical-for-everyone endpoint varies its body by session token, cache headers are PART of the security fix: a shared/CDN cache keyed only on URL will serve a member's VIP body to anonymous callers. Emit Vary: Authorization (+Origin) and Cache-Control: private, no-cache on every such route including dev-parity servers. Checklist trigger: any diff threading a viewer/entitlement parameter into a formerly-anonymous GET must also touch its response headers.
- **Uniform notfound plus hash then timing safe secret** (`871adff`, `f2bf266`): Unauthenticated finalize endpoints are enumeration surfaces: every precondition failure (missing doc, wrong purpose, mismatched intentId, malformed fields) returns one identical NOT_FOUND so probes learn nothing. Verify the one-time secret by hashing the presented plaintext (SHA-256) then timingSafeEqual against the stored hash — hashing first equalizes buffer lengths so timingSafeEqual never throws on length mismatch (itself an oracle). Order matters: the consume-once claim sits AFTER the secret check so a caller without the secret cannot burn a victim's claim; clear the secret hash on successful finalize.
- **Revocation and header hardening must sweep sibling paths** (`836c39a`, `317f60a`, `2eeb2b4`): A security control fixed on one path predictably has an unfixed twin: V3 revocation shipped in the admin handler while the catalog VIP resolver kept trusting the token role (closed a round later); nosniff on /api/images left sibling /api/files reflecting client MIME. When landing an auth/header fix, enumerate every route verifying the same token class or serving the same data class and fix in the SAME commit. Structural cure: dev-parity surfaces delegate to the one hardened handler.

### Public API Projection

- **Allowlist projection with separate gated tier** (`2eeb2b4`, `317f60a`): Public API responses must be built by explicit allowlist projection, never by spreading the DB doc — spreading shipped role-gated vipPrice and internal fields to anonymous callers while the UI gate was cosmetic. Allowlisting withholds every FUTURE field by default. Keep role-gated fields in a physically separate GATED_FIELDS list attached only after a server-side entitlement check. Construct the projected object typed as the real interface with required fields set unconditionally (no cast) so allowlist mistakes become compile errors.
- **Refcount gates public media and fails closed on corruption** (`7965ad7`, `d82bc5e`): Public media delivery is gated on a canonical publishedRefCount counter: unpublished/unreferenced images 404, replacing an O(catalog) scan per request. The counter is 'visible' only as typeof number && isFinite && > 0 — the first cut used Number(doc.publishedRefCount) which fail-opened on a corrupt numeric STRING like '1'. Field PRESENCE (Object.hasOwn) is split from validity: the legacy fallback scan runs ONLY when the field is absent; present-but-invalid is corruption and 404s. Unknown storage providers also fail closed.

### Content Validation

- **Close the mime confusion chain at all three links** (`2eeb2b4`, `adae0d0`, `317f60a`): Stored-XSS via content-type confusion is a three-link chain; close all: (1) ingest — magic-byte-sniff bytes against declared MIME before activation; on UNAUTHENTICATED write paths derive stored mimeType FROM the sniff, never the client; (2) registry — mark mimeType readOnly so generic CRUD can't rewrite it; (3) delivery — reflect Content-Type only from an allowlist (unknown degrades to octet-stream) plus nosniff always. Sniffer pitfall: per-signature accepted-alias allowlists (ZIP has 4+ MIME aliases) or valid files get rejected — write positive over-reject-guard tests.
- **Svg delivery needs csp sandbox nosniff is not enough** (`317f60a`): nosniff does NOT protect allowlisted image/svg+xml: an SVG navigated to directly is a document and its inline script executes under your origin. If SVG must stay deliverable, add Content-Security-Policy: default-src 'none'; sandbox to the binary response — script-disabled unique origin, no external fetches. Treat any active-content type on a byte-delivery allowlist as needing its own document-context control even when no user write path currently exists.
- **Magic bytes necessary not sufficient plus declared mime aliases** (`f2bf266`, `140014a`): Server-side content validation sniffs leading magic bytes (never trusts client MIME/extension), with two practical refinements: (1) the declared-vs-actual check must accept known browser ALIASES per signature (clients report non-canonical archive/image MIMEs) or valid uploads get falsely rejected — while application/octet-stream is excluded from alias lists and gated separately by purpose + extension; (2) formats with no reliable signature (CAD: step/igs/dwg/dxf) must return 'unknown' rather than guess. Enforce size at finalize by recomputing byteSize/SHA-256 from actual bytes — the storage credential cannot express content-length-range, so intent-time size is advisory only.

### Upload Lifecycle & Concurrency

- **Cas claim before destructive validation** (`f2bf266`, `871adff`): In an upload finalize saga, place the consume-once atomic single-winner claim (incrementField CAS, claim===1 wins) immediately AFTER cheap structural + secret verification but BEFORE any storage download or destructive mutation. A concurrent loser returns CONFLICT with zero storage reads, no deletes, no row mutation — closing a download-amplification vector and the race where destructive byte-failure handling ran before the winner was known. Post-claim retry policy: an unreadable object is TERMINAL for the now-consumed intent (fail row + best-effort delete, client re-uploads) because releasing the claim would itself be racy. Encode 'winner-only below this line' as a comment boundary; test that the loser touches nothing and the object is downloaded at most once per intent.
- **Reserve first admission caps never over admit** (`d69eeab`, `9cd7c81`): Check-then-create caps race: concurrent callers all read a count under the ceiling and burst past it. Fix by RESERVE-FIRST: persist the pending row before counting, count WITH the reservation included, and roll the reservation back on any denial or downstream failure (including updateDoc returning null). Every admitted reservation is visible to concurrent counters, so admitted <= ceiling holds under any burst; fails safe (may over-reject under contention, never over-admits). Chosen over per-window atomic counter docs because a pending cap is a live gauge that a counter would drift on.
- **Orphan sweep object first with paired mapping** (`f04cd2f`, `dd658c7`): Expired-intent sweeps must delete the storage object FIRST and retire the DB row only when that delete succeeds; a delete failure leaves the row retryable — never orphan bytes, never over-delete. The selection primitive must preserve doc-to-object PAIRING (items: [{docId, storageFileId}]) rather than parallel arrays: with unpaired arrays a single failed delete cannot be mapped back to its doc, so callers blindly mark all docs deleted on partial failure. Sort oldest-expiry-first and bound the batch.
- **Compensate orphaned object when staging fails post upload** (`e603f34`): Split upload-then-stage into two failure regimes: a pure upload failure leaves NO object (skip + retry), but once the object exists, any staging failure — thrown error OR updateDoc returning null — must trigger a compensating deleteObject; a null staging result must never count as success. If the compensating delete ALSO fails, the object is genuinely leaked: log loudly ('LEAKED storage object <id>') and surface in the operator-visible result payload — silent leaks of private bytes with no doc pointer are invisible to orphan cleanup.
- **Wire the sweep piggyback cleanup on hot path** (`dd658c7`, `35c6400`): A cleanup primitive that is designed, unit-tested, and exported but never CALLED from production is a silent no-op: expired pending OEM intents accumulated forever because the sweep had no production caller. When no scheduler exists, piggyback a small bounded sweep (limit ~3, oldest-first) best-effort onto the same entry point that creates the garbage, wrapped so a sweep failure never blocks a legitimate request — the abuse surface self-heals in proportion to its own traffic. Review question: for every lifecycle helper, 'who calls this in prod, and what happens if nobody does?'
- **Throttle wire contract 429 retry after exposed** (`66eaa69`): Abuse-control denials need a full wire contract: a dedicated RATE_LIMITED error code mapped to HTTP 429 (not overloaded onto 409, which clients treat as non-retryable), retryAfterSeconds in the typed error body, mirrored as a Retry-After header, AND Access-Control-Expose-Headers: Retry-After — without the expose header a browser client can never read the backoff hint. Tests assert the code and retryAfterSeconds >= 1, not just 'some error'.

### Counters & Data Integrity

- **Rate limiter fail closed counter integrity** (`f23f56c`, `f84d6cc`): Rate-limit and pending-cap helpers must fail CLOSED unless counter integrity holds: counts and limits are safe non-negative INTEGERS (Number.isInteger, not just isFinite — a corrupt -1 or fractional counter must never return 'allowed'), post-increment counts >= 1. Guard time inputs so retryAfterSeconds is ALWAYS a finite integer >= 1 even when nowMs is NaN/Infinity — the deny path's Retry-After must not be corrupted by the same malformed input that triggered the deny. Treat every counter read from shared state as untrusted.
- **State machine fail closed on unknown runtime status** (`f04cd2f`): A status-transition validator whose inputs come from DB rows must validate both values against the canonical status set BEFORE the idempotent same-state shortcut: `if (from === to) return true` silently blesses corrupt statuses ('bogus' -> 'bogus' passes). Import the runtime constant array, build a Set, return false for anything outside it — compile-time union types do not constrain what is actually stored.
- **Non transactional counter maintenance isolates errors and backfill reconciles** (`abcb162`, `fd7e62c`): When a derived counter is maintained as a side effect AFTER the primary write commits, per-item increment failures are logged and skipped — never surfaced as a 500 that would mask an already-committed write. Drift is owned by an idempotent, dry-run-capable backfill that recomputes absolute counts, rather than making the hot path transactional. Decrements are applied only for ids the batch operation ACTUALLY removed (batchRemove returns removed ids), closing a concurrent-delete double-decrement.
- **Skip limit pagination needs a unique sort tiebreaker** (`fd7e62c`): A backfill paging with skip/limit sorted on createdAt can skip or double-count rows tied on createdAt across page boundaries on Mongo-style stores — corrupting the absolute counter it writes — while invisible to stably-sorted in-memory test adapters. Always page on a unique key (_id asc) for a total order when order is irrelevant to the tally. Document the quiescent-window constraint: an absolute-SET backfill can transiently clobber a concurrent live increment; re-run to reconcile.
- **Test fakes must mirror backend edge semantics via shared helper** (`abcb162`, `ba27b60`, `f941c72`): The in-memory test adapter initialized absent fields on increment while real CloudBase reports updated: 0 for inc on an ABSENT field — unit tests passed while every production submission failed. When faking a database/SDK, the divergences that matter are EDGE semantics (absent field, null, non-numeric, missing doc); fix with one shared exported helper (nextCounterValue: absent/null→0, non-finite→throw) consumed by the local adapter AND all test fakes so backends agree by construction. Guard trusted schema-bypass write paths at the single facade choke point.
- **Inspect per item results of batch delete apis** (`65b691d`, `2631aab`): CloudBase deleteFile 'succeeds' at the call level while individual files fail: results come per-file in TWO SDK shapes ({code:'SUCCESS'} vs {status:0}). Normalize both and treat anything not positively confirmed as failure; single-delete verifies the returned fileID matches the requested one; batch delete aggregates explicit failures PLUS requested ids with no result entry ('silently dropped') and throws listing every failed id so cleanup callers can retry. Otherwise a rejected object is reported deleted — orphaned private bytes with no retry signal.

### Deploy & CI/CD

- **Artifact cold start smoke in bare temp dir** (`d69d2ab`, `6b2b3a2`): Before deploying a serverless function bundle, copy the packaged artifact into a bare mkdtemp dir (no node_modules, no workspace) and node -e require('./index.js') asserting the handler export exists — catches workspace-external requires and bundler externalization mistakes no unit test can, because unit tests run inside the monorepo where everything resolves. Pair with a static regex denylist over the bundle for known-must-be-bundled requires so the failure names the exact leaked dependency. Run as a CI gate between packaging and deploy.
- **Bundle runtime provided sdks dont stub them** (`6b2b3a2`): The first artifact smoke stubbed wx-server-sdk ('provided by the CloudBase runtime; keep it external') — but the runtime-provided assumption was wrong, and the stub meant the smoke tested a fiction. Fix: move the platform SDK to tsup noExternal (bundle it) and DELETE the stub so the cold-start smoke exercises the real dependency graph. Corollary of the four-consumer rule: every dependency added to a function's package.json needs a matching noExternal entry; the smoke's require-denylist is the executable check they stayed in sync.
- **New auth dependency has deploy time consumers** (`bde82a0`, `7d42537`): Wiring token verification into an additional serverless function has two silent deploy-time consumers beyond code: (1) the secret — public-api verified with JWT_SECRET but its runtime env never carried it; because the resolver fails closed, the feature silently no-ops forever (provisioning is the only fix); (2) bundler externals — importing a workspace package without adding tsup noExternal leaves a bare require() in a node_modules-less artifact, crashing the WHOLE function at cold start. Mirror the sibling function's deploy env + bundling config and smoke the built artifact from a clean rebuild.
- **Update function config replaces env read merge managed keys** (`ff23345`, `09c9751`): CloudBase/SCF updateFunctionConfig REPLACES the function's entire env — a deploy script sending only its manifest silently erases console-managed hotfix vars. Pattern: declare an explicit MANAGED_ENV_KEYS set (deploy owns these; absent means intentionally deleted, never resurrected), read existing env via getFunctionDetail, merge unmanaged keys UNDER managed ones, and fall back to manifest-only if the returned shape is unrecognized. Meta-lesson: the team first ruled this 'not needed' off a misread UI label — verify replace-vs-merge semantics from docs/SDK source, not tool-parameter labels.
- **Executable sdk contract script pins installed surface** (`72c6e73`, `09c9751`): A hand-written wx-server-sdk.d.ts claimed getUploadMetadata existed; TypeScript accepted it and the deployed runtime failed with 'is not a function'. Durable fix: a standing CI script that createRequire-resolves the installed SDKs from the CONSUMING package, asserts typeof method === 'function' on the live module, greps the installed .d.ts for the exact fields the code depends on, asserts the NEGATIVE (the SDK does NOT expose the method — a future SDK change forces an intentional decision), and asserts the adapter files preserve the SDK-boundary seam. Type stubs for untyped SDKs derive from the installed package's runtime + .d.ts, never from docs or memory.
- **Same platform sdk atomic op silently noops in target runtime** (`72c6e73`, `f941c72`): wx-server-sdk's command-based atomic update returns updated: 0 and does NOT apply in the Tencent CloudBase runtime, while plain updates work — silently breaking every atomic-counter caller (all OEM submissions 404'd). Invisible to 99 passing unit tests; only diagnosable live. Fixes: route atomic ops through the runtime's NATIVE SDK (@cloudbase/node-sdk), re-read via the SAME SDK for read-after-write, and treat 'two SDKs for one platform' as a contract seam where each op must be proven in a deployed smoke, not assumed equivalent.
- **Bake release sha into artifact and assert it in deploy smoke** (`7f10674`, `4b9af54`, `09c9751`): A CloudBase deploy 'succeeded' while silently shipping STALE code. Hardening: (1) bake release identity (GITHUB_SHA + build time) into the bundle via tsup define, exposed through an unauthenticated health action, so post-deploy smoke asserts the RUNNING code is the code just built; (2) assertToolSucceeded on EVERY deploy-tool result instead of ignoring return values; (3) log local artifact size + sha256 before upload; (4) wait for Active between code update and config update.
- **Never destructively recreate on ambiguous deploy result** (`9346954`): A deploy script's handler for an AMBIGUOUS tool response (update returning no RequestId) must never take a destructive branch: the delete-then-recreate 'safety' path deleted the live admin function then failed to recreate it (P0), because the recreate depended on the same flaky tooling plus artifact-size limits. On ambiguity, continue non-destructively and let a post-deploy release smoke verify the live code SHA — verification belongs downstream, not in a destructive retry. Companion: keep function artifacts lean (minify, no sourcemaps, runtime files only).
- **Stateful function deploy guards wait active runtime lock redact argv** (`8df1440`, `de65427`, `a1f4b77`): Cloud-function deploys are stateful multi-step operations with three recurring footguns: (1) a config update issued while the function is 'Updating' fails — poll for Status=Active between code deploy and config update with a bounded timeout; (2) the function RUNTIME is creation-time locked — detect runtime drift against the manifest and fail loudly rather than delete/recreate a live function; (3) when a CLI takes credentials as argv, redact flag values before embedding the command line in thrown error messages (CI logs capture exception text). Bonus: log artifact size+sha256 before deploy so 'what actually shipped' is answerable from the run log.
- **Classify terminal errors inside polling loops to fail fast with last state** (`67f2176`, `c3a8024`): A deploy activation wait polled for 90s and reported only 'did not become active' when the real cause was expired credentials — a terminal condition no polling fixes. Pattern-match credential/auth failures inside the poll and throw immediately with the specific cause; make timeout/interval env-tunable; log summarized state every 30s; include the LAST observed state in the timeout error so the failure is diagnosable from CI logs alone.
- **Job to step secret scoping must sweep every consuming step** (`7d33d35`, `20c0e7b`): Moving secrets from job-level env to per-step env blocks has a silent failure mode: any step whose run script READS the var but didn't get its own env block now sees an empty string, not an error — here the 'verify deploy credentials' step itself failed on the first real run. Rule: when descoping env, grep the workflow for every $VAR usage in run scripts and give each consumer its own env block. Also: a green workflow_dispatch is not proof the push path works (dispatch died earlier on a branch-policy check).
- **Deploy concurrency group keyed to shared target not git ref** (`9a5af20`): GitHub Actions concurrency.group keyed on github.ref only serializes deploys from the SAME branch — two branches deploying to the same external environment still interleave and corrupt each other. Key the group to the deploy TARGET identity (cloudbase-deploy-${TCB_ENV_ID}) with cancel-in-progress: false so all writers to one environment queue. The mutex unit is the mutated resource, not the code source.
- **Additive hosting upload needs targeted prune plus 404 smoke** (`ca56f33`, `ff23345`): Static-hosting upload is additive: it overwrites files but never deletes remote files absent from the new build, so retired pages linger live on the CDN. Fix: an explicit commented legacy-paths prune list in the deploy script (targeted, NOT blanket delete — no dry-run safety net in CI), plus a deploy smoke asserting retired routes return 404 (a 200 means the prune regressed). Smoke expectations must track content retirement — the earlier smoke asserted 200 on those routes and 'passed' only because stale files hadn't been pruned yet.
- **Scan built site for server secret names before upload** (`a760e8b`): Between build and hosting upload, grep the client dist for the NAMES of server-only secrets — static-site builders will happily inline any env var a template references, and scanning for names catches the leak even when the secret isn't set in the build job (the reference itself is the bug). Cheap; maintain the name list alongside the deploy env block in the same file.
- **Serverless router must tolerate gateway prefix stripping** (`5734988`): CloudBase's HTTP gateway may strip the access-path prefix (/api) before invoking the function, so a router hard-matching the full public path works locally and 404s behind the gateway. Normalize: split into segments and drop a leading 'api' segment if present, then route on the remainder — accept both shapes and unit-test both. Generic for any FaaS behind an API gateway: never encode the gateway's mount point into the function's route table.

### Frontend Islands

- **Blob object url previews keep private storage private and must be revoked** (`490459d`, `f2063de`): Admin previews of unpublished images never weaken the public gate: persisted ids fetch bytes through an authenticated preview action (serving ONLY recognized-provider + status active rows), while just-uploaded files preview instantly from URL.createObjectURL(file). Object URLs are revoked when their id leaves the value list AND on unmount (via a ref mirror, since the unmount effect has [] deps) — long editing sessions otherwise leak blob memory.
- **Commit async list mutations against a latest value ref not render snapshots** (`f2063de`): A slow upload that commits [...value, id] from its render-time closure clobbers concurrent removes/reorders made while it was in flight. Fix: a valueRef always tracks the latest committed list, every mutation funnels through one commit(next) that updates the ref and notifies the parent together, async successes append to valueRef.current. Companion: per-file Pending state with retry, each success committing cumulatively so a later file's rejection never drops earlier successful uploads.
- **Local dev routes delegate to the production handler not a mirror** (`f2063de`): The local dev server's image route first re-implemented the production visibility gate inline ('mirrors getCatalogImage') — a parity that can silently drift and let dev render images production would 404. The fix imports and DELEGATES to the actual production handler, so legacy refCount, scan-fallback, placeholder, and fail-closed behavior are shared by construction: dev cannot mask prod because there is no second implementation to drift.

### E2E Testing

- **Env guard skips with explicit hasx helpers** (`2e2fadf`): All e2e env parsing lives in one frozen helper exposing explicit predicates (hasAdminCredentials(), hasBootstrapCredentials()) and tiered opt-in flags (E2E_ALLOW_MUTATION, E2E_ENABLE_BOOTSTRAP, E2E_MEDIA_UPLOAD_SMOKE, E2E_OEM_UPLOAD_SMOKE). Every destructive/credentialed suite opens with test.skip(!flag || !hasX(), 'Set VAR=... to run') so absent credentials skip cleanly with an actionable message — never fail, never half-run. Playwright artifacts (screenshot/trace/video) are off by default behind E2E_RECORD_ARTIFACTS so credential-bearing sessions are never recorded accidentally.
- **Run id prefixed records plus finally cleanup** (`2e2fadf`): Mutation suites never depend on seed data: each run creates records named with a unique run id, verifies user-visible behavior, and deletes everything in a finally block via removeIfPresent() tolerating NOT_FOUND (idempotent cleanup even after partial failure). Documented fallback: if cleanup fails, the run-id makes records findable in the vendor dashboard. Suites run serial so cleanup ordering is deterministic.
- **Opt in smoke skip flag only fail on missing creds** (`3733e84`, `6f304df`, `c4aaa8d`): For opt-in deployed-env smoke tests, `test.skip(!FLAG || !hasCreds())` is a false-green trap: CI sets the flag but a missing secret silently skips the suite and the run passes. Skip ONLY on absence of the opt-in flag; once the flag is set, missing credentials must THROW. Pair with wiring verification: a new spec file must be added to every CI invocation and npm script that names spec files explicitly — prove the fail path once before trusting the green.
- **Audit e2e assertions against real contracts vacuous pass** (`69f453b`, `7f3612e`): A dedicated audit of the e2e suite against real handlers and rendered DOM found two vacuous-pass bugs: a selector matching nothing (test passed only on an empty DB), and a privacy assertion hitting a route that doesn't exist (404 via catch-all — property asserted but never exercised). Recorded as a numbered findings table plus a 'Verified correct' list of every API/DOM contract the specs assume. A green e2e proves nothing unless its selectors and routes were verified against the actual contract.
- **Synthetic fixtures with real magic bytes sized to prove transport** (`9f5c6a1`): The deployed OEM upload smoke builds its fixture as a real ZIP magic signature plus incompressible random padding — satisfying server-side magic-byte sniffing and checksum recompute without a ZIP-writer dependency. Default size (2 MiB) is deliberately 20x the Event-Function body cap so a pass proves bytes went DIRECT to COS rather than through the function. Fixture size is an assertion about transport path, not an arbitrary constant — document the rationale inline.
- **Per page console capture and negative payload assertions** (`7f3612e`, `3ba3039`): The public smoke isolates console/pageerror capture per route (fresh page per path, labeled assertion naming the failing route) instead of one all-or-nothing listener across a multi-page loop — the aggregate version made any benign message on one page fail the whole pass with no attribution. The same suite asserts NEGATIVE payload contracts: role-gated and internal fields must be absent from anonymous catalog responses, treating the API projection allowlist — not the client-side gate — as the security boundary under test.

### Review Process & Knowledge

- **Numbered review rounds pinned to commit ranges in living doc** (`d910bfa`, `bd5b4b6`): Claude-Codex collaboration runs through review-round sections appended to a tracked doc: each round names the exact commit range under review, a verdict, a findings table (id/severity/cause-layer/fix), and the verification commands run. Each finding gets a per-finding disposition reply committed as its own docs commit, so the review conversation is greppable git history, not chat scrollback. The pattern catches pure policy drift (a working 7MB mp4 committed against the 'never bundled' media policy) even when behavior is fine.
- **Defer review finding as executable contract** (`d9f8225`, `1445dc2`): When a P1 review finding (missing factory video) couldn't be fixed (no source clip existed), it was resolved as an EXPLICIT deferral whose deferred state is itself contract-tested: comments record the deferral and an e2e asserts the poster renders and NO video element is emitted while src is empty. When the clip later shipped, the same assertion flipped to require the video. Deferral means 'the absence is a tested invariant with a one-line upgrade path', never a silent skip that can rot.
- **Settle disputed review verdicts against vendor contract not ui labels** (`d4100f1`): A contested review finding (does updateFunctionConfig merge or replace env?) had been dismissed based on a misread Chinese console label. Contract verification against the vendor's own docs reversed the verdict — the API REPLACES env by default — and the reversal, its evidence, and the guardrail were recorded, with scattered parallel review docs reconciled into one canonical gate. Disputes between review rounds get settled by live vendor-contract verification; the losing verdict's root cause is written down.
- **Isolated worktree review with seam verification table** (`b052682`, `27e5aeb`): A branch was reviewed in an isolated git worktree so the primary checkout could stay on a different branch for a concurrent session.
