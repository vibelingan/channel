# P7c6：在同一快照中完成当前热图准备

当前范围：减少旧图、文字编辑后的准备事务往返。没有调整公开 API、商品内容、分类、价格、图片引用计数、SDK 方法或超时上限。部署与现场耗时仍待执行，不能据本地通过认定性能达标。

旧 ready 报告只用于判断是否尝试此优化。图片集合相同且为 2–12 张时，先用 P7c5 的独立保留页提交 hold，再把原 bind/check/seal/attest/finish 逐项检查组合进同一受限原生事务。新的 ready 仍属于当前 job、输入摘要、内容代数和当前封印，不复制历史授权。更多图片、冷图、缺少凭证、超出预算等情形继续使用原有分段流程；12 是优化上限，不是产品或批量发布上限。

组合调用沿用 98 次文档操作、512KiB 单行、4MiB 总 JSON 预算。所有读取先于实际写入。缺图、过期凭证、超预算返回原路径前不提交任何已规划的前缀；SDK 写入异常或未确认回执使整笔原生事务回滚。保留记录必须事先真实提交，组合内部再次核对。没有跨请求缓存，也没有共享 image/counter 写入。

提交后回复丢失时，同一命令重试委托原 finish-preparation 的完成凭证重放；仍检查当前输入及原 lease 收据。发生独立编辑时拒绝重放。提交前异常重试也重新读取原生快照，没有沿用上次规划器。

局部证据：原生快照与故障组 36/36；真实 PNG + 原 handler/本地事务串联 14/14；独立 SHA-256 + JSON 路径验证空、Unicode、转义及 121 ID 的原 plan digest 完全一致。9 图组合实测 61 个文档操作。新增 4MiB 总预算反例纳入全仓回归，最终数量与构建部署结果另记。首轮 12 图测试因测试 ID 未按字典序排列失败；实际 worker 采用已排序集合，修正 fixture 顺序后通过，未修改或移除生产封印的排序检查。类型首轮发现新增测试的可空索引及过宽 fixture 参数，补明确断言和最小参数类型后完整工作区与 E2E 类型检查通过。

审查读取 jobs、worker、media-seal、finish、transaction-plan、protected-pixels、原 native CloudBase adapter 及新增 native/PNG 测试。Standards 检查原 SDK 事务回执、读取顺序、lease 每次异步后的复核、持久化字段边界；Spec 检查历史报告不授予新授权、失败回退、源变更/取消/响应丢失及不发布副作用。原生写失败、静默写、错误代码及错误 upsert ID 均保留状态整体相等断言。没有发现本轮尚未处理的 correctness 问题；现场性能尚未验证是主要剩余限制。

文字复核将“复用旧 ready”改为“旧报告只决定是否尝试，所有当前检查仍执行”，并逐项比较实际命令、原完成收据与故障日志，避免把优化提示写成授权复用。

原截图的同步验收：26 件新未发布草稿已通过正常产品列表逐件打开 Preview，26/26 能显示详情标题；没有点击 Prepare、修改分类、标记已审阅或发布。这证明详情可以打开，不把未展开的每张图片视为已完整加载。记录与最后一件截图在私有 output 的 original-run26-browser-preview-results.json / original-run26-last-preview.png；原 31 件业务字段前后差异仍按 P7c5 的独立快照证据记录。

全仓首轮在原同步浏览器用例失败：固定的 2026-10-21T00:00:00Z 超过服务当前时钟两分钟后，真实状态处理器会正确返回 queued；测试却继续要求 syncing。修正 fixture 的任务时间和访问/刷新凭证有效期为运行时相对时间，没有更改生产状态转换或放宽原断言。该真实 UI → 原 handler → 关闭页面 → 原 runner/原始存储/图片导入/自动 readiness → 重开 UI 用例独立重跑 1/1 通过：一次 start、响应丢失恢复、两件来源草稿均 ready/未发布/未强加分类、原手动商品不变、pageErrors=[]。全仓重新运行结果待补。
