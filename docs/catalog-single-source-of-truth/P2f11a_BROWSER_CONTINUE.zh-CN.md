# P2f11a：前端有界继续与恢复控制

在既有/api/admin协议和会话传输中增加catalogPreparation调用，使用一次请求，不沿用普通CRUD的BUSY写重试。严格解码安全progress/status/continue响应，绑定请求的商品、任务及动作，校验媒体计数、当前ready报告与seal。响应额外签名/nonce等字段、跨商品/任务、只有ready字样却缺完成证明均拒绝。直接API支持既有五个人工动作；控制器仅启动/查询/继续，不自动取消或重置。

runPreparation冻结本轮productId/jobId，逐个等待请求。首次从保存商品启动，或查询已有任务；只有服务端确认partial且followUp=continue才自动推进。未知结果仅查询一次，不重新发送继续请求；读到实际ready可恢复成功，仍queued保留人工继续，读不到则保留同任务并报告未确认。来源retryable不循环。UNAUTHORIZED/FORBIDDEN停止新请求，用户仍可保存任务ID并重新登录后查状态。

单轮最多64请求、120秒，等待租约只查状态，按600/1200/2400/2400毫秒最多四次；达到预算保留原任务暂停。浏览器取消或关闭等待只终止本地等待，不宣称远端取消。结合AbortSignal与现有30秒单次fetch上限，正常成功、异常、暂停均清理总预算计时器。onProgress提供可保存的任务标识/安全状态，当前单元没有新存储token、File或私有来源。刷新后的任务ID持久化、UI旧请求代次保护与操作按钮在后续界面单元接入。

先写行为测试，新增模块缺失时红测；之后26项通过，类型检查发现异步闭包更新状态后的TS收窄问题，改为读取实际恢复响应。独立反例检出调用期间选品对象变化会干扰结果，冻结标识后转绿。实际传输中止、默认轮询等待中止、未知start、动作响应匹配继续补测。控制器33项与真实HTTP+JSON+来源导入/像素串联2项，共35项在Node24和Node20通过。

真实组合测试通过浏览器API传输、现有admin HTTP适配器/session handler、真实JSON存储、默认worker和真实图片导入/像素链路。五来源按4+1两次继续到ready；最终HTTP响应丢失仅增加一次status读，恢复同任务。重新进入只读状态，五次导入不增加、文件不改写、分类misc与未发布保留，所有临时文件清理。网络层和DNS为受控测试输入，不代表实际云端权限或真实商品验收。

11个真实源码反例均检出，33项中保留29–32正控，原字节落盘备份并恢复校验。完整site662项通过，显式GALLERY_BROWSER_TEST=1执行既有真实无头浏览器图库测试，零跳过；local-server486项通过，共1148项零失败/跳过/取消。站点测试类型、Astro209文件检查零错误/警告（8个现有hint）、local-server类型、四文件显式Biome、SDK gate与diff检查通过。精确站点构建和审查随后追加。

失败记录保留：首次调用测试使用shell默认Node25，localStorage不是浏览器实现，后来隔离mock且指定Node24；partial夹具缺真实preparing报告已修正。最初HTTP组合夹具漏传真实handler，随后补齐；把浏览器测试临时放进local-server还带入DOM/import.meta.env类型，现移到site包，服务器配置未扩宽。迁移后的来源夹具内部复制了observation，直接改外部对象未生效，补显式更新实际存储observation后才确认五次导入与4+1断言通过。所有初次失败日志保留，不以HTTP200或单独截图代替链路断言。

本单元没有接显示组件、列表准入或发布操作，Preview入口行为不变。下一步把现有问题/预览/编辑中的状态和恢复入口接到该控制器，保留编辑内容并避免旧选择覆盖。发布意图、大媒体分阶段提交、历史修复、完整流程/性能/test真实20件发布恢复仍未结束，fullDeliveryReady=false。
