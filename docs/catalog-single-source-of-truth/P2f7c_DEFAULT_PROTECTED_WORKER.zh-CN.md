# P2f7c：默认 worker 的实际受控图片准备

目标：在已批准的准备链中，消费 P2f7b 的登记协议，实际复制来源对象到服务器受控目标、读回像素、原子切换。全部采用默认存储适配器和解码器。保留原对象和分类/发布状态；本单元依然不授予商品 ready。

先登记并持有同一图片锁，再按登记的原始摘要读取字节。内部读取只忽略本次登记拥有的锁，不忽略其他锁或元数据变化。beforeWrite 持久登记真实目标；读回时将该登记目标投影为临时读取记录，前后核对原始图片及锁拥有者，然后以真实读取的 health 提交目标。提交后再次走普通默认 health 读取。已提交目标重复准备不复制；已登记目标先读回，确认存在且正常则继续提交。未知 PUT/commit ACK 保留登记用于恢复，清理只释放自己的锁。

worker 记录 verified health 的新目标摘要；失败记录仍绑定实际检查的目标，不能沿用复制前的成功摘要或把失败挂到另一张替换图上。原 checkImage 测试接缝保持原只读检查语义。

检查：实际文件复制/原生解码/重开、重复无PUT、丢PUT确认、checkpoint失败零对象写入、丢commit确认、checkpoint后取消、源/目标损坏、图片被替换、释放失败；默认 worker 9图断点跨实例，观察与登记按kind分别断言，最后总计划保持完整。按实际结果继续补review反例；局部测试不是test部署或商品发布验收。


已实现并 review：默认 worker 调用 prepareStoredCatalogImage；测试接缝仍保持只读。begin 丢ACK后重读原始摘要并取得登记来清理自己的锁；commit 丢ACK后只接受当前同一已提交 marker。checkpoint 丢ACK时目标尚无字节，重试沿同一目标继续。不同返回目标、不一致真实目标字节、其他 owner 或原图替换均不能报告完成。

review 红测另修正目标失败归属：目标大小或SHA不符时返回 retry/unavailable，保留原始图片，不能把传输失败记为原图 invalid。只有经过相同SHA/大小检查后原生像素失败，才把原图内容记为 invalid。实际坏像素且准确SHA的默认worker仍记录 invalid/content。

测试共35小流程（新文件16、既有worker19）；10个实际源码故障全部检出，正控至少22/35，源码逐字节恢复。第一轮9故障运行于33项，未重算为最终证据。新测试包括checkpoint后取消、begin/PUT/checkpoint/commit丢ACK、零字节写入、释放false/throw、坏原始SHA、目标篡改、其他锁拥有者、原图地址替换、重复不再PUT、重开、完整9图片断点、105配置及丢失媒体一步ACK。105计划只处理4图，7次facade图片读取/图共28次、2个来源绑定批次，未扫描其余101图；这不等于总数据库RPC数。

性能边界：每张首次复制先读一次原图，再读目标作原生检查，提交后普通默认健康读回，总计3对象读取和2次解码。已保护目标复用对象，仍做一次默认健康检查；尚无跨商品像素缓存。worker仍是最多4图、20秒软预算，原有CloudBase PUT为60秒传输超时，外部操作可能超过软切片，旧租约提交会拒绝且登记可恢复。这些局部测试不能证明冷/热20件批次P95，后续性能门槛必须实测。最终商品封印、来源照片未绑定的自动导入、列表/操作/UI/修复和test现场验收继续，fullDeliveryReady=false。

实际文字复核两个生产模块、两个实际文件测试、此文与SDK记录；将“目标字节错误即原图损坏”修正为“复制目标异常可重试”，保留历史观察、图片准备、商品ready和发布之间的区别。首次类型检查发现闭包可变值不能自动缩窄，改用明确状态对象和局部摘要；没有类型断言压制。既有观察测试按kind选择，不依赖混存集合首行。
