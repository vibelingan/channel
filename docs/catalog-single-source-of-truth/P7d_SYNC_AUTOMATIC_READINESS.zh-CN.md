# P7d：同步后自动检查可用草稿

状态：实施中，未部署，不能作为已完成证据。

现状实测：原 10 月 20 日任务在来源和照片阶段已结束。该 run 当前仍绑定 31 个来源，其中 5 件已发布、26 件为未发布新草稿；31 件 readiness 均为 stale，照片 pending 均已清除。因此“同步完成”尚未覆盖网站候选和准备检查。历史原 614 件 unchecked 不等于本次新增 26 件。

本单元在原同步任务中加入 checks 阶段，复用现有准备任务、原签名、租约、版本校验和像素检查。仅扫描 lastSeenRunId 等于该任务的 active 来源，通过已存在的主来源绑定找到商品。已发布或已归档商品跳过；不新建商品，不发起供应商同步，不自动发布、不补分类、不改手工报价和照片选择。未分类草稿可检查和预览，发布资格仍由原分类规则决定。

任务保存发起管理员的 ID，每轮按当前用户角色校验；浏览器不能传入角色或能力。旧任务缺此 ID 时不猜管理员，通过原 Sync 点击由当前登录管理员恢复旧任务检查；该次点击不创建另一来源 run。定时器只接续已授权任务。一个来源的准备可跨多次定时执行；只在当前检查完成、明确需要处理或明确跳过后推进源游标。租约失效时不得推进游标。传输失败保留当前任务；重试有界，明确问题不阻塞其他来源。

当前来源任务仍有三件供应商图片 403/404，自动检查不能把外部缺图改为成功。检查与照片结果分别记录，最终以需要处理呈现；不恢复 continuing。原后台沿用 Sync、状态和 View products，不新增技术按钮。默认 normal 筛选开关的开启仍须单独完成历史检查与发布性能门槛。

验收：实际 JSON 适配器及原准备 worker 串联，覆盖正常草稿、缺分类、已有发布、归档、旧 run/主来源变更、撤权、编辑、重复定时、丢回复、重试上限与游标恢复；与现有同步和照片流程联测。再运行类型、SDK、构建、完整回归，部署到 test 后恢复原任务，独立检查 26 件可正常打开及原 487 件公开内容不变。

首轮新增实际准备小流程发现空字符串主分类被网站 header 校验误判为内容损坏。修复仅在私有网站投影中把空字符串和 null 视作未分类，与缺省字段一致，保留原记录；未知非空类别仍拒绝，正式发布仍要求有效分类。分类、保存、公开校验需在组合测试中一起确认。

## 本地实现、审查与测试

实际代码已接入 handler 的当前管理员 ID、run 的 requestedBy、持久 checks 游标及原定时入口。每个来源最多执行一个原 worker 步骤；单轮继续执行为原四页上限，并为最长 20 秒 worker 留出收尾预算。待运行、临时忙和明确问题分开处理。主动取消不会被自动 retry 复活；断线恢复 checks 阶段而不重启 photos；旧任务有图片错误时，Retry sync 会先重查照片，再继续 checks。

新增小流程先发现并修复了四个边界：空值分类误拦预览、异常恢复退回照片阶段、主动取消被当作可自动重试、瞬时 BUSY 被误报为数据问题。另用旧任务重试反例确认不能跳过真正的照片重查。对应红测和中间失败日志均保留在 p3e1/p7d-*，未放宽实际 worker、像素校验或租约预算。

同步模块最终 355/355、0 跳过；真实 Chromium 单击、丢开始回复、关闭页面、来源 runner、照片导入、原 worker、两件未分类新草稿 ready、重新打开页面的串联通过。原手工商品完整记录未变。全仓类型及 E2E 类型通过，SDK 合约通过，1097 文件 Biome 检查通过。第一次全仓 7884 项中 7881 通过、0 失败、3 项既有跳过；其后审查补充的 BUSY/照片重试分支已通过上述同步全模块复查，提交后的最终全仓结果另记，不能把早一轮冒称为最终提交的完整结果。
