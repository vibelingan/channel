# P4a1 普通上传完成与过期清理

本地子单元，基线0c01a98；整体发布修复未完成。先通过实际JSON数据库、磁盘图片和后台入口取得1正常/5失败，确认旧清理会删除已完成上传，重复完成会重复读取、成功后重试报冲突，其他上传者能完成别人的上传，删除响应丢失没有终态恢复记录。

| 状态 | 操作与写入保护 | 结果 |
| --- | --- | --- |
| pending | 同一现有图片互斥，持有后重新读取身份与目标 | 其他完成/清理返回BUSY，0字节读取 |
| pending且字节暂不可读 | 释放自身互斥 | 保留原intent，可直接重试完成 |
| pending且字节有效 | 原子核对uploader权限、目标指纹、owner、当前状态、引用数 | active与严格完成回执一起提交 |
| active且当前完成回执有效 | 读取确认结果 | 重复完成不重复下载或写入 |
| pending且字节不合规 | 持锁原子保存failed与拒绝记录 | 保留精确目标，后续受保护清理；不盲删 |
| 过期pending/failed | 写入层重新查当前状态、时间、来源标记、refCount和mutex | 先持久deleted/原目标intent再删字节 |
| deleted且intent有效 | 逐项删除、确认后移除记录 | 部分失败/响应丢失续原intent |

完成回执同时绑定原输入和实际输出；所绑定的目标、MIME、尺寸或checksum变化会使回执失效。真实尺寸取解码后的字节长度，忽略adapter尺寸提示的低报。格式、MIME与SHA沿既有规则；没有新增像素解码或以回执冒称当前COS健康。拒绝不补偿删除，避免迟到/未知写结果误删成功对象。

过期清理继续一个总limit，合并pending/failed与deleted两个排序前缀，报告只列确认删除。来源图片仍走P2d8b自己的租约状态机。旧缺uploader的行保留缺失，不伪造人类用户；缺上传者时写专用 image-deletion-ownerless-v1，禁止伪造上传者；原 image-deletion-v1 仍严格要求上传者，损坏旧v1不会借兼容通过。begin/abandon仍要求显式上传者身份。含新形态后旧严格读端不能降级；读端先更新并排空900秒旧Event写端，才能启用新写端。
