# P5a：历史商品只读审计

这一单元提供可断点恢复的影子报告，用于检查历史商品数量、准备状态与查询投影。它不发布商品，不写回准备结果，也不更改分类、来源、价格、审批内容或图片计数。正常列表仍默认显示全部检查状态，尚未启用隐藏历史未检查商品的行为。

`scripts/catalog-readiness-audit.mjs` 复用管理员 me、products list/get、现有列表 DTO 与完整准备报告校验。必须明确指定 API origin，并使用环境变量 CHANNEL_ADMIN_TOKEN；凭证不写入报告或命令参数。只允许产品读取，拒绝写入和其他集合，认证请求禁止重定向。HTTP helper 的默认 follow 保留，原调用者的正向重定向回归通过。

每页 100 件，按 _id 升序 keyset 遍历，直到空尾页；不以可能过时的 total 或短页结束。每页最多四个完整读取，全部成功后才保存断点；任一读取失败，等待已启动读取结束，保留上一整页。第二遍从头重新读取，比较完整商品哈希和业务字段哈希；发现新增、删除或内容变化时标为 changed。两遍一致仅说明本次非事务扫描一致，不能作为发布授权，也不能保证扫描后的数据不变化。完成或 changed 的报告再次执行时要求新文件，不把历史结果充当当前快照。

状态复用完整准备合约，并与已有 native 查询谓词比较；损坏回执单独计数，不能仅凭 ready 字符串放行。分类复用 productFamilyForDoc，保留旧耳机 category 字段的兼容性，明确 productFamily:null 不被旧字段反向补齐。报告只保存 ID、哈希与状态摘要，不保存商品正文或凭证。

文件上限 32 MiB、每遍最多 100000 行，JSON 深度上限 64；单次完整 HTTP 响应限制 5 MiB、20 秒。文件为当前用户独占的普通文件，0600、单硬链接、拒绝符号链接；协作锁为 0700。新断点先完成序列化，再以独占临时文件写入和 sync，确认原文件未被外部改写后原子 rename。达到容量、身份/策略不一致、DTO 或顺序错误时停止，不报告完成。锁被替换时拒绝代为清理；中断后的锁需先确认原进程已退出再人工处理。

执行方式：使用项目 Node 运行 `node --experimental-strip-types scripts/catalog-readiness-audit.mjs audit /private/report.json https://API-ORIGIN`，凭证由当前 shell 的 CHANNEL_ADMIN_TOKEN 提供。相同身份、origin 和策略下使用 resume-audit 继续未完成报告。命令退出码 0 为两遍一致，2 为 changed，1 为读取/校验/断点错误。该工具要求部署端支持当前有界列表协议；旧端返回不匹配时拒绝继续，不降级到无界扫描。

本地证据位于 output/pricing-clock-repair-2026-10-13/p3e1/readiness-audit-*。最终部署契约 504/504，零失败和跳过；覆盖 205 行、过时总数、空集合、断点重启、游标之前插入/删除/编辑、身份与哈希不符、错误 DTO、完整读取失败、四并发排空、私有文件与外部改写、禁止认证重定向，以及原 HTTP helper 的正向行为。旧 category 红测先失败，使用共同分类函数后通过。临时破坏第二遍扫描和重定向防护均被测试检出，随后源码按哈希恢复。
