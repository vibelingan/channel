# P2f9c4：默认准备流程走到就绪

签名函数 main 的默认 worker 现在依次完成来源导入、实际图片保护/像素检查、有界逐张核对和当前候选原子就绪提交。明确命名的媒体子流程仍可单独检查其阶段行为；两者共用原签名 admission、claim、租约、预算、错误投影和 release 逻辑。普通调用不能传参数关闭默认流程的最终校验。

媒体全部验证后，同一 invocation 最多核对四张图片。核对使用当前占用/目标/已保护像素回执，不再读字节或复制对象，沿用 20 秒软预算与 8 秒尾段预留。部分摘要持久保存；重启后新 owner 接着核对。完整摘要后再读取完整候选，对照输入、图片集合根与数量，调用 P2f9c3 的原子提交。最终响应未知时仅以原 grant/原命令再确认一次；确认 ready 后不再 release 已完成租约。

实际 9 张图的五次 invocation：像素 cursor 为 4/8/9/9/9，核对 cursor 为 0/0/4/8/9；第三次后重开文件和 authority，禁用对象 GET/PUT，仍继续完成。实际 105 张独立配置图共 53 次有界 invocation 自动走完，保留分类和未发布状态；这是本地行为证据，不是云端吞吐或界面响应时间。

测试覆盖默认 3 图与缺分类、0 图、非受控注入像素不能伪造 ready、核对预算、核对 ACK 丢失、最终 ACK 丢失只读确认、核对前后/最后提交前取消、提交前用户编辑。采用来源绑定在最后核对之后被替换，必须拒绝旧图片集合；显式 retry 清掉旧计划后能准备当前集合。实际 alibaba main 也检查 ready 报告和 completed job。

七个源码反例覆盖核对数量、预算、最终候选重读、最终 ACK 恢复、完成后错误 release、默认模式与实际签名入口接线；每项都有失败，其他正控保留，原 worker/入口源码字节恢复。反例使用明确选定的 13 个测试，不把过滤掉的测试当成通过；之后完整包回归不带过滤。

本单元尚未提供完整的人类操作恢复、重复已完成 dispatch 的只读确认、blocked/preparing 报告及 UI、normal/issues/preparing 准入、历史 repair/resync、大批媒体 staged commit 或 test 现场验收。部署前这些仍是门槛，fullDeliveryReady=false。

文案核对 worker、既有媒体协议测试、新默认流程测试及实际 main；将“20 秒硬上限”写为“软预算与尾段预留”，保留网络与单次事务可能跨过检查时刻的边界。核对 4 张上限、9 图五步、105 图 53 步和未发布断言均对照实际日志。首次 formatter 发现测试未标注的结果变量，补具体类型后重跑，没有 any 绕过。
