# P2d7：可恢复的图片删除

本单元修复“文件已删、图片记录仍 active”和删除未确认却报成功。属于完整发布方案的媒体基础层，未替代来源绑定封存、上传回执、历史修复或 test 验收。

删除意图保存在原有 images 行，最多两个永久文件标识；没有新增存储集合，没有复制图片内容。继续使用 imageMutationOwner/imageMutationStartedAt 这一把图片锁。

| 当前状态 | 操作 | 持久化结果 |
|---|---|---|
| active，上传者匹配，引用计数 0，持有当前锁，完整引用扫描通过 | begin | 同一事务设 deleted，并记录服务端删除意图；之后才允许删除字节 |
| active，但被引用、锁不属于调用方、或尚未完成上传 | begin | 拒绝；文件和记录保留 |
| deleted，原删除意图完整，上传者、文件标识、provider 和引用计数仍匹配 | begin/retry | 返回原操作与原目标；不重开 active、不等待崩溃留下的锁过期 |
| deleted，匹配原操作且所有文件已确认删除 | finish | 同一事务确认删除行；零条删除 ACK 不算成功 |
| deleted，但意图损坏或文件身份改变 | retry/finish | 不删新目标，保留记录，进入后续修复流程 |
| 行已不存在 | retry | 后台 abandonUpload 保留幂等成功；来源候选删除保留原 not-found 契约 |

每次首次删除先检查 unfinished approval，再检查所有注册引用。审批恰在两次检查之间完成时，产品引用已写入；审批仍须拒绝图片锁或 deleted 状态；快照读不构成序列化证明，完整媒体引用封存与审批写入围栏继续由后续 P2/P3 验证。重复删除允许重入同一个终态操作；字节删除要求存储适配器确认成功或确认不存在。finish 绑定原 operationId，不能删除换过目标的记录。

| 并发组合 | 保护与验证 |
|---|---|
| 首次删除 / 保存图片引用 | 原有资源锁；删除后的新引用被拒绝，已保存引用阻止删除 |
| 首次删除 / 审批完成 | jobs-first + reference scan；保留既有 DEC-21 交错回归 |
| 首次删除 / 旧图片迁移 | 迁移先持同一图片锁并重读；已 deleted 的图片不迁移；真实本地串联测试 |
| 已隔离删除 / 重试删除 | 同一原意图可重复删；竞争 finalizer 的确认缺失通过读回判断，不复活图片 |
| begin/finish / 数据库提交响应丢失 | 读回持久状态；读回失败不进行未获授权的字节删除，不把未知状态当成功 |
| primary 已删 / migration 文件删除失败 | 两个原目标仍在持久意图中；重启适配器后继续，无需数据库手工改状态 |
| quarantine / 后台旧 base64 预览 | deleted 在 legacy 回退前被拒绝；真实迁移行回归先红后绿 |

文件标识属于存储接口的不透明值，逐字保留编码、大小写和空格。原 2,048 字符试行限制会误拒编码后的合法对象键，已用反例改为 8,192；图片来源 URL 与上传限制没有改变。真实文件名末尾空格的反例还证明 trim 会删错目标并谎报完成，现在删除意图和存储调用都保持原值。

前台传 imageId，上传者来自已验证的会话；来源删除仍只接受固定来源上传者。generic image CRUD 的 strict schema 无法写入删除意图、状态或文件标识。数据库事务不调用存储服务，单次 begin/finish 最多两个文档操作。

上线门槛仍包括：实际云存储重复删除/确认不存在的 owned probe；新 reader 和迁移 writer 先部署并按实际函数超时排空旧实例，再启用或调用新删除路径；service authority、媒体来源绑定和报告封存；正常/错误/准备列表与恢复 UI；导入及迁移上传的未知提交回执；大媒体计数协议、历史审计、全部 test 流程与真实三件时钟和 20 件发布后恢复。该单元不把本地数据库或文件测试写成云上已验收。
