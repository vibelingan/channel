# P2f11b：现有预览中的准备与恢复入口

AdminDetailPreview的正常、加载和错误分支接入同一准备控件。首次打开只读预览和浏览器中的任务定位记录，不启动准备或写商品。管理员明确点击后可以准备、查询、继续、停止本地等待、取消未完成任务或显式重试；坏详情仍保留原有Edit入口。ready后仅重新读取保存预览，分类、批准、发布意图都未由控件写入。

任务定位仅在sessionStorage保存schemaVersion/productId/jobId，以actor和product双重命名空间隔离，不存token、来源、报告、File或blob。记录严格有界解码，损坏、错商品、额外字段不授予状态；存储不可用时保留内存中的任务并提示恢复限制。同用户交替两件商品不会覆盖另一件任务。前端定位不是授权，服务端仍验证当前角色和输入。

每次动作在首次await之前占用同步ref，异步状态、任务记录与ready回调都核对当前controller、挂载和actor。切换商品/用户、关闭或停止等待会中止本地等待并忽略旧结果；重新登录保留同用户任务并恢复按钮。仅认证事件及channel.token/channel.user存储变化重置控件，无关偏好变化不会中断准备。新请求再次核对当前actor；手工查询/取消/重试同样校验固定product和job，错指记录只读恢复且提供Check current product，不对另一件商品执行动作。

取消和重试先查询新鲜状态与leaseVersion，已完成不取消；结果不明不重发写入，只读恢复，未确认时不显示取消或重试成功。停止等待不发送cancel。分类缺失可以准备内容，ready提示发布仍检查分类与权限。删除准备照片的提示改为先在商品照片选择中移除/替换并保存，未弱化图片保护。既有RecordForm实际加载/子面板恢复与服务端旧删除提示仍在P4继续，当前仅验证预览错误页的raw Edit回调。

真实无头浏览器在StrictMode与390px视口下检查只读首屏、双击、partial到ready、重新打开定位、正常取消/重试、未确认取消/重试、同用户重新登录、错商品拒绝及直接恢复、商品切换后晚到结果、停止等待零取消、actor隔离、无关storage连续性、贡献者控件隐藏及实际AdminDetailPreview错误时编辑入口。SSR不访问浏览器存储；十一项定位记录测试覆盖严格字段、键边界、存储故障与双商品交替。共13项本单元测试通过。

本地真实HTTP/JSON/来源4+1/原生像素组合继续保留。完整site675项通过，显式启用既有图库浏览器测试，本单元浏览器测试也实际执行，零失败/跳过/取消。Node20五文件48项、Astro212文件零错误/警告（8个既有hint）、七文件显式Biome、SDK gate与diff检查通过。故障组后仅把一条照片提示中的binding改为photo selection，formatter逐字对比证明无功能变化，随后13项再通过；精确构建随后在审查记录追加。

14个实际源码反例最终全部检出，13项中保留9–12正控，恢复字节并留哈希。首次故障组在product-namespace反例未检出而主动失败，补同用户交替双商品用例后最终检出；不能把第一次绿灯作为覆盖完成。最终故障脚本先因格式化后的定位串不匹配失败，未修改源码；更正并用独立备份重跑。最终组要求真实断言失败，拒绝语法错误或整项测试超时作证据。

实现中三项真实浏览器红测先检出再修复：同用户重新登录按钮仍禁用、手工状态未绑定商品、无关storage事件错误中断等待。初次SSR测试从repo根运行使用了错误JSX配置，改由site配置运行；a11y检查要求原生output已修正。浏览器元素与异步Route夹具做真实类型收窄。实际预览依赖Astro的Markdown文案，隔离Vite宿主增加真实frontmatter转换并按完整入口扫描CommonJS依赖；未修改生产文案/打包规则。宿主最初清理顺序卡住，已核对cwd/命令后仅终止自有测试父进程，改为先关浏览器再关Vite；后续失败、故障组与最终回归正常退出，临时缓存均清理。首次copy-audit写入未提权遭OS拒绝，确认未改源码后在已授权checkout重跑记录。所有失败日志保留。
