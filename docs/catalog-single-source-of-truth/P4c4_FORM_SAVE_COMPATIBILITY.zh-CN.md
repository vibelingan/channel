# P4c4：原编辑表单的保存约定

把实际 `coerceValues` 输出交给 P4c3 控制器后，发现表单的 `archived:false` 会被严格 Root 输入拒绝。控制器现在只在确认商品未发布、未归档且请求没有开启这两个状态时移除这两个字段；保存草稿不会夹带归档或发布动作。

另补原 Admin 的明确清价命令：操作输入允许 `manualCatalogPricing:null`，原 Root 仍保留这个命令及其 digest。只有已通过原生绑定保存检查的 update，在共有保存计划中将其转换成原 Admin 已使用的空字符串。原 create 入口、错误价格类型、身份、分类、图片和供应商决定的门槛保留。继承供应商价格不清掉保存着的手工价格。

新增四条实际 RecordForm 转换→默认客户端→实际 Admin/临时 JSON 的正向组合：普通保存、合法清价、修改阶梯、链接商品恢复继承；另有两条拒绝及停止恢复，保护手工模式缺价格和无来源商品强选继承的旧规则。共有保存计划另验证与旧清价结果一致、参数不被修改和过期版本被拒。没有以放宽价格验证来接受错误操作。

初始四条正向组合失败，移除无变化生命周期字段后，普通保存/阶梯编辑通过。两条初始价格夹具不符合旧规则：清空价格却保留强制手工模式、给无来源商品选择继承。正向夹具已按实际合法状态纠正，并将这两个错误输入保留为负向控制；不能将它们称作旧功能缺陷。类型检查指出 registry shape 可能缺字段和测试可选时间字段，改用已有共享价格 schema、明确 nullable 时间，没有断言绕过。

本单元的最终 Node20 367 项、DB 2255 项、Admin 638 项、DB/site 测试类型、五文件 Biome、SDK gate 及 Admin node20 target 构建记录在 `draft-form-compat-*`。构建产物和源 SHA 另存验证 JSON。这是表单接线前的兼容修复；RecordForm 接线、媒体和 live 编辑尚未完成。未部署或更改真实商品，`fullDeliveryReady=false`。
