# P2d8b 来源图片复制、绑定和中断恢复

本地子单元，基线32b935a，整体发布修复仍在实施。使用现有 images、catalogSourceLinks 和图片互斥；没有新集合、全局锁或第二套图片锁。

导入先原子保存待上传图片与每个URL的操作归属，再下载。存储适配器取得永久目标后，必须先确认该目标的数据库检查点，才写字节。120秒归属租约内至少保留完整60秒PUT窗口；数据库确认迟到则不开始上传。上传结束后在同一事务中激活图片和绑定URL。未知数据库响应只重放同一操作一次；未知上传结果保留精确目标，不执行可能误删成功文件的补偿删除。重试失败复制使用新目标，已有注册绑定可复用。

校验和复用先按active状态过滤，再限一行；持有现有图片互斥，在事务里实际写同一图片行，防止仅快照读到active而并发退休已完成。unused pending行与URL绑定一并提交。来源失败记录由同一状态机写入，重复结果不多加尝试次数，迟到失败不盖过成功或正在进行的操作。BUSY不是永久图片失败，也不消耗下载进展预算。

清理先核对当前图片身份、归属、租约与互斥，并持久化deleted及原目标清单，才删外部字节。部分删除、进程重启、响应丢失继续原intent。后台将待清理和已退休服务图片两个有界排序前缀合并，遵守一个总limit；报告只列已确认删除的文件。旧非来源上传的cleanup路径仍待后续单元处理，不以本单元替代整个上传生命周期修复。
