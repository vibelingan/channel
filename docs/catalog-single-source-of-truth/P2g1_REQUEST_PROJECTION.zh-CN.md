# P2g1：开始检查时的商品状态投影

任务开始原来只写私有任务行。首次检查点之前、以及重试之后，商品列表无法通过自身字段查到这些请求。本单元在原事务中同步写入有界的 catalogPreparationRequest，并将商品状态设为 checking。请求只含商品/任务身份、输入摘要、内容代次、策略与请求时间；没有签名、nonce、worker owner、来源正文或媒体数据。checking 表示已请求检查，不表示后台正在运行，也不授予预览或发布资格。120000ms 是 worker 租约时间，不是任务过期时间。

同输入再次开始直接返回同一任务，当前请求存在时零新增写入；旧活跃任务缺请求时，显式开始可补齐，但不覆盖当前有效 preparing/blocked 检查点。取消只使自己的当前请求或匹配非就绪检查点失效，旧任务晚到取消不能清除新代次请求。显式重试原子写回 checking 和新的请求时间。内容编辑保留有界历史字段并使其失效；通用更新不能伪造该受管字段。分类、发布、批准内容、价格、时间戳和业务版本计数均保持原值。

独立检查：原生 CloudBase 事务包装器实际测量手工商品开始5操作、来源商品8操作，所有读发生在写之前。商品/任务两个写点分别注入抛错、静默失败、错误代码和错误upsert ID，8类均回滚整对记录；提交后丢ACK，同输入再次开始读回原对且不重复写入。实际JSON适配器经过关闭/重开、取消和重试，分类/发布及旧记录缺失的代次字段保持。公开API有非空名称正控，四个准备诊断字段均不泄露。

先保留红测41通过/5失败，再实现和扩大回归。初次扩大测试的22处差异逐一核对为新增受管元数据或重试状态变化：在开始之后捕获整行基线；允许的输出键在两侧同时剔除，并单独断言新请求；其他业务字段仍完整比较。错误的重复文本定位脚本未执行写入；函数调用代码未检查该退出值，随后启动了旧断言回归，日志保留且不计最终通过。后续每个依赖操作均检查前一步退出值。
