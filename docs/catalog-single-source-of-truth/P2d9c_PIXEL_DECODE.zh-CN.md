# P2d9c：图片像素校验与原生运行时验证

本单元提供独立的 decodeCatalogImagePixels，不写商品、来源、分类、图片记录或发布状态，也不生成准备完成或发布授权。生产准入和应用打包尚未接线，fullDeliveryReady=false。属性容量及完整来源数据保持前面已确认的方案，未添加属性筛选、同名合并或拆分业务存储。

## 输入、结果和恢复

复用 shared 的四种网站图片 MIME 和10MiB字节上限。先复制输入，核对文件结构、动画帧数/序号和PNG CRC，再由精确固定的sharp0.35.5检查实际像素。检查包括GIF、WebP动画，以及原生PNG解码器只读取海报时会漏掉的APNG后续帧；APNG保留局部帧、透明调色板及独立海报。原始图片不改写，每帧仅产生小的临时输出。

结果区分 decoded、invalid、retry；decoded绑定原始字节SHA、画布尺寸和帧数。它还没有绑定当前图片记录、存储目标或商品版本，不能直接存为ready。资源读取和解码库暂不可用时可重试，内容失败与大小失败有受控原因，响应不带原生异常或私有路径。

异步调用使用至多5000ms总预算，原生处理额外设置2秒超时；输入复制、结构检查和hash已耗去的时间从同一预算扣除。过期后不再启动原生工作，晚到结果不返回decoded。同步CPU工作无法被计时器抢占，原生超时不包含libuv排队；destroy不被当成已运行C++工作的硬取消。真实云端4,202,201字节PNG的1ms预算反例在490ms时返回timeout，解码器调用数为零。这验证了不继续启动工作，不能写成1ms墙钟硬截止。

默认像素上限沿sharp的268402689；这不是进程内存保证。本轮小样本的约37MiB峰值不能替代最大合法图片、原生并发、持久准备任务及P6性能验收。接入生产前仍须完成这些预算和恢复检查。

## 实际发现的问题

已有GIF解码器会容忍截断并返回首帧；原生PNG读取会忽略APNG后续坏帧。现在通过完整结构与逐帧像素校验补齐，正常动画与损坏动画都有对照。截止预算红测还发现同步检查已耗尽时限后仍启动原生解码，已经修复；晚到加载也有实际调用次数断言。

Linux依赖使用lockfile固定的sharp-linux-x64@0.35.5及sharp-libvips-linux-x64@1.3.4，归档SHA-512核对通过。官方MCP2.35.2的依赖声明固定manager-node5.8.8；对应发布源码与现场运行对照揭示两个部署条件：父目录与函数同名时MCP会向上调整路径；Event函数又被强制在线安装，manager会额外过滤根node_modules，普通ignore不能关闭。移除package.json也不会关闭Event在线安装；这次尝试没有算成功。

最终独立探针采用Node20标准package imports绑定 #catalog-image-decoder，源码包解析至已安装sharp；部署包解析至vendor/image-decoder.mjs，再加载vendor/node_modules中的固定依赖。完整原生依赖随代码包上传，解码时不下载、不解压、不依赖在线安装重新选版本。这一布局已由真实Linux探针验证；应用tsup、package-functions及裸目录smoke仍需在下一接线单元实施。

## P2d9c1：精确review发现的合法空数据边界

48d062c的精确review对照[PNG3推荐标准fdAT](https://www.w3.org/TR/png-3/#11fdAT)，发现length<5误拒合法的4字节序号加空frame_data。原37项补充基线只有这条合法输入失败，其余36项对照通过；改为length<4后37项全部通过。有效空IDAT/fdAT后接像素数据可解码；整个帧只有空数据、fdAT短于4字节仍拒绝，且不会抛范围异常。首轮候选未获review blessing。

修订后全量254文件3452项/0fail/skip/cancel，80.45秒；Node20组合176项/0fail/skip，类型和4文件Biome通过。18种源码缺陷由同一37项基线全部检出，正控22–36，零跳过/取消；恢复后17文件hash与修订全量冻结记录一致。三件时钟冻结副本的57张实际图片再由当前默认解码器通过，逐件byteSize/SHA一致；这是本机Node20只读回放，不冒充当前云对象快照。

修订后的同一默认加载器在Linux/Node20.19.3通过21项云验证，新增合法空数据、整帧无像素和短序号三例。1ms人工预算的4MB PNG返回timeout、原生调用0，实际耗195ms；同步CPU不能被计时器抢占。该轮临时函数已删除并读回确认，仅原三应用函数，累计5轮有效临时创建及7失败记录清理完。显式临时代码对象仍保持已删除状态。结果分别保存为pixel-revision1-*，不覆盖首轮34/3449/18证据。应用打包/生产准入及完整任务仍未完成。
