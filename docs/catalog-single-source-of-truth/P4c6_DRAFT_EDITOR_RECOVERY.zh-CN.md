# P4c6：在实际编辑表单接入原保存恢复

管理员从 CollectionView 打开未发布商品，保存使用已有 save-draft Root。已确认关闭时核对回执与当前商品；不确定时保留同一表单和指针，提供 Check / Continue / Stop。没有把保存变成发布，也不补分类。非管理员、其他集合、能力明确关闭时的旧入口保留；完整表单 Publish、live 保存、归档/下架仍按后续单元处理，不能据此称为全部接线完成。

恢复期间按既有 RecordForm 的 readOnlyReason 约定只读，防止把不同编辑提交到未完成的任务。停止一个未写入商品的原任务后，检查当前版本未变，点 Keep editing this draft 可以保留原输入继续编辑。停止已经保存的任务保留该次商品修改。历史回执只供确认，不覆盖之后的独立编辑。

打开已保存版本前，用户先下载当前表单。下载包含最新的供应商选择、配置图片和表单值，不含 JWT；数据只在内存和用户选择的下载文件中。下载后的表单如果发生变化，不能拿旧下载确认替换。RecordForm 使用最新值 ref，供异步恢复前后比对；任务待处理时 Close/Discard 在候选图片清理之前拦住。正常编辑的浏览器离开提示由 protectEdits 控制，其他 RecordForm 默认保持原行为。

会话变化后暂停原控制器；重新验证原 actor 和 endpoint 后，可显式重新连接，表单不重建。此单元覆盖编辑组件内的重连，AdminApp 全局过期会话处理仍须后续修复和验收。原发布任务未完成时提供现有 ProductPublicationRecovery，解决后须重新打开当前商品，避免继续使用旧 initial。

实际浏览器沿坏 Preview → 打开原始商品 → 供应商/图片独立 Retry → 编辑 → 原生保存。保留原 16 项媒体/异步子流程断言，并把最终保存从一次通用 update 改为实际 start/save + saved Root/当前版本/照片清理验证；不是只检查按钮文字。新增已提交回复丢失、回复及确认同时失效、未到达 start 的停止/继续编辑、后续独立编辑、同账号重连及其他 actor 拒绝、照片清理失败继续和停止。

第一版新增两条用例试图在恢复只读期间填写字段而失败；这不符合本单元约定，已改为检查只读与原输入保留，并在确认停止后编辑；历史回执用真实独立 update 产生新版本，检查不会重写。未放宽回执、分类、媒体、版本和权限规则。最初测试类型指出 Vite 浏览器绝对模块路径不能用作 Node 静态解析，改为由 page.evaluate 参数传入，与已有宿主加载方式一致。

验证和完整组合结果以实施日志及 draft-editor-* 为准。本单元没有部署或修改真实商品，fullDeliveryReady=false。
