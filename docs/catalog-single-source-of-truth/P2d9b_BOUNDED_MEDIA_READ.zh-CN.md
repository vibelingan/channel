# P2d9b：有界读取与上传失败恢复

本单元把实际存储读取接入总时限和流式字节上限，补普通上传完成时的超大文件处理。应用函数尚未部署；没有修改商品、分类、发布状态、来源或业务图片。云端只先后创建和删除了同一个自有临时 SDK 探针，两轮均已读回确认函数不存在。

## 行为和边界

MediaStorageAdapter.getObjectAsBase64 增加可选读取限制。普通上传完成及存储字节检查现在明确传入 10MiB 和 5000ms。旧调用不带限制时保持原路径；本单元不证明其余媒体接口或 10MiB 图片的浏览器交付已全部修好。

读取开始即固定限制，不能被异步期间对 options 的改写放大。来源初始化、URL 获取和完整响应都在同一个 Promise 总时限内；逐块累计实际字节，超限立即关闭来源。仅复制已经接纳的字节，不保留借用 buffer 的可变内容。10MiB 是接纳的文件字节上限，不是整个进程的内存上限；base64、复制和其他并发仍占内存。

CloudBase 有界分支向真实 node-sdk 3.17.2 请求带 COS_URL 的临时链接，严格核对唯一回包、SUCCESS 和原 fileId，再发原始 GET，只接受 HTTP200。签名链接只留在服务端内存，不返回业务 API 或写入证据。HTTPS、userinfo、fragment 和重定向检查保持明确。内部 storage.downloadFile 的 COS_URL 分支是发送方对照，不据此宣称公共 app.downloadFile 的所有包装层都转发相同参数。

总时限中止当前 HTTP 读取，晚到 SDK 元数据不能再启动 GET。SDK 元数据请求没有在这里增加 AbortSignal 契约，不声称它被硬取消。真实云端负控中，读取调用在 2ms 返回 timeout，SDK 在 145ms 时已结束，后续 HTTP GET 数为零。

普通上传的真实对象一旦超过上限，先在原图片锁内持久化拒绝，再释放锁，保留目标给现有过期清理；不盲目删文件。旧 active 上传复核失败沿原规则保留已公开状态和引用数，并给替换图片的入口。新提示改为用户可执行的“稍等并重试上传”，删除 completeUpload/PUT 这类内部术语。暂时读取失败仍允许原上传重试，已确认完成的回执不重复读文件。

该模块仍只提供字节证据，不是像素证明或发布授权。服务端健康封印、列表准入、持续修复、统一发布操作及其他媒体交付流程继续按总方案实施。

## 实际发现并修正的问题

- 真实 HTTP 响应揭示 Node 的 NativeSignal 单独取消路径会在已完成响应的 Socket 上触发无人处理的 AbortError。独立事件监测确认发出者是 Socket，不能靠给 response 加监听解决。改为显式关闭当前请求/响应，并保护已经交还连接池的 socket。
- 本地磁盘集成揭示 CJS/ESM 两份包实例的 Error class 不能用 instanceof 自有类互认。改用受控的全局 Symbol 品牌和受限原因；真实超大文件现在得到 VALIDATION_ERROR，不再误报找不到。
- 反例证明可变 options 能在读取途中放大上限。捕获初始数值，并增加借用 buffer、字符串 chunk 和晚到数据测试。
- 新流式超限分支有独立的持锁等待测试，直接观察 reject 尚未进入实际写入时 release 尚未被调用，避免本地 DB queue 掩盖提前 finally。

首次单独重新加入 NativeSignal 的变体仍受显式关闭路径保护，139 测试前的 136 项全部通过，不把它算作缺陷检出。恢复已复现的“NativeSignal 单独取消”旧设计后，真实 HTTP 测试确实失败。首次故障脚本在该绿变体处停止、恢复源码；最终按更新后的 139 项分母重新执行 23 种实际缺陷，全部检出。
