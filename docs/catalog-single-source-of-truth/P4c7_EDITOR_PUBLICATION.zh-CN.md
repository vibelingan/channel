# P4c7：完整编辑表单的原任务发布

本单元接管理员未发布商品的完整表单 Publish，复用现有 product-operation publish 和服务端照片申请/清理/审批/最终回执；不先调用通用 update，再另建发布任务。冻结产品 ID、打开版本及完整可写 patch 后才进行能力/账号检查。已有主/子分类按表单真实值保留，缺主分类直接提示选择，不补分类。

共有保存后发布入口继续支持创建后的空 patch：原行为、原错误含义和旧两参数调用保持；非空编辑 patch 不会持久化成可重放的空 patch，也不会在尚未确认保存时提示“已保存”。后台返回的字段 issues 保留到表单。

恢复期间保存/关闭受原任务约束。明确停止且从未保存商品、当前商品版本仍是打开版本时，可以继续原表单输入；已经保存或已有其他版本，则下载当前编辑后显式打开最新商品。完成发布只读确认，不以旧任务再次上线。候选图清理在已解决任务之后、换表单之前进行。

先验：正常完整保存发布、冻结输入、原 start/continue 回复丢失、公开/私有读回失败、未到达 start 刷新后停止、保存前拒绝后保留编辑、保存后审批失败、来源/分类/并发下架及账号变化；每个完成对象按其回执下架并核对匿名详情和图片引用。创建、分类、表格、草稿、媒体、价格/供应商决策的旧组合继续回归。

已发布商品 Save 的 refresh-live 另沿下一步确认：仍公开旧批准版本，保存候选编辑不下架，最终只替换本次批准版本；并发下架/归档后原任务不得重新发布。不得简单放宽 publish 的 draft 门槛代替这个生命周期规则。归档/下架及全局会话后续门槛保留。本单元没有部署或真实商品变更。


## 实现和验证

ProductEditForm 的管理员草稿 Publish 已接完整原任务。表单的 ID、打开版本和嵌套输入在首次等待前冻结；字段错误回到原表单。未选择供应商新描述的情况仍被阻止，提示明确指出 Keep website version / Use Alibaba's，不放宽审批规则。

故障测试复现并修复了另一个恢复缺口：匿名详情确认后，batch 已移除恢复指针，随后的私有商品读取若失败，重新登录就会失去原任务。现在重新保留同一任务的指针，继续保护输入；指针不含表单正文或 JWT。真实浏览器覆盖重新登录后检查同一原任务、下载当前编辑、显式打开当前商品。

整站回归还复现了关闭窗口的问题：从分类操作留下原任务后，再打开的只读编辑窗口被误当作当前表单提交，无法取消。现在只有从本表单提交的未完成发布才阻止关闭；继承的任务仍禁止新编辑，但可以关闭只读窗口。既有 1440px / 390px 测试由红转绿。
