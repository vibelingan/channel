## S1：后台自动接续

- 保留现有 run/checkpoint 和带 fencing 的主租约。点击 Sync 创建或接回已有任务，返回已保存的进度；重复点击复用同一任务。
- 每分钟的 CloudBase 原生定时器只接续运营已发起的任务，不按旧时间水位自行新建全量或增量任务。无需浏览器 JWT。
- 来源处理完成时，先在同一 run 写入待处理标记和草稿/照片游标，再释放来源任务槽位。若进程在两步之间退出，下一次调用会修复槽位。
- 现有来源处理本身会建草稿和处理报价。仅发现建草稿或报价更新失败时，再分页补同一次已完成/已批准 run 的数据；不放行隔离或未完成数据。
- 照片使用原有字段归属、版本检查、媒体锁和重试规则。每页保存游标。网络失败保留原阶段和游标；连续3次传输失败转为需要处理，避免无限无声重试。
- 不发布、不强加分类、不覆盖手工报价或手工照片、不清除 NEW。已有发布商品继续按原有来源变更规则处理。

安全边界：定时入口同时验证平台设置的 `TRIGGER_SRC=timer` 和精确触发器名称；仅伪造 JSON 无法启动工作。旧 runNow 等受保护 API 保留，避免破坏现有调用方。

## 风险及不能提前作出的承诺

- Alibaba返回不安全数据时不能自动批准，应保留已有商品并提供可理解的提示。
