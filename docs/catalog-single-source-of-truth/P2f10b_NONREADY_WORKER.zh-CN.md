# P2f10b：默认准备流程保存诊断，取消时撤销当前状态

默认 worker 在来源下载尚未完成、像素检查只完成一部分、内容或图片有问题、元数据确认尚未完成时，调用已有 checkpoint-preparation 保存当前 preparing/blocked 报告。沿用同一候选的 previewReady 和安全 issue；事务内重新核对完整输入和租约，不为写报告额外读取一次全候选。真实媒体错误优先返回 blocked，已消费的像素重试即使只检查到前缀也返回 retryable。检查结果不是发布许可，ready 仍须完成既有封存与最终提交。

诊断提交抛出异常时，用原 grant 再确认一次。明确 BUSY 等失败照常返回失败；两次传输失败不能伪造成功。后续调用能从持久化 cursor 继续，避免重复下载和写入已保护的图片。

人工取消在原 admin/expectedLeaseVersion 检查之后，核对当前商品和报告是否仍属于该任务的 input/generation，并在同一事务内将 catalogPreparationState 改为 stale、保存 cancelled job。旧报告保留为历史；分类、公开状态、图片、计数、业务字段和用户更新时间不变。旧输入任务不能清除新输入的报告；再次取消零业务写入。来源商品最多八次点读写，两个写入对象的八种 ACK 异常均回滚。

任务 release 仍为 queued，调用端必须结合 outcome 决定下一步。来源 503 尚无媒体计划时可以重新 dispatch；像素检查已消费 retry 时使用现有显式 retry 重置；永久来源 404 和内容问题提示编辑/重新同步，不自动循环下载。用户 API/UI、过期恢复和列表准入仍在后续单元，不能从底层 queued 状态推定已完成。

本地验证：四包完整 DB1107/admin549/alibaba304/local467，共2427项通过，零失败、跳过、取消。Node20五文件346项通过，四消费者类型、三完整源码/测试文件显式Biome、原生新增块格式、SDK gate、diff检查通过。旧媒体预算测试的商品无报告断言改为当前 preparing，符合本单元新增行为；没有删除测试或改为跳过。8个实际源码反例全部检出，21–30个正控/31项保留；原始源码字节恢复后才执行完整回归。

真实本地小流程包括：坏名称可读取诊断，编辑后新版本 ready；来源503继续成功；永久404不重复下载；像素暂时失败显式重试成功；诊断写入丢 ACK 可确认；两次失败后继续不丢 cursor；诊断前后取消；旧任务取消保留新输入报告；坏像素前缀立即可见 blocked。实际云端、现场三件时钟和20件发布/恢复均尚未验收，fullDeliveryReady=false。精确构建和 bundled main 的记录在审查 sidecar 追加。

文案核对 worker/jobs/checkpoint、共享 report 和原生/JSON 测试。将“queued 就自动继续”改为“按 outcome 选择继续、重试或修复”；八次事务预算、回滚、分类/公开状态和测试数量都对照程序断言及日志。未将本地模拟事务称为云端 MVCC 验收。
