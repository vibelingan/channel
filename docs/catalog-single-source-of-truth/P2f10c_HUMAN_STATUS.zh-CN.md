# P2f10c：当前准备进度与显式重试

新增严格的人工 status 仓库命令，沿用每次读取当前 admin 用户行的权限检查。请求只需 jobId，不依赖旧的30秒签名。结果只投影已有安全 progress、确认计数、当前报告与 nextAction，不返回 nonce、租约所有者、签名、grant、来源URL或存储对象。无对象IO、无逐图扫描，来源商品最多六次点读、零写入；mutationRevision 已达最大值仍可读取。

报告展示前核对完整商品/来源/观察记录/关联输入及 generation。旧输入返回 current=false、空报告和空确认进度、restart建议。完成态重用已实现的 receipt/seal/report校验；坏证明不能凭 ready 字段冒充成功。完整输入的四类原生对象分别改动，完成与非完成状态都能隐藏旧结果。不可能的封存进度返回CORRUPT，旧像素策略提供重试。

nextAction 是人工恢复建议。当前运行中的新鲜租约先 wait，过期运行任务先 continue 接管；排队的失败像素才 retry，永久内容/图片问题 edit。初次复核确实发现过期运行任务仍带失败图片时被错误推荐 retry，而现有状态机不接受；新增红测后修正，并实际经过接管、释放、再推荐重试。不能仅看queued和诊断自动循环来源下载，后续控制器还需预算和退避。

显式 retry 在原 expectedLeaseVersion 和完整当前输入检查下，轮换nonce、重置游标并在同一事务内撤销仍属于该输入的非就绪报告状态。保留报告历史、用户字段、公开状态、分类、图片与计数。否则旧 blocked 会在新尝试开始后继续显示。允许当前 stale/blocked 任务通过显式重试恢复；输入变化仍返回STALE，运行任务和queued无计划状态不会被直接重置，当前ready报告也不会被清除。来源商品最多八次点读写，八种写ACK异常均回滚两行。

最初四项红测分别暴露动作不存在和旧报告残留。首次格式校验发现重复导入既有常量，已移除；完成态测试误用了不存在的时间推进方法，已在夹具提供真实时钟推进，并断言原签名确实过期。失败记录保留。首轮小组合385通过，补恢复反例后扩大。十个实际源码反例全部检出，42项中33–41个正控保留，原字节恢复后才运行完整回归。
