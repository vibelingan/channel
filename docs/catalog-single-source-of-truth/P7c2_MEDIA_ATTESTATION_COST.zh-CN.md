# P7c2：照片证明分页事务

真实单件仅改description仍需照片检查，准备耗时约13秒，其中缓存照片的持有/记录/确认被拆成多次事务。先合并确认图片证明这一段，保留完整候选检查与当前代次，不把旧媒体证明直接视为新文字已经检查，避免改变准备状态语义。

## 边界与数据

新增仅服务端租约可用的attest-media-page命令，输入原jobId/lease/planDigest、from旧seal及最多8个已选imageIds。持久数据仍为原seal结构；不增加产品字段、图片字段或SDK方法。原单张命令保留。

事务内逐张检查原hold、当前图片、保护意图和像素证明，生成相同滚动摘要；最后再检查当前来源/产品代次和租约，统一写一次job。任一中间图片失败不写部分seal。重复原page必须能重新算出与当前seal完全相同的结果，保持回执丢失恢复。不能仅凭from或调用方传入的图片列表判通过。

最坏读写为job1 + 每图hold/image/intent/pixels共4×8 + product/source/observation/link最多4 + job写1 = 38，低于原98预算。无外部下载，物理图片每步4张与整个metadata每步16张上限保留。单次有界页替代单张确认，不增加原20秒worker、8秒收尾预算；页间继续检查时间。

## 取舍

直接复用旧内容代次的完整ready报告会把新文字未检查伪装为已检查；不采用。并行读取同一CloudBase事务之前已实际触发TransactionBusy；此处仍用现有串行读取适配器。页面仅减少事务往返，不能提前断言整个live-save已达到8秒。

## 红测及检查

实际PNG/保护证明的三图分页、无写重放、原单图兼容；第三图校验变化、缺hold、反序、错误plan、超过8图时不部分推进。之后补租约过期、取消、并发来源、丢回复和数据库重开，并执行原worker全套、相关core和SDK/type/lint。旧注入若只拦截单张命令，需要同时覆盖新页，不删除异常用例。
