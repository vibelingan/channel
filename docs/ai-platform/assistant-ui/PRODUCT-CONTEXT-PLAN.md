# MIU 4／5a：多轮产品上下文补齐

复核发现结构化卡片保存于最终事件，但后续模型只收到通用答复文字，无法知道上一轮展示了哪些产品。补齐现有 store → worker → engine 的公开上下文投影，保留最近 30 条消息；不新增历史恢复、正式询盘存储或供应商工具。

仅从同一会话、消息对应的 final 事件读取已校验的公开产品字段；重建字段 allowlist，不传额外属性。明确标记历史查询资料，当前问题需要比较/核对时让现有有限 lookup 重新读取实际公开 API；不把聊天记录里的旧产品事实当当前库存或报价。

验收：真实 PG 下当前消息正确关联卡片，外来会话和额外私有属性不能混入；最新 lookup 的下架 ID 进入上下文；浏览器连续问答可根据第一轮真实查询结果执行第二轮 lookup。保留无凭据恢复、假模型标识与询盘提交关闭；测试及定向变异通过后推送。
