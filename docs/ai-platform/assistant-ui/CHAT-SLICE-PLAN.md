# 提问到停止：前后端一起交付

2026-10-30。按用户最新要求，每轮交付一个可操作的完整流程。本轮沿用原 MIU 5f／6b／6c／7／11c，完成创建会话、连续提问、真实流式读取和停止当前回答。复用 BFF、PostgreSQL、worker、ConversationEngine 和前端 Experience，不另建任务系统。真实邮件不发送。

历史恢复暂不实施：重新打开助手 → 凭原浏览器会话授权验证身份 → 获取以前消息 → 展示并继续；授权失效则新会话。是否需要这条流程，留给用户决定。断网后继续读取当前回答是本轮可靠交互的一部分，和重新打开后恢复历史分开。

## 接口与门禁

增加 `/api/ai/v2`，原 v1 保留。v2 消息仍复用追加事务；同 key 换正文拒绝，同会话已有回答时拒绝新的并发提交。GET `conversations/:id/turns/:key` 只返回该提交的运行身份和状态，不返回聊天历史。

取消路径绑定该提交 key、runId 和 controlVersion，在同一事务核对当前活动运行；晚到的旧取消不能作用于新回答，重复取消不增加 outbox。SSE 仅投影该 run 的已提交事件，带消息和运行身份；浏览器严格解码后才推进 cursor。

“停止”指服务器关闭该回答的写入与交付，未来 token 不会继续写入或显示。引擎支持带外取消时复用现有执行路径；厂商实际计算／费用是否立即结束仍按引擎能力报告，不承诺底层进程一定已杀死。

## 验证顺序

1. 真 PostgreSQL 下的 v2 凭据归属、重放内容冲突、状态读取、精确取消与重复取消测试。
2. adapter 解码、丢失回执同 key 重试、错 run 与重复事件测试。
3. 实际 React → 真 BFF → 真库 → 原 worker／确定性测试引擎的浏览器闭环，覆盖多轮、停止、停止后再问与单次失败后继续。测试引擎清楚标识，不称真实模型验收。
4. 已有 v1／store／worker 回归、定向缺陷注入、构建与 CI；若现有安全配置允许，再单独尝试已配置的真实模型，不因缺账号阻断可验证代码。
