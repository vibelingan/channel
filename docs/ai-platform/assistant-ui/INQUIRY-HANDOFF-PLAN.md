# SG1.2／SG3.2：云库与自动接任务验收

2026-11-01。沿用已有两条 Channel 分支和 Hermes Sales 分支。用户已授权在现有 Channel CloudBase 环境写入明确标记的新功能测试数据。不要求独立云环境；不更新现有机器人、共享 Hub、dispatcher 或已有客户记录。

## 本轮验收

1. CloudBase 管理登录后核对环境 ID 与新资源范围，在现有环境创建 Sales 私有集合和固定归属的合成询盘。明确这是共用云环境中的标记数据，不宣称物理隔离；记录清单便于后续只清理本次数据。此项实际云库验收已通过。
2. 复用现有询盘保存、来源登记、通知器、Hermes intake／dispatcher／consumer。补齐助手入口到自动归档的跨仓库验收，核对同一询盘 reference、task、run 和唯一成果。
3. 浏览器操作现有助手核对组件，经真实 BFF／会话 PostgreSQL 提交；Channel 云库未就绪时明确使用原事务替身，Hermes 使用本次创建的独立 MySQL。模型采用本地 HTTP 样例，不连接邮件服务。
4. 正常提交、已提交但丢回执、重复通知、撤权、产品引用和已有非销售任务兼容分别验证。缺陷注入只修改临时副本；环境／导入错误不算检测到业务缺陷。

## Hermes 部署边界

Sales 是单独入口，默认关闭，不自动注册共享 Hub。新消费进程和 Sales 专用表不应安装到现有业务库。上线仍需独立数据库账号、私有目录、服务身份、监听地址、资源限额与停用方式；逻辑归属校验不能替代这些基础设施隔离。

本次仅新增专用管理端验收函数，不部署或重启现有业务进程。远端只读检查只能证明所查主机的状态，不能从一台没有 Hub 的旧主机推断实际部署不存在。普通咨询模型与 VibeKB 公开检索仍单独验收。

## 证据

每份结果标明浏览器／HTTP／CI 入口、真实服务及替身、分支 SHA、资源创建和清理，以及未完成的真实云库检查。完成代码经过分轮自查、测试、E2E 后提交推送；仅报告实际通过的层次。
