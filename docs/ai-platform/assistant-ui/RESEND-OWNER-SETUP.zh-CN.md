# Resend 接入：客户授权，我们配置

API Key 已收到并验证有效，客户不用重新创建。建议邀请 Sean 登录接手配置，客户再把原来负责网站地址设置的人介绍给他。现有 Key 已支持程序侧接入；团队邀请用于人工查看、配置和验收，不是要求重新开通 API 权限。

可直接发给客户：

> API Key 已经收到，可以正常连接。后续配置我们来做：请登录 Resend，点左上角公司名称选贵公司团队，打开 Team Settings → Invite，填写我们提供的技术邮箱，角色选 Member，然后发出邀请。技术人员会用自己的账号接受邀请，不需要您的密码。另外，请把原来负责网站或管理 supplychainsai.com 的同事介绍给我们，我们会联系他完成邮件授权。您不用自己改网站或邮箱设置；本次只验证保存邮件草稿，不发送邮件。

## Sean 接下来做什么

1. 用自己的邮箱接受邀请并登录客户团队；没有 Resend 账号时，邀请流程会引导注册。邀请邮件用于开通登录权限，不是用来模拟买家收邮件。已有 API Key 是程序连接凭据，团队邀请是人登录操作的入口，两者用途不同。
2. 在 Resend 的 Domains 中添加 `supplychainsai.com`，取得平台为该网址生成的发信授权记录。添加网址只是告诉 Resend 想用哪个地址发信；还必须在网址的设置后台公开登记授权，证明公司允许 Resend 代发，避免别人仅凭填写公司网址就能冒充发信。
3. 与原建站人员或云账号负责人联系，给出平台实际生成的记录，由他添加；也可让他仅授权 Sean 修改本次所需的那些记录，Sean 自行完成。2026-11-04 公开查询显示该网址使用 DNSPod 的 `ns3.dnsv4.com`、`ns4.dnsv4.com`；具体属于谁的登录账号尚未确认。这个人不是 Resend 官方客服。
4. Resend 验证通过后，配置 `sales@supplychainsai.com` 的 Inbox（邮件草稿和往来邮件所在的收件箱），使用转发接入模式；保留现有企业邮箱收信设置。再保存一封测试草稿并读回核对正文、收件人和附件，不调用发送接口。草稿测试不需要先接 Webhook 或开启邮箱自动转发。

## 给多少权限

Resend 先选 **Member**。官方说明它能管理邮件、域名和 Webhook；**Admin** 另外能邀请成员、处理付款和删除团队，这次不需要。官方没有列出“能配置域名、但禁止查看邮件或客户名单”的独立角色，不能承诺 Member 会隐藏这些资料。我们只访问配置和测试内容；如客户要求系统上完全不可见，则需要单独的测试团队，不能靠口头约定保证。配置结束后客户可移除人工登录成员，后续程序仍用专用 API Key 连接。

网址设置后台的授权与 Resend 成员权限是两回事。DNSPod 支持只共享部分记录的读写权限；应按 Resend 实际生成的记录限制授权，不交出整个腾讯云账号。原负责人直接添加记录时，无需再给 Sean 该后台的登录权限。保留网站解析和原企业邮箱收信记录。
