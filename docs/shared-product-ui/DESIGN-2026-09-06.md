## 1. 结论与范围

沿用用户确认的店小秘原型布局和 contextual RFQ 交互，适配已经存在的共用详情 DTO。
继续在当前 wiring 工作区按小 MIU 顺序实施，不整体合并另一个脏 worktree，也不等待
整个 Catalog refactor 完成。每个需要移植的模块单独记录来源与依赖闭包。

本阶段做：本地真实耳机样本 → 同一详情 gateway/state/view → 选型/图片/来源报价/
规格/本地 RFQ 填写复核。店小秘解析产生的样本走同一个组件，不做第二套页面。

本阶段不做：客户未确认的分类映射、358 件商品批量归类、云端变体回填、同步调度、
Excel 云端 worker、正式 RFQ 启用/通知、VIP 价格、汇率/销售价格政策、Admin 重设计。
注：CUI-06D 已按后续用户授权实现 RFQ 云端记录策略与部署；静态前端及 RFQ 开关尚未开启。
既有 NEW/审核状态与草稿发布状态必须保持不变。

## 4. 界面设计规范（CUI-04 修订版当前规则）

目的：让采购者确认一个真实商品的配置、可用事实和报价条件，在询价复核中保留所选
商品/变体/数量；数据缺失时保持可读、可操作，不产生虚构产品信息。

方向：原有 precision industrial editorial。视觉主次仍是商品图 → 标题/配置 →
询价 → 技术事实。不是新的 dashboard 或新商城风格。

- 颜色沿用 `tokens.css`：brand-700 `#2f3da3`、brand-950 `#0b1030`、accent-500
  `#f59e0b`、ink `#0f172a`、surface-alt `#f6f8fc`。
- 字体沿用 Poppins / Inter。这是已有品牌约束，不按通用设计 skill 换字体或配色。
- 桌面图文列 46%/54%，容器继续使用 `--width-container:80rem`。主图高 420px；
  <640px 高不超过 340px，640–1023px 图框最大 560×360px、居中。
  `object-fit:contain`、20–32px 内边距、张数提示；仅 detail Gallery variant 改样式。
- 单 DOM、CSS 响应式：手机标题/摘要、主图、横向缩略图、可见选项、配置与数量、
  specifications；当前 RFQ 入口为内联，可打开本地表单并显式保存到本机样本库，不使用固定底栏占位。
- 规格使用原生 details/summary + definition rows，包装配件独立显示；供应商说明默认折叠、
  行长限制 70ch。v1 无内容块时保留纯文本分段，绝不在浏览器猜 HTML/交替行参数。
- v3 的 `noteBlocks: {kind:'heading'|'paragraph', text:string}[]` 保持原顺序；heading
  渲染为 h3、加粗并留段前间距，paragraph 渲染为 p。v1/v2 没有字段时不猜小标题。
- 数量初始为空；只接受正安全整数，不把空值/小数/科学计数法自动改成 1。产品或批准
  revision 更换时重置；SKU 切换时保留输入并重算。明确 MOQ 未满足、阶梯空档和无价分别显示。
- 来源报价按 product / selected variant 分区，各 offer、币种和 regular/promotion 分开。
  高亮实际命中的数量档；不能用产品报价补 SKU，也不合并最低价、换汇或生成订单总额。
- 标题附近最多 3 个 Material / Drivers Size / Frequency Response / Impedance 等简短事实；
  冲突字段退至说明，Microphone 等 SKU 相关字段不进入摘要。产品级规格与选型字段明确分开。
  不声称提取后的源事实经过真实性认证；缺失时不造卖点。
- 弹窗保留原型的上下文摘要与三步结构；桌面限制宽度，手机底部 sheet，同一表单。
- 扩展现有 SiteHeader / SiteFooter / BaseLayout、Gallery / ProductMedia、字体与间距
  tokens。原型全局 `body/button/main` 样式、导航、Xiaomi assets 不导入生产页面。
- 图标延续应用既有 SVG 风格；不为迁移原型引入整个 Phosphor 依赖。

UI skill 在此约束“先核实既有视觉、先写设计规范”，不触发重新设计网站。

本节与[修订验收](CUI-04-REVISION-ACCEPTANCE-2026-09-06.md)同步维护。
历史 prototype 文本保持只读，不能反向修改来源快照冒充原设计。

## 5. 数据、分页与异步状态

```text
两种 source adapter（已有）
  → observation / explicit bindings（私有，已有）
  → 共享 parse5 有界表格提取 / 私有 content candidate
  → approved canonical snapshot（本地已验证；云端接线后续）
  → /api/products/:id/detail + revision pages
  → strict gateway → request/selection state → 同一 CatalogDetail
```

结构提取复用现有 sanitizer；parse5 7.3.0 仅在服务端包中使用。原输入限 64,000 字符、
树限 4,000 节点/32 深度，规格及包装各最多 100 行、字段名 200/值 2,000 字符、
说明最多 80 段各 2,000 字符。超限放弃内容块，回退已批准的 v1 文本，不静默截断。
明确两非空格行才进入候选；嵌套/合并/多值行不猜，未知名称保留说明；同名冲突不选赢家。
历史 sanitizer 已丢失的合并格属性无法恢复，需 raw evidence 后续审核，不能当作已识别。
本地批准将合法 content 固定到同一 revision；管理员改过描述时不批准旧提取结果。
公共 v2/v3 只含文本结构，不含 HTML、账号、证据路径；默认 v1 字段一字不扩充。
v3 的 noteBlocks 与 content.notes 必须逐项文本/顺序一致，heading 最多 200 字符、
paragraph 最多 2,000 字符、总计最多 80 块。批准时固定到同一 revision。
解析阶段识别保留下来的 h1–h6；此次真实样本的两项标题实际上没有 heading 标签，因此
另明确配置用户确认的两个完整独立标签：Experienced Headphones Manufacturer、Product Description。
不按长度/大写/关键词猜测，不将正文中包含该短语的句子变成标题；其他无法恢复边界的内容
保持普通说明。原始数据仍保留，规则调整只需本地重新解析，不需要重新调用 Alibaba。

当前 Alibaba 和 Excel adapter 的 amountMinor 均按百分之一编码；展示用安全整数和 BigInt
保留精确小数及来源币种，不按 ISO 币种小数位改变源值。该既有编码约定不是通用货币换算器；
未来若修改入库金额单位，必须独立版本化迁移，不能只改前端格式化。

### 输入边界

HTTP body 当作 unknown：读取失败、空 body、非 JSON、null、错误 envelope、schema 不符、
超界 body 都进入可恢复 error，不 `as CatalogProductDetail`。使用共享 decoder，不再为
页面做容错 raw parser。不把失败变成一个看似成功的空商品。错误日志不能打印完整 body。

当前 DTO 的 revision 可选是 candidate/test 兼容；真实分页 gateway 要求 revision。
每页核对 product ID、page/pageSize、total、revision，以及 header 一致性和跨页重复 ID。
后续页 409 时丢弃旧页并提示重新加载，不自动无限重试，不把新旧 revision 拼起来。

### 有限加载策略

默认 pageSize=50。商品头可以先展示，配置区域区分 loading/partial/complete/error。
本阶段小产品可以顺序加载完整集合后建 option matrix；最多收集 500 个变体、10 页，
并设每页 2 MiB/合计 8 MiB 的客户端字节预算。这是前端保护上限，不是阿里/API 商品上限。
实际样本若超预算，返回清晰的限额状态并重新评估，不静默丢字段。

总数超过 500 时使用服务端页码式 SKU 浏览（保留当前页 + 已选择快照），仍可遍历后续
页；不构建一个“全商品”option matrix。未加载完整时，不声称组合不存在，不把未见
选项禁用成“无货”，也不自动选择前页 SKU 代替 URL 指定的后页 SKU。

URL 指定 variant 在尚未读取的页中时保留 pending selection，允许继续查找/翻页；
只有完整范围检查结束才能称其无效。用户可显式清除 pending selection 重新选型。
分页读取失败可重试该页，但只有相同 revision 才能合并；切换商品/关闭页面中止请求。

## 6. 选型、媒体、金额与本地 RFQ

- 唯一选择是 canonical variant ID，不是 SKU 字符串或 `{Color, Storage}`。无 SKU 文本不
  丢变体；两个 ID 同名选项不能静默折叠。variant_quote 需要真实 canonical variant；
  零变体商品保留 Ask about customization 作为商品级沟通入口，不生成虚构 SKU。
- Unknown/conflict 显示“Availability to be confirmed”；reported 显示来源报告及语义，
  0 是已报告 0，不等于禁止发起询问。这里不新增出库/履约承诺。
- 选 SKU → 显式 variant.images 优先，否则保留父图库；任意缩略图点击只改变 active
  image。失败图片有稳定占位，不清空已选 SKU。将来有独立 role 契约后才启用反向联动。
- offer.kind 是报价种类，不是 provider 分支。多币种/多 offer 分别显示，不自动选最低
  价或跨币种相加。当前报价没有批准的销售政策，页面和结构化 SEO 均不生成销售 Offer。
- quantity 编辑允许暂时为空；复核时严格检查正安全整数，不沿用原型任意 999999 上限。MOQ 来自当前明确
  offer，缺失则不宣称最低订购量为 1；技术输入下限与商业 MOQ 是两件事。
- fixed/tiered/range/negotiable/unavailable 穷尽处理。阶梯空档不沿用前档价，范围价不
  强制取最小值。金额使用现有 minor-unit 规则；只对已支持的币种格式化，不猜单位。
- 固定价和范围价无需先输入数量即可看到，阶梯价始终展示完整档位表。数量为空、
  无效或低于 MOQ 时仍保留参考价格，同时明确显示数量提示/未达 MOQ；不得将显示
  价格误作数量校验通过，也不计算订单总额。有效数量下避免重复显示同一固定价。
- RFQ 打开时带入 productId/revision/variantId/quantity；数量可修改并回流报价区，更换配置或 revision 后必须
  明确重新复核。字段由既定 React Hook Form + Zod resolver 管理，业务 reducer 只管
  intent、步骤、身份和复核有效性，不手写一套表单 touched/error 引擎。
- 已重新核对并安装 react-hook-form 7.87.0 / @hookform/resolvers 5.9.1，site 直接依赖
  与 shared 相同的 Zod 3.25.76；MIT、React 19 与 Zod 3 兼容已核实。安全审计仍有告警，
  具体路径及 bundle 检查见 CUI-06 验收，不将“已检查”写成“无风险”。无新全局 state/router 库。
- 表单本地内存保存，关闭同一产品可保留草稿；换产品清除并提醒。无 localStorage、
  云端写入、真实邮件或 CRM。只有 dev 预览注入本地 transport 后显示 Save inquiry locally。
- shared 字段 schema 验证格式/上限；跨字段规则区分询价和定制，校验真实且非过去日期。
  target policy 独立校验可见性、revision、SKU 归属。当前 UI 只能针对已取得的批准快照
