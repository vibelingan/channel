## CUI-01 — 严格详情 gateway 与分页装配

**Runtime problem.** 当前新 handler 与浏览器旧消费路径不同：

```ts
// apps/functions/public-api/src/http-adapter.ts（当前）
segments[2] === 'detail' && config.enableCatalogDetail === true
// apps/site/src/islands/shop/SkuDetailPage.tsx（当前）
fetchProductBySlug(slug, controller.signal)
```

**Data / lifetime / scope.** 网络 unknown → shared CatalogProductDetail；页面内短期 page
集合，身份为 productId + revision + page。源 observation、OAuth、raw 路径不能到浏览器。

**Technology constraint.** 共享 `decodeCatalogProductDetail` 是唯一 DTO 校验；fetch 与
AbortSignal、apiUrl 使用既有工具，不加 Axios 或 public Query provider。

**Design / fix.** 新 `catalog-detail-api.ts` 负责有限字节读取、JSON/envelope 解码、状态
分类；`catalog-detail-pages.ts` 负责核对页码、total、revision、header 和跨页 ID。

```ts
// 目标模式；先检查 HTTP/envelope，再进入共享 decoder
const parsed = decodeCatalogProductDetail(envelope.data);
if (!parsed.ok) return { status: 'invalid-response' };
// 仅 productId/revision/page 与当前请求一致的页可进入集合
```

预算与 >500 的 paged-SKU 模式按 DESIGN §5。404=不可用，409=需刷新，空 body/非法
格式=invalid-response，网络失败=retryable，Abort=取消，不假装成功。

**Rejected.** 不读旧 list.variants、不 cast JSON、不用 `data ?? {}` 隐藏失败、不自动重试
409，不逐页无限积累数据。**Translation.** 组件拿到的是已验证结果，不负责猜接口形状。

**Risk / tests.** `catalog-detail-api.test.ts`: `rejects empty null and malformed bodies`、
`forwards abort and preserves 404/409`、`enforces body byte limit`。
`catalog-detail-pages.test.ts`: `loads variant 51 without truncation`、
`rejects mixed revisions and duplicate IDs across pages`、`keeps large products pageable`。
窄命令：`pnpm --filter @vibelingan-channel/site exec tsx --test src/catalog/infrastructure/catalog-detail-api.test.ts src/catalog/application/catalog-detail-pages.test.ts`。

**Done.** 同一 gateway 读取两种来源的本地已批准详情；无组件代码、无云端写入。

## CUI-02 — 不会选错 SKU 的详情状态

**Runtime problem.** 原型只靠四个固定 SKU 和本地默认值：

```ts
// reference/.../prototype/App.jsx.txt（原型）
const [selectedId, setSelectedId] = useState("black");
variants.find((item) => item.id === selectedId) ?? variants[0]
```

**Data / lifetime / scope.** 临时 request generation、validated pages、canonical selected ID、
pending URL ID；产品切换时失效。不是供应商 SKU 全局身份，不写 DB。

**Technology constraint.** 纯 TypeScript domain reducer，React effects 留给 controller。
**Design / fix.** 完整集合才建立 option matrix；未完整集合允许 paged SKU 明确选择，
不会断言未知组合不存在。相同 options 的不同 IDs 用 SKU/稳定编号作二次选择。

```ts
// 目标：请求身份先产生，发送和提交使用同一份身份
if (event.generation !== state.generation) return state;
// 同时核对 event.productId；URL 未找到且集合不全时保持 pending
```

**Rejected.** 不用 `setState` updater 读取 generation；不把暂未加载的 URL variant 当
无效；不以库存未知/0 推断不能询价。**Translation.** 选项是对真实 ID 的导航，不创建 SKU。

**Risk / tests.** `catalog-product-detail-state.test.ts`: `ignores late product A after B`、
`keeps URL selection pending until searched`、`invalid URL needs completed coverage`。
`catalog-variant-state.test.ts`: `never synthesizes a combination`、`duplicate options require explicit identity`、
`empty options and absent sku remain selectable`、`reported zero differs from unknown`。
窄命令：`pnpm --filter @vibelingan-channel/site exec tsx --test src/catalog/application/catalog-product-detail-state.test.ts src/catalog/application/catalog-variant-state.test.ts`。

**Done.** 数据只要未完整/身份不确定，就不会显示一个被默默替换的“已选 SKU”。
