## 1. 已确认的问题，不再用功能通过代表设计验收

### 描述：当前是临时降级展示，不是原型最终信息架构

原型有 highlights、分组规格和次要来源信息折叠；CUI-04 因 v1 只有 `facts[]` 与
`descriptionText`，先做了 plain-text fallback。这个 fallback 可以保留为兼容路径，
但用户已明确它不满足可读性，不能继续称为最终描述设计。

实际链路：两种 observation adapter 都保留 HTML/text → `detail-candidate.ts` 只把
identity.attributes 投影为 facts、description.text 投影为 descriptionText →
`CatalogSpecifications` 以单个 whitespace-pre-wrap 段落呈现。不是 API 没返回内容。

三件本地 Ali 样本 facts 都为 0，但 description.sanitizedHtml 都有 1 张表格：

| 样本 | text 字符数 | HTML 字符数 | 观察 |
| --- | ---: | ---: | --- |
| 无线耳机 | 1,414 | 1,952 | 两列 Product Name / Material / Function / Package；同表还混入 Our services |
| 儿童耳机 | 209 | 785 | 五列含空单元格；实际包含 Drivers Size / Frequency Response 等参数 |
| 有线耳机 | 296 | 920 | 同类表格；不能把所有行不加判断地当 SKU 专属参数 |

商品介绍、供应商规模和服务承诺现在同权重混排。尤其不能把公司出口量或 OEM 服务
放进“商品关键参数”。标题、描述、变体字段也可能矛盾，不能自动晋升为 Verified highlights。

分类：**内容契约范围缺口 + 呈现不足**。修复层：共享服务端内容转换、批准投影、UI 模板。

### 图片：中间宽度放大，单栏没有高度/宽度上限

浏览器固定高度 900 CSS px，实测同一商品：

| 700 | 652×572 | 1097 | 单栏、固定 CTA |
| 768 | 720×507 | 995 | 单栏、固定 CTA |
| 900 | 852×600 | 1088 | 单栏、固定 CTA |
| 1023 | 975×687 | 1175 | 单栏、固定 CTA |

当前 `lg` 才切双栏；Gallery 的 detail 模式只有宽度/比例，未约束单栏放大，
CTA 又在所有小于 lg 的宽度固定到底部。用户截图的窗口 CSS 宽度/缩放未知，

不能改旧 Gallery 默认布局。前轮 390/1440 截图与页面不溢出断言没有覆盖中间断点和信息密度。

### 入口与按钮：有意分阶段，不是鉴权或网络错误

- `?preview=shared&id=...` 是已有 item shell 的 dev-only 入口，旧 slug/列表仍使用旧页。
- 新 RFQ 按钮当前硬禁用。CUI-05 做数量/来源报价，CUI-06 做本地草稿和复核，
  CUI-07 接本地列表/返回；真实发送与生产切换仍是独立后续阶段。
- 即使 CUI-06 可打开表单，也不能宣称已发送或伪造成功编号。

## 2. 已批准并实施的修订方向

### 信息顺序：先判断商品，再看选型，最后看供应商附加说明

1. 标题附近给至多 3–4 条有依据、无冲突的关键参数；没有时不造卖点，不复制手机原型参数。
2. 商品参数用 label/value 表格，包装与配件另成简短区；只显示实际有内容的组。
3. 原描述中的供应商介绍、服务条款与未分类内容归入低优先级折叠说明，限制阅读行长
   至约 65–75ch，不再满屏一条长行。不默认删源文字，也不把原始 evidence 暴露到 DOM。
4. 尚无内容块的旧 v1 数据仍可用：fallback 按段落呈现完整批准文本，明确它是来源描述，
   不能用每两行配对的正则把纯文本猜成规格。
5. 这属于**内容分组**，不重新决定网站 family/subcategory，客户分类问题仍保持待确认。

以无线耳机为例：Material→ABS 可成为参数候选，Package→包装/电源线/AUX 线属于包装候选；
“60,000–100,000 pieces per month”是供应商自述，不是本商品性能或可售库存。

### 结构恢复放在共享数据层，不在 React 中写 Alibaba 专用识别规则

两种 adapter → 共用有界内容结构提取 → 私有候选/证据 → 明确批准的公共内容块 → 同一 UI。
只允许 paragraph、list、key/value rows 等受控文本结构；不把 HTML 直接送进 innerHTML。
分组和重点是显式分类规则/审核选择，结构解析成功不等于内容真实性已认证。

现有 sanitizer 会去掉所有 HTML attributes，因此不能假设 colspan/rowspan 等语义仍在。
简单明确行可形成候选；嵌套表格、合并格、空列或多个值的歧义不强配对，保留有序内容并
记录不可分类原因。完整原始证据仍是恢复依据。零新增 Alibaba 调用即可先验证当前已存样本；
不为改展示重新 full sync。

实施前核对可复用的现有 HTML 结构解析模块/依赖；不自造第二套安全 sanitizer。
契约必须同时覆盖 Alibaba 与 Excel，并明确大小/深度/行数上限和异常降级。
当前 v1 Zod 是 strict：新增内容字段不能直接塞进旧响应。需要明确版本化或兼容投影、
decoder、approved snapshot 和 revision 的成套变更；旧消费端继续得到合法 v1，
新内容仍须显式本地批准，不能靠刷新页面自动公开。

### 视觉：收住图库，给配置留空间，不用无依据装饰填空

保留当前品牌、原型图文结构及 Gallery。候选尺寸基线：

- <640px：单栏、主图不高于 340px，保留完整图、内边距与可触达缩略图；RFQ 可用后
  再使用紧凑底栏，禁用阶段不必占据固定底部空间。
- 640–1023px：图库居中，图框 max-width 560px / max-height 360px；不机械提前双栏，
  避免把长标题/配置挤到狭窄侧栏。CTA 内联。
- ≥1024px：图文列约 46%/54%，主图高不超过 420px；正文、配置和后续报价占更高权重。
- 图片 object-fit: contain，图框内留约 20–32px；使用现有浅色底、细边框、稳定缩略图和
  “第几张/共几张”的轻辅助信息。不要加假认证章、库存承诺、无功能卡片或多余营销装饰。
- 具体数值以真实长标题、竖图/横图和浏览器几何验收微调，不把截图缩放像素当 CSS 尺寸。

## 3. 方案比较与顺序

- **推荐：布局修复 + 共享内容结构恢复。** 可读性与两来源统一一起补齐，需小幅扩展契约。
- 只缩图、缩字体/折叠描述：改动小，但表格语义和重点依然丢失，只适合作为兼容 fallback。
- 直接渲染源 HTML：不采用；样式不可控，也绕过当前受控公共投影设计。

实施顺序为 R1（尺寸/CTA/几何验收），再 R2（共享内容结构/契约/双 adapter 样本），
最后 R3（内容模板、两来源渲染、文档与浏览器验收）；再继续 CUI-05/06/07。
R1 不等待分类确认；R2/R3 不构造新供应商 UI，也不改动其他 worktree。
R1/R2/R3 已单人顺序完成，未派发任务；CUI-01..04 的既有功能测试成绩仍作为历史事实保留。

## 4. 下一次验收必须补的证据

390/640/700/768/900/1023/1024/1440 宽度；900px 单栏不再出现 600px 主图；
同时断言 frame 尺寸、SKU 起点、缩略图可触达、CTA 不覆盖内容和文字行长。
不以 document.scrollWidth 单项替代布局验收。加入 200% 缩放/长标题/图片失败检查。

两来源的明确表格、空列、多值、合并格、重复字段/矛盾值、无描述、乱码/坏 HTML、
超长内容必须覆盖；新增内容不可破坏 v1、revision paging、404/未批准 gate。
三件真实 Ali + Excel 解析样本都要看页面，而不只看测试数量。
