# 本地助手怎样把文章送到人手里

2026-10-26：以下闭环已在真实 CloudBase 和网站通过，本地原生 Hermes 只加载两个草稿工具。页面操作由自动化浏览器模拟管理员；正式 HermesInfra / 企业微信未修改。实际证据见[整体验收](evidence/assistant-acceptance.json)，后续进度统一在[当前入口](../README.zh-CN.md)。网站代码仍在原 SEO 分支，日常发文章不调用下面的 GitHub 测试任务。

## 三种身份各自做什么

| 谁 | 做什么 | 凭据放哪里 |
| --- | --- | --- |
| GitHub 人工部署入口 | 核对现有函数和权限、连接一条草稿路由、登记或停用测试凭证 | 已有 `test` 环境密钥，留在 GitHub |
| 本地 Hermes | 生成正文，保存一篇私有草稿，读取这次保存的结果 | 本机私有配置中的草稿凭证；模型看不到凭证 |
| 管理员 | 登录原后台、编辑、预览，确认后点击发布 | 原网站账号；测试只在浏览器步骤使用已有测试账号 |

本轮没有修改 HermesInfra、企业微信群或全局 Hermes 配置。网站接口可以给后续正式助手复用；本地原生 Hermes 模拟与 HermesInfra/WeCom 正式接入分别验收。

## 先接通网站接口

固定使用现有环境的标准服务域名：

`https://diversity-123-d9grnqfux221323bb-1443560658.ap-shanghai.app.tcloudbase.com`

只新增 `/api/integrations → article-import` 并透传完整路径。已有商品和后台的旧服务地址不改。接口只接受创建草稿和查询本次导入，没有发布、撤回、删文、商品或通用管理操作。

`blog-import-setup` 沿用现有 GitHub 人工入口及 `cloudbase-deploy-test` 队列。它核对实际运行包与已通过 CI 的原包相同、Node20.19、无触发器、配置保留、三集合 ADMINONLY。先归档范围，再接新路由和登记测试凭证；实际 HTTP 的程序身份和匿名拒绝都要通过。任何未知旧资源、包不符或配置变化都停止，不能借接线覆盖旧服务。

本机生成随机 32 字节密钥，明文文件权限为 0600，目录 0700。服务端只保存 SHA-256。测试凭证有效两小时，不能重复运行入口悄悄延长，也不能重新启用已停用的凭证。

技术入口参数保留现有十个输入限制：此模式的 `plan_token` 字段只承载测试密钥的 SHA-256，`action=initialize` 接通，`action=restore` 只停用本次凭证。这里没有 AI token 或模型调用。操作通过本机已准备的非明文输入文件提交：

```sh
gh workflow run seo-static-canary.yml --repo vibelingan/channel \
  --ref feat/seo-foundation --json < output/hermes-blog-live/setup-inputs.json
```

不要把 `credential.json` 传给 GitHub，不要把密钥放命令行、截图、工单或聊天。接线入口不替换现有函数程序，也不还原数据库。

## 再运行一次本地创作

使用已经安装的 Hermes 运行目录和本次独立的 `~/.hermes/profiles/channel-blog-acceptance-*` 配置。不要复制用户全局认证文件；运行时按 Hermes 原生规则读取已登录的模型账号。云端没有这套本机运行时就跳过原生模拟，另行配置其自己的模型认证，不能把本机认证打包交接。

先运行 `tools/hermes-blog/run-acceptance.py --initialize-only`，实际断言只出现创建草稿、查询结果两个工具，再允许真实模型生成内容。本轮任务号、草稿号、集成号在生成之前固定，模型不能换号重复创建。每次 HTTP 有限时和限量；临时网络错误复用同一正文和编号重试，409 或权限错误不换号重试。

真实运行会把原始模型对话和导入正文保存到本机私有 output，不上传完整对话。独立从受限接口和数据库读回同一个导入结果；模型说“已保存”不能作为成功证据。

## 人工页面与公开结果分别验收

1. 用 `blog-import-review` 操作本轮固定导入号：真实登录、打开编辑链接、增加一段人工审阅文字、保存、刷新、预览并截图。独立读数据库，确认草稿仍未公开。
2. 重放原始助手请求，确认返回原导入结果，不覆盖管理员保存的新版本。
3. 查看正文和预览截图后，用单独的 `blog-import-publish` 操作模拟人在后台点击发布。立即读取正文 HTML、列表、sitemap 和 canonical/Article 信息，不运行文章内容构建。
4. 用 `blog-import-withdraw` 撤回同一测试文章，确认公开页面 404、列表与 sitemap 移除，草稿仍可编辑。
5. 停用本次凭证，用本机原凭证确认接口拒绝访问，再移除本机明文配置。停用只核对私有凭证记录，不依赖网站或文章函数的 HTTP 健康，因此服务异常时也能单独停用。保留草稿、导入结果和验收资料。

页面测试只允许固定集成、任务号和原始内容摘要一致的这一篇文章。正式发布前还要求管理员保存的版本和审阅文字，不能把模型原始输出直接当作已审稿。

停止测试不会删除客户文章，不回灌数据库，不关闭原后台，不修改商品、价格、同步任务或已有函数。新的路由可保留供后续正式接入；没有有效凭证时，服务拒绝草稿读写。需要关闭时只停用这个标准域名下明确归属 `article-import` 的 `/api/integrations`，保留其他路径。
