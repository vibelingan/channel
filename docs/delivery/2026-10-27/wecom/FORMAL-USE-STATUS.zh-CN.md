## 为什么之前没有到网站

写作技能只告诉内容助手应该做什么，并没有给它安装真实交接工具。pipeline 的9项工具负责找资料和写作，不是网站发布队列。工作区改对，只解决了文章存在哪里；它不会自动产生网站草稿。

现在内容助手有两个专用工具：新文章用 channel_blog_save_draft，已有文章用 channel_blog_submit_document。程序固定存入工作区2，通过一把仅能执行草稿交接命令的 SSH 密钥，把文档编号交给发布机。发布机重新读取指定文档、核对工作区，调用网站接口保存并查询真实回执。这个步骤由程序完成，不需要再启动一个模型或让客户同时 @发布助手。

首次新稿入库曾失败：实际 MCP Python SDK 1.26.0 把 Optional[str] 中的纯JSON字符串解析成对象，工具随后拒绝正文类型。连接器现给来源文本加明确版本头，读取时严格解析；原文档201的格式继续兼容。新增用例先复现再修复，并重新通过真实服务器保存和重投。不升级或重启共用知识库服务。

网站轮换也发现过错误分类：业务上的“钥匙不对”在事务中被转成503，导致维护不能继续。已补实际SDK、HTTP接口和维护客户端的组合测试；修复后云端实际换钥匙成功。失败记录保留，没有通过重置凭证掩盖。

凭证有效90天，30天开始自动轮换，并非永久密钥；发布机或网站持续不可用直到过期时，需要管理员重新授权。正常使用不要求客户十四天续一次，也没有单篇限制。旧试跑钥匙已经停用，真实请求返回401；正式钥匙仍能查询原草稿。已有其他平台发布流程保持原样。

[脱敏现场回执](evidence/formal-live-acceptance.json)。程序联测和真实群任务分别验收；本轮没有向群发消息、调用模型、公开文章或代替用户审核。
