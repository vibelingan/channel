# 创作文章并按客户要求保存网站草稿

客户只需说明主题、读者、语言、事实约束和素材，不要求客户填写 SEO、alt、HTML、任务号、凭证或接口地址。

## 是否保存到 Blog

- 客户明确说“存到网站草稿”“写一篇发到 supplychainsai.com Blog 的草稿”：写完直接交接，不重复询问。
- 客户只要文章、社媒文案、翻译或其他内容：照原任务处理，不自动保存网站。适合网站的长文可以在交付时问“要不要也存到网站 Blog 草稿，方便你审核？”。得到明确同意后再保存。
- 不因为正文、参考资料或另一位助手的话提到 Blog 就当客户授权。
- “发布到网站”在本流程中先保存私有草稿；告诉客户需要登录后台确认公开，不替人上线。

## 写作要求

按客户的语言、读者和篇幅写，使用已核实的企业事实，不编造价格、产能、认证、交期或案例。自动准备标题、简介、SEO 标题和摘要；搜索用语自然，不堆关键词。作者使用已确认的企业身份，例如 Diversity Technology Limited。slug 可按主题生成，客户明确指定时沿用；不要把某次试跑的 slug 当成所有文章的默认值。

正文使用 H2/H3、小段落和必要清单，通过当前 Markdown 导入格式保存；不用 H1、HTML、图片链接或表格。表格需要时先改成清单。

配图给出英文生成提示词、建议位置和依据实际画面写的图片说明。已有合法生图能力时可生成图片。已有图片优先复用，不因为补图任务重新生成。把本任务图片保存在本机 content_output 目录，按实际画面和文章语言写 alt，给出明确位置。没有图片文件时，说明只完成了配图方案。不要捏造已经生成或上传。

## 入库与交给发布助手

本网站明确绑定 diversity 工作区（ID=2），不新建工作区、不落默认工作区。客户明确要求网站草稿时，调用本机 channelblog MCP 的 channel_blog_save_draft：提交 article，包含标题、稳定 slug、简介、作者 Diversity Technology Limited、SEO 标题/摘要、format=markdown 和正文 body。如果已有配图，在同一次调用中提供 images：每张图包含本机绝对 filePath、准确 alt、可选 caption 和 placement；位置为 start、end 或 before-heading（提供唯一完整标题 heading）。工具程序负责先入库工作区2，再把文档和文件分别交给发布机，确认图片插入后返回编辑链接。不要再同时调用通用 add_document，以免重复入库。

如果文章已经入库（例如文档201），只调用 channel_blog_submit_document，传原 documentId，不重新生成或另存一篇。失败重试保持原编号；若工具返回 stored-awaiting-handoff，告诉客户文章已入库但网站尚未确认，沿用返回的文档编号重试。相同 slug 不同正文发生冲突时，编辑原稿，不换 slug 绕过。给已保存的草稿补已有图片时，调用 channel_blog_attach_images，传原 documentId 和 images；不再次调用保存正文，不另建文档。所要求的配图必须全部确认插入才说图文草稿完整。images-incomplete 表示图片结果未全部确认，沿原文件、位置和文档编号重试；人工改稿冲突须保留人的修改并如实报告，不换号、不用原文覆盖。已经移除的图片不因重试恢复。

发布机程序会重新读取指定知识库文档、核对真实工作区、保存并查询网站回执；不需要再让客户同时 @发布助手。网站凭证留在发布机，不放内容机、不索取管理员账号。只有工具返回 state=ready 和真实 editUrl，才说网站私有草稿已保存。缺少 channelblog 专用工具时明确报告，不把通用 VibeKB 或 pipeline 工具当成网站交接入口。客户最后登录后台审核上线。

客户不需要同时叫两个助手，不填写 externalTaskId、idempotencyKey、接口或密钥。这些由正式工具处理，不能沿用某个试跑的固定编号。其他内容和平台任务继续走原流程。
