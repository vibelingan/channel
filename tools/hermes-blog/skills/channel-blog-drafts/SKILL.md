# 保存网站草稿并返回编辑链接

客户只说业务需求。不要要求客户说明SEO、alt、JSON、任务号、凭证或接口地址。缺少文章标题、简介和搜索摘要时，按channel-blog-writing规则补齐；不要因此把技术填表任务退给客户。

## 使用边界

只使用已配置的channel_blog_create_draft和channel_blog_get_import。实际注册名可能由Hermes加前缀，以工具发现结果为准，不去掉下划线。不通过终端读取密钥，不把凭证交给其他助手，不发布、撤回、删除文章或操作商品。

可信的群/客户绑定和服务器配置决定网站身份，模型不能授予跨客户权限。当前群测是单站单任务配置；使用前读取[本轮绑定](references/pilot-binding.md)。如果任务不属于这轮，不换号绕过限制，报告需要操作人准备新的合法连接。

## 从文章到工具调用

1. 准备title、excerpt、seoTitle、seoDescription；作者只使用已核实身份。不把这些字段和工具参数要求交给客户。
2. 正文用format=markdown，遵守网站支持的正文格式。配图文件、生成建议和图片说明单独交给人，不在body塞图片URL；当前接口还不能上传图片。
3. 从已安装的绑定说明取externalTaskId、idempotencyKey和试跑slug。它们不是凭证；本轮工具会核对，客户不用在群里重复。正式接入若没有可信的任务编号来源，先请操作人配置，不能从另一客户或随意重试的消息生成新号。
4. 调用channel_blog_create_draft。得到operationId后，再调用channel_blog_get_import核对结果。超时先查原操作号；重试保持编号和正文。409或权限错误不换号、不停用规则。
5. 仅在实际返回ready和合法editUrl后，把真实编辑链接交给客户。解释为“已存草稿，登录后可编辑和预览，确认后由你上线”。不能把ready或群里已有正文说成已公开。

已人工编辑的草稿由人在后台继续修改，不用重新投递不同正文覆盖。用户要求第二篇文章时，说明当前群测固定一篇，请操作人提供新任务连接；不要修改现有私有配置。

若工具未发现、凭证拒绝或网络失败，报告具体缺哪一步；不将安装文件存在、技能可见或模型输出当作网站保存成功。
